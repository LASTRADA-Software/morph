Detailed Description

What an action changes, and which records its result holds.

BRIDGE_REGISTER_EFFECTS records an action's effects as data under its id. Nothing is matched or checked at registration, so the order of record, action and effects registrations across translation units does not matter. The first read through effectsOf, recordsOf, recordNamed or actionsHolding matches every action's result slots against the record registry and validates the whole configuration, once. A configuration with problems throws morph::model::EffectsRegistrationError naming all of them, on that read and on every later one.

Declares what action A changes: any of morph::effects::updates<R>, changes<R>, changesInstance and none.

Place it beside the action's registration, where ActionTraits<A> is visible. It defines no specialisation, so a translation unit that does not see it is consistent with one that does. Repeating the same effects is a no-op; different effects for one action are refused on the first read. Expands to nothing under MORPH_CLIENT_ONLY.

Registers action A of model M as the reporter of the next instant at which the listed records change by the passage of time alone, with no action behind it.

A returns std::optional<morph::time::DateTime>: the next such instant, strictly after the model's own now, or nullopt when none is pending. It is a read: it declares no effects and takes no fields. The server asks it, owns the clock, and at that instant marks the records changed as an action's changes<R> would, then asks again; the model arms no timer and posts no work. A reporter that is not a registered action, that also declares effects, or that names an unregistered record is refused on the first read. Repeating the same registration is a no-op. Expands to nothing under MORPH_CLIENT_ONLY.

Adds effects to action A from the code that composes its module with the module that owns the record: any of morph::effects::updates<R>, changes<R> and changesInstance.

The action's own module cannot name a record of a module it does not include, and a second BRIDGE_REGISTER_EFFECTS for the action is refused, so the composing code, which includes both, adds the effect here. The addition is unioned with the action's own declaration and never removes an effect; none is refused at compile time. An addition for an action nobody registered, or for a record nobody registered, is refused on the first read, never ignored. Repeating an addition is a no-op. Place it in a translation unit that is always linked into the server. Expands to nothing under MORPH_CLIENT_ONLY.
