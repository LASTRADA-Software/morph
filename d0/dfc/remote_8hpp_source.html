59/// @brief Whether `RemoteServer` requires an `execute` body to carry every
60/// field the action's served schema marks `required`.
61///
62/// The one mechanical check `morph::wire`'s published action-evolution policy
63/// (docs/spec/core/wire.md, "Action-evolution policy") supports without
64/// contradicting itself. The policy's first bullet — *"New fields must be
65/// optional … so an older peer that omits them decodes cleanly"* — makes
66/// optionality, and only optionality, the wire's marker for *may be absent*.
67/// A field that is **not** optional therefore may not be absent, and the
68/// lenient `fromJson` cannot notice when it is: an absent field is
69/// default-constructed and an unknown one is dropped, so a client/server
70/// rename (`amount` → `amountCents`) decodes to a zero-valued action that
71/// `validate()` cannot tell from a legitimate zero.
72///
73/// @warning Not the default, and deliberately so. Turning it on rejects
74/// payloads a pre-existing client sends today, which is a non-additive change
75/// to the wire contract — precisely what the same policy says requires a
76/// `kProtocolVersion` bump. Enabling it by default would break the policy in
77/// the act of enforcing it. See docs/spec/core/wire.md, "Enforcing the policy".
78enum class PayloadCompleteness : std::uint8_t {
79 /// @brief Today's behaviour: the action codec's lenient decode is the only
80 /// gate, and a missing field is a default-constructed one.
81 Lenient,
82 /// @brief Reject an `execute` whose `body` omits a key the action's served
83 /// schema lists in `required`, with
84 /// `err "payload missing required field(s): …"`.
85 RequireDeclaredFields,
86};

90/// @brief Keyed 64-bit bijection that turns a monotonic counter into an
91/// unguessable, non-sequential id.
92///
93/// Implements a 4-round Feistel network over two 32-bit halves. A Feistel
94/// network is a bijection over its full domain for *any* round function —
95/// that is what guarantees `RemoteServer` never hands out the same id twice
96/// for two different counter values. What makes the permutation *opaque*
97/// rather than merely "scrambled" is that each round's mixing function folds
98/// in a secret round key drawn once, at construction, from
99/// `std::random_device`: an *unkeyed* public mixing function would be
100/// invertible by anyone reading the source, letting an attacker who observes
101/// one id recover the counter and predict the next; the secret per-round keys
102/// prevent that without needing the mixing function itself to be secret.
103///
104/// This is a self-contained reference construction (no external crypto
105/// dependency), in the same spirit as the hand-rolled HMAC-SHA256 in
106/// `session_auth.hpp`: adequate for the stated defence-in-depth goal (opaque
107/// ids are not the authorization boundary — `IAuthorizer::authorizeInstance`
108/// is), not a cryptographically-audited primitive.
109class OpaqueIdGenerator {
110public:
111 /// @brief Draws four independent 32-bit round keys from `std::random_device`.
112 OpaqueIdGenerator() {
113 std::random_device rd;
114 for (auto& key : _roundKeys) {
115 // std::random_device::result_type is unsigned int on this platform's
116 // standard library, so the cast below is a no-op here -- but the
117 // standard does not guarantee that, so it stays for portability to a
118 // standard library where result_type is wider than uint32_t.
119#if defined(__GNUC__) && !defined(__clang__)
120#pragma GCC diagnostic push
121#pragma GCC diagnostic ignored "-Wuseless-cast"
122#endif
123 key = static_cast<uint32_t>(rd());
124#if defined(__GNUC__) && !defined(__clang__)
125#pragma GCC diagnostic pop
126#endif
127 }
128 }
129
130 /// @brief Applies the keyed permutation to @p counter.
131 ///
132 /// Bijective over the full 64-bit domain: distinct @p counter values
133 /// always produce distinct results (the Feistel structure guarantees
134 /// this regardless of the round function), so a monotonically
135 /// increasing, non-repeating @p counter can never yield a collision.
136 /// @param counter Monotonic input, e.g. from an atomic counter.
137 /// @return A 64-bit value that is a bijective function of @p counter.
138 [[nodiscard]] uint64_t permute(uint64_t counter) const noexcept {
139 auto lo = static_cast<uint32_t>(counter & 0xffffffffULL);
140 auto hi = static_cast<uint32_t>(counter >> 32);
141 for (const uint32_t roundKey : _roundKeys) {
142 const uint32_t nextHi = lo;
143 lo = hi ^ mix(lo, roundKey);
144 hi = nextHi;
145 }
146 return (static_cast<uint64_t>(hi) << 32) | static_cast<uint64_t>(lo);
147 }
148
149private:
150 /// @brief Keyed avalanche mix (fmix32-style) used as the Feistel round function.
151 /// @param half Current 32-bit half being folded into the other half.
152 /// @param key This round's secret key.
153 /// @return A well-mixed 32-bit value depending non-linearly on both @p half and @p key.
154 [[nodiscard]] static uint32_t mix(uint32_t half, uint32_t key) noexcept {
155 uint32_t val = half ^ key;
156 val ^= val >> 16;
157 val *= 0x7feb352dU;
158 val ^= val >> 15;
159 val *= 0x846ca68bU;
160 val ^= val >> 16;
161 return val;
162 }
163
164 std::array<uint32_t, 4> _roundKeys{};
165};

283 /// @brief Synchronously processes a JSON `Envelope` on the calling thread and returns the reply.
284 ///
285 /// Equivalent to `handle()` but never posts to the worker pool, so it is safe
286 /// to call from a thread that *is* the worker pool — for example, from a
287 /// `BridgeHandler` constructor invoked from inside an action handler.
288 ///
289 /// Only safe for control messages (`register`, `deregister`). An `execute`
290 /// envelope posts to the strand and produces its reply asynchronously, after
291 /// this synchronous call has already returned and destroyed the local reply
292 /// buffer the deferred callback would write into. To keep that from becoming a
293 /// dangling write, `execute` is rejected up front with an `err` reply.
294 ///
295 /// @param msg JSON-encoded `morph::wire::Envelope` (via `wire::encode`).
296 /// @return JSON-encoded reply envelope.
297 std::string handleInline(const std::string& msg) { return handleInline(msg, 0); }
298
299 /// @brief Like `handleInline(msg)`, but additionally attributes any
300 /// `register` decoded from @p msg to a connection scope.
301 ///
302 /// The synchronous counterpart to the scoped `handle(msg, reply, cid)`
303 /// overload — same "processed inline, safe from the worker pool itself"
304 /// contract as the two-argument `handleInline`, with `register`/`attach`
305 /// additionally recorded in `cid`'s scope so a later `closeConnection(cid)`
306 /// reclaims it. Passing `cid == 0` is exactly the unscoped overload above.
307 ///
308 /// @param msg JSON-encoded `morph::wire::Envelope` (via `wire::encode`).
309 /// @param cid Connection scope to attribute a `register` in @p msg to;
310 /// `0` means unscoped.
311 /// @return JSON-encoded reply envelope.
312 std::string handleInline(const std::string& msg, ConnectionId cid) {
313 try {
314 auto env = ::morph::wire::decode(msg);
315 if (env.kind == "execute") {
316 return ::morph::wire::encode(::morph::wire::makeErr(
317 "handleInline does not support execute (reply is asynchronous)", env.callId));
318 }
319 } catch (const std::exception&) { // NOLINT(bugprone-empty-catch)
320 // Malformed input: fall through so dispatchMessage produces the
321 // canonical decode-error reply (avoids duplicating that path here).
322 }
323 std::string reply;
324 std::function<void(std::string)> capture = [&reply](std::string out) noexcept { reply = std::move(out); };
325 dispatchMessage(msg, capture, cid);
326 return reply;
327 }

329private:
330 /// @brief Shared body of both `handle()` overloads.
331 ///
332 /// Peeks at @p msg's `kind`/`modelId` — a cheap, best-effort decode, thrown
333 /// away immediately either way — and, for an `execute` naming a `modelId`,
334 /// takes an execute-ordering ticket (see
335 /// `takeExecuteTicket`'s own doc comment on the class-private members
336 /// above) *before* posting to `_pool`, so two same-model `execute`s
337 /// posted back-to-back always take their tickets in call order — the
338 /// same order the transport called `handle()` in, i.e. send order. If
339 /// this peek fails to decode at all, or isn't an `execute`, no ticket is
340 /// taken; `dispatchMessage` still does the real (only) decode moments
341 /// later on the pool thread and produces the canonical error for
342 /// genuinely malformed input — this peek only ever *adds* a ticket for a
343 /// well-formed `execute`, it never changes what gets sent to
344 /// `dispatchMessage` or how errors are reported.
345 /// @param msg JSON-encoded `morph::wire::Envelope` (via `wire::encode`).
346 /// @param reply Callback invoked with the JSON-encoded reply envelope.
347 /// @param cid Connection scope; `0` means unscoped (see `handle()`'s own doc).
348 void handleImpl(std::string msg, std::function<void(std::string)> reply, ConnectionId cid) {
349 auto self = shared_from_this();
350 std::optional<std::pair<::morph::exec::detail::ModelId, std::uint64_t>> ticket;
351 try {
352 if (auto peek = ::morph::wire::decode(msg); peek.kind == "execute" && peek.modelId != 0) {
353 ::morph::exec::detail::ModelId const mid{peek.modelId};
354 ticket.emplace(mid, takeExecuteTicket(mid));
355 }
356 } catch (const std::exception&) { // NOLINT(bugprone-empty-catch)
357 // Malformed input: no ticket taken (there is no well-formed
358 // execute to order). dispatchMessage's own decode, on the pool
359 // thread, produces the canonical decode-error reply for this —
360 // duplicating that error path here would serve no purpose since
361 // this peek's only job is deciding whether to take a ticket.
362 }
363 // Owns the ticket for the window between taking it and successfully
364 // handing it to the pool: if `_pool.post` throws, the guard releases it
365 // on the way out instead of stranding it. It is disarmed only once the
366 // post has returned, at which point the posted task — which adopts the
367 // ticket into its own guard in `dispatchMessage` — is its owner.
368 ExecuteTicketGuard ticketGuard{*this, ticket};
369 _pool.post([self, msg = std::move(msg), reply = std::move(reply), cid, ticket]() mutable {
370 self->dispatchMessage(msg, reply, cid, ticket);
371 });
372 ticketGuard.disarm();
373 }

376 /// @brief Opens a new connection scope and returns its id.
377 ///
378 /// Call once per accepted transport connection (e.g. from a WebSocket
379 /// server's "new connection" callback). The returned id is never `0`, so
380 /// it can always be distinguished from the reserved "unscoped" value. Pass
381 /// it to the scoped `handle(msg, reply, cid)` overload for every message
382 /// received on that connection, and to `closeConnection(cid)` once the
383 /// connection is gone.
384 ///
385 /// Thread-safe.
386 /// @return A fresh, non-zero `ConnectionId`.
387 [[nodiscard]] ConnectionId openConnection() {
388 ConnectionId const cid{_nextConnectionId.fetch_add(1) + 1};
389 std::scoped_lock const lock{_regMtx};
390 _connectionScopes.try_emplace(cid);

392 }

394 /// @brief Reclaims every model still registered under @p cid, then drops the scope.
395 ///
396 /// Call once the transport observes the connection is gone (disconnect,
397 /// close, error). Erases every surviving model in `cid`'s scope from the
398 /// registry exactly as an explicit `deregister` would (so a later
399 /// `execute` against one of those ids replies `err "model not found"`),
400 /// then drops the scope itself.
401 ///
402 /// Idempotent: `cid == 0`, an unknown `cid`, or a `cid` already closed is a
403 /// no-op. Deliberately does **not** consult `IAuthorizer` — this is the
404 /// server's own housekeeping in reaction to a transport-level event, not
405 /// an action attributable to any caller (see docs/spec/core/backend.md).
406 ///
407 /// Safe to call while a model in the scope has an `execute` in flight: the
408 /// strand task already holds its own `shared_ptr` to the model holder, so
409 /// erasing the registry entry here only prevents *new* lookups (see
410 /// docs/spec/concurrency_and_lifetimes.md).
411 ///
412 /// Thread-safe.
413 /// @param cid Connection scope to close, as returned by `openConnection()`.
414 void closeConnection(ConnectionId cid) {
415 if (cid == 0) {
416 return;
417 }
418 std::scoped_lock const lock{_regMtx};
419 auto scopeIter = _connectionScopes.find(cid);
420 if (scopeIter == _connectionScopes.end()) {
421 return;
422 }
423 for (const auto& [mid, refs] : scopeIter->second) {
424 // Release exactly as many references as this connection held. A
425 // shared instance another connection is still attached to survives;
426 // a private one (count 1, no directory entry) is erased outright,
427 // which is byte-for-byte the previous behaviour.
428 for (std::size_t idx = 0; idx < refs; ++idx) {
429 releaseInstanceLocked(mid);
430 }
431 }
432 _connectionScopes.erase(scopeIter);
433 }

546 /// @brief Enters shutdown: from now on, `register` and `execute` envelopes
547 /// are rejected with `err "server shutting down"`. `deregister` is
548 /// still served so clients can tear down cleanly.
549 ///
550 /// Idempotent — safe to call more than once, and safe to call while
551 /// `handle()`/`handleInline()` calls are concurrently in flight on other
552 /// threads. There is no way back: a restarted service constructs a fresh
553 /// `RemoteServer` rather than un-shutting-down this one.

574 /// @brief Blocks until every in-flight `execute` has delivered its reply,
575 /// or @p deadline elapses.
576 ///
577 /// "In-flight" is one counter (`_inFlightExecutes`), incremented when
578 /// `dispatchExecute` admits a call for dispatch (right before posting to
579 /// the model's strand) and decremented right before its reply is sent, on
580 /// every resolving path (`ok`, `err`, or a `LimitPolicy::executeTimeout`

582 /// configured) gates and `health()`'s `inFlight` field reads, shared
583 /// rather than double-counted. Waits on a condition variable signalled
584 /// when the counter reaches zero — not a busy poll. Safe to call from any
585 /// thread, independently of `beginShutdown()` (it only observes the

591 std::unique_lock lock{_drainMtx};
592 return _drainCv.wait_for(lock, deadline,
593 [this] { return _inFlightExecutes.load(std::memory_order_acquire) == 0; });
594 }

632 /// @brief Releases one reference to @p mid, destroying it at zero. Caller holds `_regMtx`.
633 ///
634 /// A private instance has no `_attachCount` entry and is erased outright —
635 /// byte-for-byte the pre-sharing behaviour. A shared instance is erased, and
636 /// removed from the directory, only when its last attachment goes away, so
637 /// one client's `deregister` or dropped connection never tears an instance
638 /// out from under another client still using it.
639 /// @param mid Instance to release.
640 /// @return `true` if this call destroyed the instance.
641 bool releaseInstanceLocked(::morph::exec::detail::ModelId mid) {
642 if (auto refIter = _attachCount.find(mid); refIter != _attachCount.end()) {
643 refIter->second -= 1;
644 if (refIter->second > 0) {
645 return false;
646 }
647 _attachCount.erase(refIter);
648 if (auto keyIter = _sharedKeyOf.find(mid); keyIter != _sharedKeyOf.end()) {
649 _directory.erase(keyIter->second);
650 _sharedKeyOf.erase(keyIter);
651 }
652 }
653 _models.erase(mid);
654 _owners.erase(mid);
655 _firstActionPending.erase(mid);
656 _poisoned.erase(mid);
657 return true;
658 }

713 /// @brief Attaches to an already-live directory entry, if there is one. Caller holds `_regMtx`.
714 ///
715 /// Factored out because `acquireSharedInstance` checks the directory twice —
716 /// once on entry, and again under the insert lock after building a holder
717 /// outside it, in case a concurrent request for the same key won the race.
718 /// The second check is by nature almost never taken, so duplicating the body
719 /// would leave a block that is both untested and free to drift from the one
720 /// that is.
721 ///
722 /// @param dirKey Directory key being acquired.
723 /// @param env Decoded request, for `callId`.
724 /// @param reply Reply sink; invoked only when this returns `true`.
725 /// @param cid Connection scope, or `0` for unscoped.
726 /// @return `true` if an entry existed and @p reply was invoked; `false` to keep going.
727 bool attachExistingLocked(const DirectoryKey& dirKey, const ::morph::wire::Envelope& env,
728 const std::function<void(std::string)>& reply, ConnectionId cid) {
729 auto found = _directory.find(dirKey);
730 if (found == _directory.end()) {
731 return false;
732 }
733 auto const mid = found->second;
734 if (_poisoned.contains(mid)) {
735 // This instance's first action already failed; it must not be
736 // handed to a new attacher. Evict it from the directory -- its
737 // own eventual release still tears it down normally -- and report
738 // a miss so the caller falls through to creating a fresh
739 // instance.
740 _directory.erase(found);
741 _sharedKeyOf.erase(mid);
742 return false;
743 }
744 _attachCount[mid] += 1;
745 if (!noteScopeAttachLocked(mid, cid)) {
746 releaseInstanceLocked(mid);
747 reply(::morph::wire::encode(::morph::wire::makeErr("connection closed", env.callId)));
748 return true;
749 }
750 reply(::morph::wire::encode(::morph::wire::makeOk(env.callId, {}, mid.v)));
751 return true;
752 }

754 /// @brief Acquires (or creates) the shared instance for `(typeId, primary)` and replies.
755 ///
756 /// The register-or-attach core shared by the `register` branch (when
757 /// `shared` is set) and by `attach`. A shared instance is recorded with an
758 /// **empty owner principal**: `IAuthorizer::authorizeInstance`'s documented
759 /// `ownerPrincipal == ctx.principal` policy would otherwise reject every
760 /// client but the one that created it, defeating cross-client sharing
761 /// outright. Gating access to a shared model is therefore `authorize`'s job
762 /// (per type and action) or the model's own — see docs/spec/security.md.
763 ///
764 /// @param env Decoded request; uses `typeId`, `primary`, `contextKey`, `callId`.
765 /// @param reply Reply sink; always invoked exactly once.
766 /// @param cid Connection scope, or `0` for unscoped.
767 /// @param releaseCurrent Instance to release once the target is
768 /// confirmed acquired or confirmed about to be
769 /// created (an `attach` re-point), or `ModelId{0}`.
770 /// A throwing *construction* (`_registry.create`)
771 /// never touches it. Once construction succeeds,
772 /// release happens in the same locked section as
773 /// the `maxLiveModels` admission check, so a sole
774 /// holder's release frees the slot the re-point
775 /// itself needs rather than losing it to the cap;
776 /// the only remaining post-release failure is the
777 /// connection's own scope having closed
778 /// concurrently, in which case no further request
779 /// on it will run anyway.
780 void acquireSharedInstance(const ::morph::wire::Envelope& env, const std::function<void(std::string)>& reply,
781 ConnectionId cid, ::morph::exec::detail::ModelId releaseCurrent) {
782 LimitPolicy const limits = snapshotLimits();
783 DirectoryKey dirKey{env.typeId, env.primary};
784 {
785 std::scoped_lock const lock{_regMtx};
786 if (attachExistingLocked(dirKey, env, reply, cid)) {
787 // Acquired (or re-confirmed) the target before touching
788 // `releaseCurrent` -- a same-key re-attach lands on the exact
789 // same mid attachExistingLocked just incremented, so
790 // releasing it here cancels out only the redundant reference
791 // that call just took, never the caller's sole hold on the
792 // instance it is "re-pointing" to itself. A genuinely
793 // different-key re-point releases the real old instance, same
794 // as before.
795 if (releaseCurrent.v != 0U) {
796 releaseScopedLocked(releaseCurrent, cid);
797 }
798 return;
799 }
800 }
801 // Directory miss. Construct outside the lock, exactly as the private
802 // register path does, then re-check under the insert lock: a concurrent
803 // request for the same key may have won the race while we built ours.
804 // env.primary is this instance's directory key -- always non-empty
805 // here (acquireSharedInstance is only reached for a shared/keyed
806 // register-or-attach), so the model learns its own key once, at
807 // construction, via IModelHolder::attachIdentity.
808 auto holder = _registry.create(env.typeId, env.primary);
809 attachLogIfConfigured(*holder, env);
810 ::morph::exec::detail::ModelId const fresh{nextOpaqueId()};
811 {
812 std::scoped_lock const lock{_regMtx};
813 if (attachExistingLocked(dirKey, env, reply, cid)) {
814 if (releaseCurrent.v != 0U) {
815 releaseScopedLocked(releaseCurrent, cid);
816 }
817 return;
818 }
819 // Confirmed miss: release the old instance now, in the same
820 // locked section as the maxLiveModels admission check, so a sole
821 // holder's release frees exactly the slot this re-point needs
822 // rather than losing it to the cap in between -- the property
823 // the single `attach` wire request exists to provide. The only
824 // way admission can still fail after this is a concurrently
825 // closed connection scope (noteScopeAttachLocked below), which
826 // makes "stranding" moot: no further request on that connection
827 // will ever run anyway.
828 if (releaseCurrent.v != 0U) {
829 releaseScopedLocked(releaseCurrent, cid);
830 }
831 if (limits.maxLiveModels != 0 && _models.size() >= limits.maxLiveModels) {
832 reply(::morph::wire::encode(::morph::wire::makeErr("too many models", env.callId)));
833 return;
834 }
835 if (!noteScopeAttachLocked(fresh, cid)) {
836 reply(::morph::wire::encode(::morph::wire::makeErr("connection closed", env.callId)));
837 return;
838 }
839 _models[fresh] = std::move(holder);
840 _owners[fresh] = std::string{}; // shared instances are ownerless, by design
841 _directory.emplace(dirKey, fresh);
842 _sharedKeyOf.emplace(fresh, std::move(dirKey));
843 _attachCount[fresh] = 1;
844 _firstActionPending.insert(fresh);
845 }
846 reply(::morph::wire::encode(::morph::wire::makeOk(env.callId, {}, fresh.v)));
847 }

877 ///

879 /// judged on the **key**, not on the decoded value, because that is the
880 /// only question the action codec cannot answer: `fromJson` turns an
881 /// absent field and an explicitly-sent zero into the same action, which is

887 /// published requirement (`requiredFieldsFor` returning `nullptr`)

890 ///

936 /// @brief Owns a taken execute-ordering ticket and releases it on every
937 /// exit path, unless ownership was explicitly handed on.
938 ///
939 /// A ticket handed out by `takeExecuteTicket` must be released exactly once
940 /// by whatever path took it: an unreleased ticket permanently stalls every
941 /// later ticket for the same model, because `awaitExecuteTurn` is a
942 /// `cv.wait` with no deadline. That rule used to be a per-call-site
943 /// convention — `dispatchExecute`'s `rejectAndRelease` helper for its
944 /// explicit early returns, plus one hand-written release in
945 /// `dispatchMessage`'s shutdown gate — and the convention was missed
946 /// twice: by the shutdown gate itself (issue #348), and by every exception
947 /// that unwinds out of `dispatchExecute` past all of its early returns
948 /// (issue #351). The latter is ordinary, documented reachability, not a
949 /// hypothetical: `IAuthorizer::authorize`/`authenticate`/
950 /// `authorizeInstance` are non-`noexcept` virtuals on a public extension
951 /// point, and `missingRequiredFields` parses the payload. Such a throw
952 /// landed in `dispatchMessage`'s outer catch, which replied but released
953 /// nothing, stranding every later same-model `execute` forever.
954 ///
955 /// This holder makes the rule structural instead of remembered: the ticket
956 /// is owned from the moment it is taken until the guard dies, so every exit
957 /// path — `return`, `throw`, and any branch a later change adds — releases
958 /// it. Two members opt out deliberately:
959 ///
960 /// - `release()`, for the paths that want the ticket freed *before* their
961 /// reply goes out rather than at end of scope, so a slow reply callback
962 /// never holds a later same-model `execute` up; and
963 /// - `disarm()`, for the one place ownership is genuinely handed on —
964 /// `handleImpl`, whose posted pool task adopts the ticket in
965 /// `dispatchMessage`.
966 ///
967 /// Neither copyable nor movable: it is only ever a local of the frame that
968 /// owns the ticket.
969 class ExecuteTicketGuard {
970 public:
971 /// @brief Adopts @p ticket on behalf of @p server.
972 /// @param server Server whose gate map @p ticket belongs to. Borrowed:
973 /// a guard is always a local of one of that server's own
974 /// member functions, so it cannot outlive it.
975 /// @param ticket This call's ticket from `takeExecuteTicket`, or
976 /// `std::nullopt` if it took none (any envelope that is
977 /// not a well-formed `execute` naming a `modelId`), in
978 /// which case the guard is inert.
979 ExecuteTicketGuard(RemoteServer& server MORPH_LIFETIMEBOUND,
980 std::optional<std::pair<::morph::exec::detail::ModelId, std::uint64_t>> ticket) noexcept
981 : _server{server}, _ticket{std::move(ticket)} {}
982
983 ExecuteTicketGuard(const ExecuteTicketGuard&) = delete;
984 ExecuteTicketGuard(ExecuteTicketGuard&&) = delete;
985 ExecuteTicketGuard& operator=(const ExecuteTicketGuard&) = delete;
986 ExecuteTicketGuard& operator=(ExecuteTicketGuard&&) = delete;
987
988 /// @brief Releases the ticket if it is still held — the backstop that
989 /// covers every path which did not release explicitly.
990 ~ExecuteTicketGuard() { release(); }
991
992 /// @brief Releases the held ticket now, letting the next ticket for the
993 /// same model proceed. Idempotent: a no-op if no ticket was
994 /// taken, or if it has already been released or disarmed.
995 void release() {
996 if (!_ticket) {
997 return;
998 }
999 auto const held = *_ticket;
1000 // Cleared before the release, not after: this guard owes nothing
1001 // further from here on, so the destructor cannot release twice
1002 // even if `releaseExecuteTicket` itself exits by exception.
1003 _ticket.reset();
1004 _server.releaseExecuteTicket(held.first, held.second);
1005 }
1006
1007 /// @brief Gives up ownership *without* releasing, for the one path that
1008 /// hands the ticket on to a new owner.
1009 void disarm() noexcept { _ticket.reset(); }
1010
1011 /// @brief Blocks until the held ticket's turn comes (see
1012 /// `awaitExecuteTurn`). A no-op if no ticket is held.
1013 void awaitTurn() {
1014 if (_ticket) {
1015 _server.awaitExecuteTurn(_ticket->first, _ticket->second);
1016 }
1017 }

1019 private:
1020 RemoteServer& _server;
1021 std::optional<std::pair<::morph::exec::detail::ModelId, std::uint64_t>> _ticket;
1022 };

1024 // One flat switch over the wire's `kind` discriminator. Splitting it would
1025 // scatter the authorization sequence each branch depends on across helpers,
1026 // with no reader benefit.
1027 //
1028 // `executeTicket`, when engaged, is this call's execute-ordering ticket from
1029 // `handleImpl`, adopted below by an `ExecuteTicketGuard` that owns it for
1030 // the rest of this frame — including `dispatchExecute`, the only branch that
1031 // does anything with it beyond releasing it. Every other `kind` ignores it;
1032 // `handleImpl` never takes one for a non-`execute` envelope in the first
1033 // place, so it is always `std::nullopt` for those.
1034 // NOLINTNEXTLINE(readability-function-cognitive-complexity)
1035 void dispatchMessage(const std::string& msg, std::function<void(std::string)>& reply, ConnectionId cid = 0,
1036 std::optional<std::pair<::morph::exec::detail::ModelId, std::uint64_t>> executeTicket = {}) {
1037 // Adopted before anything that can fail, including the decode: from
1038 // here on every way out of this function — each early return below,
1039 // the outer catch, and any branch a later change adds — releases the
1040 // ticket, which is what makes `releaseExecuteTicket`'s stated rule
1041 // structurally true rather than a convention each call site has to
1042 // remember (issues #348 and #351).
1043 ExecuteTicketGuard ticketGuard{*this, std::move(executeTicket)};
1044 ::morph::wire::Envelope env;
1045 try {
1046 env = ::morph::wire::decode(msg);
1047 } catch (const std::exception& exc) {
1048 // Undecodable envelope: the one server-side record of a request
1049 // that never dispatched at all. A client that swallows its own
1050 // error (or is malformed precisely because it is confused) would
1051 // otherwise leave no trace here. The payload prefix is the most
1052 // useful field for diagnosing *why* the client sent something
1053 // malformed -- and the most likely to carry application data, so
1054 // it is capped at kLogPayloadPreviewBytes rather than logged in
1055 // full. See docs/spec/core/backend.md, "Server-side observability".
1056 constexpr std::size_t kLogPayloadPreviewBytes = 256;
1057 std::string_view const preview =
1058 std::string_view{msg}.substr(0, std::min(msg.size(), kLogPayloadPreviewBytes));
1059 ::morph::log::logError(
1060 "[dispatchMessage] undecodable envelope from connection {}: {} ({} bytes, "
1061 "payload prefix: {}{})",
1062 cid, exc.what(), msg.size(), preview, msg.size() > kLogPayloadPreviewBytes ? "..." : "");
1063 reply(::morph::wire::encode(::morph::wire::makeErr(exc.what())));
1064 return;
1065 }
1066 // One line per successfully-decoded request -- the point every kind
1067 // funnels through, so a client stuck mid-handshake (or one that never
1068 // sent anything) is distinguishable from one whose requests are
1069 // arriving normally. Deliberately omits the session principal (opt-in
1070 // territory: personal data in many deployments) and the payload body
1071 // (already covered, truncated, on the decode-failure path above;
1072 // logging every successful body by default would be far higher volume
1073 // and duplicate what dispatch already records via the action log for
1074 // execute).
1075 ::morph::log::logDebug(
1076 "[dispatchMessage] connection {}: kind={} callId={} typeId={} modelId={} "
1077 "modelType={} actionType={} bodyBytes={}",
1078 cid, env.kind, env.callId, env.typeId, env.modelId, env.modelType, env.actionType, env.body.size());
1079 // Once shutdown has begun, new work is rejected fast — before any of
1080 // the existing register/execute validation runs — while `deregister`
1081 // (and any other kind) still flows through unchanged, so a client can
1082 // still tear its models down cleanly during the drain window.
1083 if ((env.kind == "register" || env.kind == "execute" || env.kind == "attach") &&
1084 _shuttingDown.load(std::memory_order_acquire)) {
1085 // Release before replying, rather than leaving it to the guard's
1086 // destructor: this reply may be slow (it is a transport write), and
1087 // nothing about it is worth making a later same-model `execute`
1088 // wait for.
1089 //
1090 // Not merely a leaked map entry on a dying server (which is what
1091 // this branch was previously believed to cost): tickets are taken
1092 // in send order on the transport thread, but the pool is free to
1093 // run the two posted tasks in either order. A *later* ticket that
1094 // passed this gate before `beginShutdown()` is already parked in
1095 // `awaitExecuteTurn`, on a `cv.wait` with no deadline, waiting for
1096 // this one -- so dropping it strands that caller permanently, holds
1097 // a pool worker forever, and (because `_inFlightExecutes` is
1098 // incremented before that wait) makes `drainedWithin()` unable to
1099 // ever succeed. See `tests/test_remote_execute_ordering.cpp`'s
1100 // shutdown-gate case, which forces that interleaving.
1101 ticketGuard.release();
1102 reply(::morph::wire::encode(::morph::wire::makeErr("server shutting down", env.callId)));
1103 return;
1104 }

1652 // ── Per-model execute-ordering gate ──────────────────────────────────────
1653 // Specified in `docs/spec/core/backend.md`, "Per-model execute ordering".
1654 //
1655 // `handle()`'s two overloads dispatch to `_pool`, a multi-worker
1656 // ThreadPoolExecutor: two `execute` envelopes for the *same* model,
1657 // posted back-to-back, can have their pre-strand work (decode, authorize,
1658 // authenticate, registry lookup) finish on two different pool threads in
1659 // either order -- so without this gate, whichever one finishes first
1660 // reaches `_strand.post(mid, ...)` first, even if the client sent the
1661 // other one first (`tests/test_remote_execute_ordering.cpp` reproduces
1662 // this deterministically). A first attempt strand-routed the *entire*
1663 // dispatch pipeline for a known `modelId`, which closed the race but
1664 // broke `test_remote_connection_scope.cpp`'s "an in-flight execute
1665 // completes safely across a disconnect" guarantee: a lookup against a
1666 // since-reclaimed `modelId` must resolve immediately without waiting on
1667 // some other, still-blocked model's strand, and moving the whole
1668 // pipeline onto the strand collapsed that fast-reject path into the same
1669 // queue as the slow model's in-flight work. The ticket gate below fixes
1670 // only the ordering of the `_strand.post()` call itself, leaving the
1671 // fast-reject path exactly as fast as it always was.
1672 //
1673 // The gate orders only the *moment of the `_strand.post()` call itself*,
1674 // not the pipeline before it: a ticket is handed out synchronously in
1675 // `handleImpl` (called directly from `handle()`, which runs on
1676 // whatever single thread the transport calls it from -- in true send
1677 // order, nothing async yet) for every `execute` with a known `modelId`,
1678 // *before* posting to `_pool`. `dispatchExecute` waits for its ticket's
1679 // turn only immediately before the pre-existing `_strand.post(mid, ...)`
1680 // call, and releases the next ticket's turn either right after posting
1681 // (live model) or immediately on a "model not found"/other early-return
1682 // rejection (dead model, unauthorized, over limit, etc. -- none of these
1683 // ever reach the strand, so their ticket must not block anyone behind
1684 // it -- and, on any path that leaves by exception rather than by return,
1685 // `ExecuteTicketGuard`'s destructor does the same). This keeps the
1686 // fast-reject path exactly as fast as it always was
1687 // (`test_remote_connection_scope.cpp`'s "an in-flight execute completes
1688 // safely across a disconnect" test — a lookup against a since-reclaimed
1689 // modelId must resolve without waiting on some other blocked model's
1690 // strand — never touches this gate at all, since it never gets a ticket
1691 // for a model that turns out to be gone... except it does get a ticket,
1692 // and must release it immediately rather than hold up a live ticket
1693 // behind it; see `releaseExecuteTicket`'s own doc comment).
1694 //
1695 // Keyed by ModelId, not held forever: a model with no outstanding
1696 // tickets has no entry in `_executeGates` at all (erased once its last
1697 // ticket is released), so this never grows unbounded across the
1698 // server's lifetime the way a per-model map with no cleanup would.
1699 struct ExecuteGate {
1700 std::uint64_t nextTicket = 0;
1701 std::uint64_t nextToRun = 0;
1702 std::condition_variable cv;
1703 };
1704 std::mutex _executeGateMtx;

1706 ::morph::exec::detail::ModelIdHash>

1709 /// @brief Hands out the next ticket for @p mid, in call order.
1710 ///
1711 /// Called synchronously from `handleImpl` (i.e. from `handle()`'s
1712 /// own calling thread, before anything is posted anywhere) — the ticket
1713 /// numbers two calls receive for the same `mid` are therefore always in
1714 /// the order `handle()` was called, which is the order the transport
1715 /// received them in.
1716 /// @param mid The model the upcoming `execute` targets.
1717 /// @return This call's ticket number.
1718 [[nodiscard]] std::uint64_t takeExecuteTicket(::morph::exec::detail::ModelId mid) {
1719 std::scoped_lock const lock{_executeGateMtx};
1720 auto& gate = _executeGates[mid];
1721 if (!gate) {
1722 gate = std::make_shared<ExecuteGate>();
1723 }
1724 return gate->nextTicket++;
1725 }

1727 /// @brief Blocks until @p ticket is next in line for @p mid, then returns.
1728 ///
1729 /// Called from a pool thread, immediately before the pre-existing
1730 /// `_strand.post(mid, ...)` call in `dispatchExecute` — nothing else
1731 /// about that call site changes; this only delays *when* it happens; it
1732 /// still runs on the pool, never blocks the strand itself.
1733 /// @param mid The model the caller is about to `_strand.post()` to.
1734 /// @param ticket This call's ticket, from `takeExecuteTicket`.
1735 void awaitExecuteTurn(::morph::exec::detail::ModelId mid, std::uint64_t ticket) {
1736 std::unique_lock lock{_executeGateMtx};
1737 auto iter = _executeGates.find(mid);
1738 if (iter == _executeGates.end()) {
1739 return; // Nothing left to wait for -- every ticket for mid already released.
1740 }
1741 auto gate = iter->second; // Keep it alive even if releaseExecuteTicket erases the map entry mid-wait.
1742 gate->cv.wait(lock, [&gate, ticket] { return gate->nextToRun == ticket; });
1743 }
1744
1745 /// @brief Releases @p ticket for @p mid, letting the next ticket (if any) proceed.
1746 ///
1747 /// Called exactly once per ticket taken, from every path that took one —
1748 /// whether that path went on to `_strand.post()` (a live model) or bailed
1749 /// out early (model not found, unauthorized, over limit, a decode/
1750 /// validation throw). A ticket that is taken but never released would
1751 /// permanently stall every later ticket for the same `mid`, since
1752 /// `awaitExecuteTurn` waits with no deadline.
1753 ///
1754 /// **Callers do not carry that rule themselves.** Every ticket is owned by
1755 /// an `ExecuteTicketGuard` from the moment `takeExecuteTicket` returns, and
1756 /// the guard calls this on destruction unless the path already called it
1757 /// explicitly (or handed ownership on with `disarm()`). Call sites that
1758 /// release explicitly do so only to free the gate *earlier* than end of
1759 /// scope — before writing a reply — never because the release would
1760 /// otherwise be missed.
1761 ///
1762 /// It was a per-call-site discipline until it had been missed twice: by
1763 /// `dispatchMessage`'s shutdown gate, which returns before `dispatchExecute`
1764 /// is reached at all (issue #348), and by every exception unwinding out of
1765 /// `dispatchExecute` past all of its explicit early returns into
1766 /// `dispatchMessage`'s outer catch (issue #351). Both stranded a later
1767 /// same-model `execute` in `awaitExecuteTurn` forever, blocked a pool
1768 /// worker for the process's remaining life, and — because
1769 /// `_inFlightExecutes` is incremented just before that wait — left
1770 /// `drainedWithin()` unable to succeed. Hence the guard: the rule is now
1771 /// structural, and `tests/test_remote_execute_ordering.cpp` pins both
1772 /// paths.
1773 /// @param mid The model @p ticket was taken for.
1774 /// @param ticket The ticket to release.
1775 void releaseExecuteTicket(::morph::exec::detail::ModelId mid, std::uint64_t ticket) {
1776 std::scoped_lock const lock{_executeGateMtx};
1777 auto iter = _executeGates.find(mid);
1778 if (iter == _executeGates.end()) {
1779 return; // Defensive; should not happen (this ticket's own take() created the entry).
1780 }
1781 iter->second->nextToRun = ticket + 1;
1782 if (iter->second->nextToRun == iter->second->nextTicket) {
1783 // No ticket is currently waiting and none can arrive for a ticket
1784 // number already handed out — safe to drop the entry so a model
1785 // with no in-flight executes leaves no trace in this map.
1786 _executeGates.erase(iter);
1787 } else {
1788 iter->second->cv.notify_all();
1789 }
1790 }
