40/// @brief Opt-in, connection-agnostic resource limits enforced by `RemoteServer`.
41///
42/// Every field defaults to `0`, meaning "unbounded": a default-constructed
43/// policy applies no limit. Given as `ServerConfig::limits`, at construction.
44/// See `docs/spec/core/backend.md`.
45struct LimitPolicy {
46 /// @brief Max wall-clock time a single `execute` may take before the server
47 /// sends an `err "timeout"` reply and discards the eventual strand
48 /// result. `0` = no timeout (today's behavior).
49 ///
50 /// An ordinary handler is never interrupted — it keeps running to
51 /// completion on its strand, so this bounds the *caller's wait*, not the
52 /// model. A handler returning `core::async::Task` is also asked to stop: its
53 /// stop token is requested, and it unwinds at its next stop-aware
54 /// `co_await` (see `docs/spec/core/coroutines.md`).
55 std::chrono::milliseconds executeTimeout{0};
56
57 /// @brief Max models this `RemoteServer` will hold live at once, across all
58 /// callers. A `register` beyond this cap replies `err "too many
59 /// models"`. `0` = unbounded (today's behavior).
60 std::size_t maxLiveModels{0};
61
62 /// @brief Max concurrent in-flight `execute` calls this server will accept
63 /// before replying `err "server busy"` instead of dispatching.
64 /// `0` = unbounded (today's behavior).
65 std::size_t maxInFlightExecutes{0};
66};

68/// @brief Whether `RemoteServer` requires an `execute` body to carry every
69/// field the action's served schema marks `required`.
70///
71/// The one mechanical check `morph::wire`'s published action-evolution policy
72/// (docs/spec/core/wire.md, "Action-evolution policy") supports without
73/// contradicting itself. The policy's first bullet — *"New fields must be
74/// optional … so an older peer that omits them decodes cleanly"* — makes
75/// optionality, and only optionality, the wire's marker for *may be absent*.
76/// A field that is **not** optional therefore may not be absent, and the
77/// lenient `fromJson` cannot notice when it is: an absent field is
78/// default-constructed and an unknown one is dropped, so a client/server
79/// rename (`amount` → `amountCents`) decodes to a zero-valued action that
80/// `validate()` cannot tell from a legitimate zero.
81///
82/// @warning Not the default, and deliberately so. Turning it on rejects
83/// payloads a pre-existing client sends today, which is a non-additive change
84/// to the wire contract — precisely what the same policy says requires a
85/// `kProtocolVersion` bump. Enabling it by default would break the policy in
86/// the act of enforcing it. See docs/spec/core/wire.md, "Enforcing the policy".
87enum class PayloadCompleteness : std::uint8_t {
88 /// @brief Today's behaviour: the action codec's lenient decode is the only
89 /// gate, and a missing field is a default-constructed one.
90 Lenient,
91 /// @brief Reject an `execute` whose `body` omits a key the action's served
92 /// schema lists in `required`, with
93 /// `err "payload missing required field(s): …"`.
94 RequireDeclaredFields,
95};

99/// @brief Keyed 64-bit bijection that turns a monotonic counter into an
100/// unguessable, non-sequential id.
101///
102/// Implements a 4-round Feistel network over two 32-bit halves. A Feistel
103/// network is a bijection over its full domain for *any* round function —
104/// that is what guarantees `RemoteServer` never hands out the same id twice
105/// for two different counter values. What makes the permutation *opaque*
106/// rather than merely "scrambled" is that each round's mixing function folds
107/// in a secret round key drawn once, at construction, from
108/// `std::random_device`: an *unkeyed* public mixing function would be
109/// invertible by anyone reading the source, letting an attacker who observes
110/// one id recover the counter and predict the next; the secret per-round keys
111/// prevent that without needing the mixing function itself to be secret.
112///
113/// This is a self-contained reference construction (no external crypto
114/// dependency), in the same spirit as the hand-rolled HMAC-SHA256 in
115/// `session_auth.hpp`: adequate for the stated defence-in-depth goal (opaque
116/// ids are not the authorization boundary — `IAuthorizer::authorizeInstance`
117/// is), not a cryptographically-audited primitive.
118class OpaqueIdGenerator {
119public:
120 /// @brief Draws four independent 32-bit round keys from `std::random_device`.
121 OpaqueIdGenerator() {
122 std::random_device rd;
123 for (auto& key : _roundKeys) {
124 // std::random_device::result_type is unsigned int on this platform's
125 // standard library, so the cast below is a no-op here -- but the
126 // standard does not guarantee that, so it stays for portability to a
127 // standard library where result_type is wider than uint32_t.
128#if defined(__GNUC__) && !defined(__clang__)
129#pragma GCC diagnostic push
130#pragma GCC diagnostic ignored "-Wuseless-cast"
131#endif
132 key = static_cast<uint32_t>(rd());
133#if defined(__GNUC__) && !defined(__clang__)
134#pragma GCC diagnostic pop
135#endif
136 }
137 }
138
139 /// @brief Applies the keyed permutation to @p counter.
140 ///
141 /// Bijective over the full 64-bit domain: distinct @p counter values
142 /// always produce distinct results (the Feistel structure guarantees
143 /// this regardless of the round function), so a monotonically
144 /// increasing, non-repeating @p counter can never yield a collision.
145 /// @param counter Monotonic input, e.g. from an atomic counter.
146 /// @return A 64-bit value that is a bijective function of @p counter.
147 [[nodiscard]] uint64_t permute(uint64_t counter) const noexcept {
148 auto lo = static_cast<uint32_t>(counter & 0xffffffffULL);
149 auto hi = static_cast<uint32_t>(counter >> 32);
150 for (const uint32_t roundKey : _roundKeys) {
151 const uint32_t nextHi = lo;
152 lo = hi ^ mix(lo, roundKey);
153 hi = nextHi;
154 }
155 return (static_cast<uint64_t>(hi) << 32) | static_cast<uint64_t>(lo);
156 }
157
158private:
159 /// @brief Keyed avalanche mix (fmix32-style) used as the Feistel round function.
160 /// @param half Current 32-bit half being folded into the other half.
161 /// @param key This round's secret key.
162 /// @return A well-mixed 32-bit value depending non-linearly on both @p half and @p key.
163 [[nodiscard]] static uint32_t mix(uint32_t half, uint32_t key) noexcept {
164 uint32_t val = half ^ key;
165 val ^= val >> 16;
166 val *= 0x7feb352dU;
167 val ^= val >> 15;
168 val *= 0x846ca68bU;
169 val ^= val >> 16;
170 return val;
171 }
172
173 std::array<uint32_t, 4> _roundKeys{};
174};

248/// @brief Server-side message handler that owns model instances and dispatches actions.
249///
250/// `RemoteServer` receives JSON envelopes (`morph::wire::Envelope`) from any
251/// transport (WebSocket, in-process simulation, …) and executes the corresponding
252/// model operations via an `ActionDispatcher`. Authorization is delegated to an
253/// `IAuthorizer` that defaults to allow-all.
254///

257/// in-flight count, readiness — belongs to one strand over the worker pool, the

259/// to it. An `execute` is admitted there and then posted to its model's own

271/// `wire.hpp` for the field semantics. The `kind` field is the discriminator.

421 /// @brief Processes a control `Envelope` on the server strand and returns
422 /// its reply, blocking the caller until it has one.
423 ///
424 /// For `register`, `deregister`, `attach`, `assign`, `instances`, `schemas`
425 /// and `hello` — the synchronous control path `SimulatedRemoteBackend`
426 /// uses. Runs inline when the caller is already on the server strand;
427 /// otherwise posts and waits. `execute` is rejected up front with an `err`
428 /// reply: its reply is produced later, on the model's strand.
429 ///
430 /// Callable from a pool thread, including one inside a running action (a
431 /// handler registered from an action handler): the server strand then runs
432 /// on another pool thread while this one waits. So the pool needs a thread
433 /// free for it — a one-thread pool calling this from inside its own task,
434 /// or every pool thread blocked here at once, never gets its reply. See
435 /// docs/spec/concurrency_and_lifetimes.md, "Synchronous re-entry".
436 ///
437 /// @param msg JSON-encoded `morph::wire::Envelope` (via `wire::encode`).
438 /// @return JSON-encoded reply envelope.
439 std::string handleInline(const std::string& msg) { return handleInline(msg, 0); }
440
441 /// @brief Like `handleInline(msg)`, but additionally attributes any
442 /// `register` decoded from @p msg to a connection scope.
443 ///
444 /// The synchronous counterpart to the scoped `handle(msg, reply, cid)`
445 /// overload, on the same terms as the one-argument `handleInline`.
446 /// Passing `cid == 0` is exactly the unscoped overload above.
447 ///
448 /// @param msg JSON-encoded `morph::wire::Envelope` (via `wire::encode`).
449 /// @param cid Connection scope to attribute a `register` in @p msg to;
450 /// `0` means unscoped.
451 /// @return JSON-encoded reply envelope.
452 std::string handleInline(const std::string& msg, ConnectionId cid) {
453 Decoded decoded = decodeEnvelope(msg);
454 if (decoded.env && decoded.env->kind == "execute") {
455 return ::morph::wire::encode(::morph::wire::makeErr(
456 "handleInline does not support execute (reply is asynchronous)", decoded.env->callId));
457 }
458 std::string out;
459 std::function<void(std::string)> capture = [&out](std::string reply) noexcept { out = std::move(reply); };
460 if (_strand.runningHere()) {
461 dispatchDecoded(std::move(decoded), capture, cid);
462 return out;
463 }
464 std::latch done{1};
465 _strand.postTask([self = shared_from_this(), &decoded, &capture, cid, &done] {
466 // Counted down however the dispatch ends, so the caller is never
467 // left waiting on a task that threw.
468 try {
469 self->dispatchDecoded(std::move(decoded), capture, cid);
470 } catch (...) {
471 done.count_down();
472 throw;
473 }
474 done.count_down();
475 });
476 done.wait();
477 return out;
478 }

501 /// @brief Reclaims every model still registered under @p cid, then drops the scope.
502 ///
503 /// Call once the transport observes the connection is gone (disconnect,
504 /// close, error). Releases exactly as many references as this connection
505 /// held, exactly as an explicit `deregister` would, then drops the scope
506 /// itself. A *private* instance (count 1, no directory entry) is erased
507 /// outright, so a later `execute` against its id replies
508 /// `err "model not found"`; a *shared* instance another connection is still
509 /// attached to survives, and an `execute` against it still succeeds — see
510 /// `InstanceDirectory::release`'s `retained` outcome.
511 ///
512 /// Idempotent: `cid == 0`, an unknown `cid`, or a `cid` already closed is a
513 /// no-op. Deliberately does **not** consult `IAuthorizer` — this is the
514 /// server's own housekeeping in reaction to a transport-level event, not
515 /// an action attributable to any caller (see docs/spec/core/backend.md).
516 ///
517 /// Safe while a model in the scope has an `execute` in flight: the model
518 /// strand's task holds its own `shared_ptr` to the model holder, so erasing
519 /// the registry entry here only prevents *new* lookups (see
520 /// docs/spec/concurrency_and_lifetimes.md).
521 ///
522 /// Callable from any thread; runs on the server strand, before any
523 /// `handle()` the same thread makes next.
524 /// @param cid Connection scope to close, as returned by `openConnection()`.
525 void closeConnection(ConnectionId cid) {
526 if (cid == 0) {
527 return;
528 }
529 _strand.postTask([self = shared_from_this(), cid] { self->closeConnectionHere(cid); });
530 }

590 /// @brief Answers whether every in-flight `execute` delivers its reply
591 /// within @p deadline.
592 ///
593 /// "In-flight" is one count, kept on the server strand: incremented when an
594 /// `execute` is admitted for dispatch and decremented, on the strand, when
595 /// its reply is sent — on every resolving path (`ok`, `err`, or a
596 /// `LimitPolicy::executeTimeout` firing first). The same count
597 /// `LimitPolicy::maxInFlightExecutes` gates and `health()`'s `inFlight`

599 /// new work from arriving. Callable from any thread; nothing blocks. The
600 /// caller attaches to the answer on @p replyExec, the owner it names.
601 /// @param deadline Longest time to wait; `0` answers from the count as it

607 /// count is zero, `false` if @p deadline elapses first. Its
608 /// callbacks run on @p replyExec.

613 [self = shared_from_this(), deadline,

615 self->noteOwner("RemoteServer::drainedWithin");
616 self->addDrainWaiter(deadline, promise);
617 });
618 return std::move(settleable.first);

702 /// @brief Registers a drain waiter, or answers it at once. On the server strand.
703 /// @param deadline Longest time to wait for the in-flight count to reach zero.
704 /// @param promise Settled `true` at zero, `false` at the deadline.
705 void addDrainWaiter(std::chrono::milliseconds deadline, const DrainPromise& promise) {
706 if (_inFlight == 0) {
707 promise->resolve(true);
708 return;
709 }
710 if (deadline.count() <= 0) {
711 promise->resolve(false);
712 return;
713 }
714 std::uint64_t const waiterId = ++_nextDrainWaiter;
715 if (!_drainTimer) {
716 _drainTimer = std::make_unique<::morph::async::detail::TimeoutScheduler>();
717 }
718 // Weak: a pending deadline does not keep a server alive that nothing
719 // else refers to. The expiry is posted back, since the waiters are
720 // strand state and the timer fires on its I/O loop.
721 auto const handle = _drainTimer->schedule(deadline, [weak = weak_from_this(), waiterId] {
722 if (auto self = weak.lock()) {
723 self->_strand.postTask([self, waiterId] { self->expireDrainWaiter(waiterId); });
724 }
725 });
726 _drainWaiters.push_back(DrainWaiter{.id = waiterId, .promise = promise, .timer = handle});
727 }

729 /// @brief Answers `false` to the drain waiter @p waiterId, if it is still
730 /// waiting. On the server strand.

732 void expireDrainWaiter(std::uint64_t waiterId) {
733 noteOwner("RemoteServer::drainedWithin");

735 if (found == _drainWaiters.end()) {
736 return;
737 }
738 DrainPromise const promise = found->promise;
739 _drainWaiters.erase(found);
740 promise->resolve(false);
741 }

792 /// @brief Drops one of @p cid's references to @p mid and releases the
793 /// instance by that one reference. On the server strand.
794 ///
795 /// A scoped connection releases only a reference it holds: if @p cid's
796 /// scope records none for @p mid — it never attached it, already released
797 /// every reference it had, or its scope is closed — nothing is released,
798 /// because the reference that would go belongs to another connection.
799 /// The unscoped path (`cid == 0`) records no references, so it always
800 /// releases.
801 /// @param mid Instance to release.
802 /// @param cid Connection whose reference is being dropped; `0` for unscoped.
803 void releaseScoped(::morph::exec::detail::ModelId mid, ConnectionId cid) {
804 if (cid != 0) {
805 auto scopeIter = _connectionScopes.find(cid);
806 if (scopeIter == _connectionScopes.end()) {
807 return;
808 }
809 auto refIter = scopeIter->second.find(mid);
810 if (refIter == scopeIter->second.end()) {
811 return;
812 }
813 refIter->second -= 1;
814 if (refIter->second == 0) {
815 scopeIter->second.erase(refIter);
816 }
817 }
818 releaseInstance(mid);
819 }

878 /// @brief Acquires (or creates) the shared instance for `(typeId, primary)`
879 /// and replies. On the server strand.
880 ///
881 /// The register-or-attach core shared by the `register` branch (when
882 /// `shared` is set) and by `attach`. A shared instance is recorded with an
883 /// **empty owner principal**: `IAuthorizer::authorizeInstance`'s documented
884 /// `ownerPrincipal == ctx.principal` policy would otherwise reject every
885 /// client but the one that created it, defeating cross-client sharing
886 /// outright. Gating access to a shared model is therefore `authorize`'s job
887 /// (per type and action) or the model's own — see docs/spec/security.md.
888 ///
889 /// The directory check, the construction, the `maxLiveModels` admission and
890 /// the insert all run in this one strand task. Only host code this task
891 /// itself calls — the model's construction, the log provider — can file the
892 /// key in between, through `handleInline`, so the directory is checked
893 /// again after it.
894 ///
895 /// @param env Decoded request; uses `typeId`, `primary`, `contextKey`, `callId`.
896 /// @param reply Reply sink; always invoked exactly once.
897 /// @param cid Connection scope, or `0` for unscoped.
898 /// @param releaseCurrent Instance to release once the target is confirmed
899 /// acquired or about to be created (an `attach`
900 /// re-point), or `ModelId{0}`. A throwing construction
901 /// never touches it. It is released before the
902 /// `maxLiveModels` admission check, so a sole holder's
903 /// release frees the slot the re-point itself needs.
904 void acquireSharedInstance(const ::morph::wire::Envelope& env, const std::function<void(std::string)>& reply,
905 ConnectionId cid, ::morph::exec::detail::ModelId releaseCurrent) {
906 detail::DirectoryKey dirKey{env.typeId, env.primary};
907 if (attachExisting(dirKey, env, reply, cid)) {
908 // A same-key re-attach lands on the exact mid attachExisting just
909 // incremented, so releasing `releaseCurrent` here cancels only the
910 // redundant reference that call took, never the caller's sole hold.
911 // A different-key re-point releases the real old instance.
912 if (releaseCurrent.v != 0U) {
913 releaseScoped(releaseCurrent, cid);
914 }
915 return;
916 }
917 // env.primary is this instance's directory key -- always non-empty here
918 // (acquireSharedInstance is only reached for a shared/keyed
919 // register-or-attach), so the model learns its own key once, at
920 // construction, via IModelHolder::attachIdentity.
921 auto holder = _registry.create(env.typeId, env.primary);
922 attachLogIfConfigured(*holder, env);
923 // Checked again: the construction and the log provider are host code,
924 // and one that registers or attaches through `handleInline` runs that
925 // request inline, on this strand, possibly filing this very key.
926 if (attachExisting(dirKey, env, reply, cid)) {
927 if (releaseCurrent.v != 0U) {
928 releaseScoped(releaseCurrent, cid);
929 }
930 return;
931 }
932 ::morph::exec::detail::ModelId const fresh{nextOpaqueId()};
933 if (releaseCurrent.v != 0U) {
934 releaseScoped(releaseCurrent, cid);
935 }
936 LimitPolicy const& limits = _config.limits;
937 if (limits.maxLiveModels != 0 && _instances.size() >= limits.maxLiveModels) {
938 reply(::morph::wire::encode(::morph::wire::makeErr("too many models", env.callId)));
939 return;
940 }
941 if (!noteScopeAttach(fresh, cid)) {
942 reply(::morph::wire::encode(::morph::wire::makeErr("connection closed", env.callId)));
943 return;
944 }
945 // Filed with one attachment, an empty owner (shared instances are
946 // ownerless, by design -- see this function's doc comment) and its
947 // hydration pending, so the first action's outcome decides whether a
948 // second client may ever be handed it.
949 _instances.insertShared(fresh, std::move(holder), std::move(dirKey));
950 reply(::morph::wire::encode(::morph::wire::makeOk(env.callId, {}, fresh.v)));
951 }

977 /// @brief Names the fields `(modelType, actionType)`'s served schema marks
978 /// `required` that @p body does not carry a key for.
979 ///
980 /// The whole of `PayloadCompleteness::RequireDeclaredFields`. Presence is
981 /// judged on the **key**, not on the decoded value, because that is the
982 /// only question the action codec cannot answer: `fromJson` turns an
983 /// absent field and an explicitly-sent zero into the same action, which is
984 /// exactly why a renamed field survives `validate()`.
985 ///
986 /// Conservative in both directions. A `body` that is not a JSON object at
987 /// all reports nothing missing — malformed JSON is `fromJson`'s error to
988 /// raise, with a better message, a moment later — and an action with no
989 /// published requirement (`requiredFieldsFor` returning `nullptr`)
990 /// contributes no rule, since the gate enforces what the schema published
991 /// and cannot enforce what it could not publish.
992 ///
993 /// @param modelType Model type-id from the envelope.
994 /// @param actionType Action type-id from the envelope.
995 /// @param body The `execute` envelope's opaque payload JSON.

998 [[nodiscard]] std::string missingRequiredFields(const std::string& modelType, const std::string& actionType,
999 const std::string& body) const {
1000 const auto* required = _dispatcher.requiredFieldsFor(modelType, actionType);
1001 if (required == nullptr || required->empty()) {
1002 return {};
1003 }

1005 if (glz::read_json(dom, body) || !dom.is_object()) {
1006 return {};
1007 }
1008 std::string missing;
1009 for (const auto& field : *required) {
1010 if (!dom.contains(field)) {
1011 if (!missing.empty()) {
1012 missing += ", ";
1013 }
1014 missing += field;
1015 }
1016 }
1017 return missing;
1018 }

1071 // One flat switch over the wire's `kind` discriminator. Splitting it would
1072 // scatter the authorization sequence each branch depends on across helpers,
1073 // with no reader benefit. On the server strand.
1074 // NOLINTNEXTLINE(readability-function-cognitive-complexity)
1075 void dispatchEnvelope(::morph::wire::Envelope env, std::function<void(std::string)>& reply, ConnectionId cid) {
1076 // One line per successfully-decoded request -- the point every kind
1077 // funnels through, so a client stuck mid-handshake (or one that never
1078 // sent anything) is distinguishable from one whose requests are
1079 // arriving normally. Deliberately omits the session principal (opt-in
1080 // territory: personal data in many deployments) and the payload body
1081 // (already covered, truncated, on the decode-failure path; logging every
1082 // successful body by default would be far higher volume and duplicate
1083 // what dispatch already records via the action log for execute).
1084 ::morph::log::logDebug(
1085 "[dispatchMessage] connection {}: kind={} callId={} typeId={} modelId={} "
1086 "modelType={} actionType={} bodyBytes={}",
1087 cid, env.kind, env.callId, env.typeId, env.modelId, env.modelType, env.actionType, env.body.size());
1088 // Once shutdown has begun, new work is rejected fast — before any other
1089 // validation runs — while `deregister` (and any other kind) still flows
1090 // through unchanged, so a client can still tear its models down cleanly
1091 // during the drain window.
1092 if ((env.kind == "register" || env.kind == "execute" || env.kind == "attach") && _shuttingDown) {
1093 reply(::morph::wire::encode(::morph::wire::makeErr("server shutting down", env.callId)));

1292 // Admission: one ordered gate sequence — limits, authorize, authenticate,
1293 // lookup, per-instance authorize, payload completeness, in-flight
1294 // reservation — whose *order* is the security contract itself (see
1295 // docs/spec/security.md), so it is deliberately not broken up. On the
1296 // server strand; the admitted run is posted to the model's strand.

1298 void dispatchExecute(::morph::wire::Envelope env, std::function<void(std::string)> reply) {

1301 reply(::morph::wire::encode(::morph::wire::makeErr(message, env.callId)));

1306 if (limits.maxInFlightExecutes != 0 && _inFlight >= limits.maxInFlightExecutes) {
1307 reject("server busy");
1308 return;
1309 }
1310 if (!_authorizer->authorize(env.session, env.modelType, env.actionType)) {
1311 reject("unauthorized");
1312 return;
1313 }
1314 // Make the identity authoritative. A verifying authorizer returns the
1315 // principal it extracted from a valid token; we stamp it so model code
1316 // reading session::current()->principal can trust it. If authenticate()
1317 // returns nullopt the authorizer cannot vouch for the caller, so we CLEAR
1318 // the client-asserted principal rather than passing it through unverified.
1319 // This closes two holes: (1) the TOCTOU window where a token that passed
1320 // authorize() expires before authenticate() (worst case is an empty
1321 // principal, never the attacker's claim), and (2) an authorize-only or
1322 // allow-all authorizer that never authenticates (the model never sees an
1323 // untrusted principal as authoritative). See docs/spec/security.md.

1327 // together: they are fields of one record.
1328 const auto* inst = _instances.find(mid);
1329 if (inst == nullptr) {

1331 // so a lookup of a model that is gone never waits on a model that
1332 // is busy.
1333 reject("model not found");
1334 return;

1341 // env.session carries the verified principal (stamped just above), so an
1342 // ownership authorizer compares the recorded owner against it.

1348 // After authorization — the diagnostic names the action's own field,

1351 // payload that will not be dispatched never consumes one.

1356 reject(message.c_str());

1358 }

1361 // once, by `complete`, whichever of the model strand's finish and the
1362 // `executeTimeout` gets there first; `complete` posts the matching
1363 // `executeFinished` back to this strand.
1364 _inFlight += 1;

1370 // is handed to the model's strand: dispatchEnvelope's catch replies on

1377 Reservation(RemoteServer& owner, std::shared_ptr<std::atomic_flag> flag)
1378 : server{owner}, finished{std::move(flag)} {}

1380 Reservation& operator=(const Reservation&) = delete;
1381 Reservation(Reservation&&) = delete;
1382 Reservation& operator=(Reservation&&) = delete;
1383 // NOLINTNEXTLINE(bugprone-exception-escape): executeFinished runs the server's drain bookkeeping on its owner; a failure there has no recovery in a destructor.

1386 server.executeFinished();

1388 }

1503 ///
1504 /// Metrics and endSpan are recorded before `complete(...)` runs (in
1505 /// finishRemote) so a caller observing completion — via handle()'s reply
1506 /// or the timeout path racing it — can never see the reply before this
1507 /// dispatch's own instrumentation is recorded. This mirrors the
1508 /// reply-exactly-once contract `complete` already provides: whichever
1509 /// path wins the race, the metrics for *this* dispatch are always
1510 /// emitted, exactly once, regardless of which path's reply the caller
1511 /// actually receives.

1514 /// throws morph::model::ValidationError before Model::execute runs. No
1515 /// special-casing is needed: it becomes an ordinary `err` reply carrying its
1516 /// message and callId, exactly like any other dispatch failure. See
1517 /// docs/spec/core/registry.md.

1520 run.spanId =
1521 ::morph::observe::detail::beginSpan(run.env.session.requestId, run.env.modelType, run.env.actionType);
1522 }

1540 /// gate, on the strand. It replies when its Task completes.

1561 });
1562 });
1563 } catch (...) {
1564 run->self->_strands->withdraw(run->mid, executor.get());
1565 finishRemote(*run, std::string{}, std::current_exception());

1570 /// next execute on the instance can start. On the strand.

1580 // the outcome is known but unrecorded is handed an instance whose first
1581 // action has already failed. See shared_instances.md's Failure modes.
1582 if (run.hydration) {

1676/// processed through `RemoteServer::handleInline`, which answers before it
1677/// returns, so a bind settles inside the call. `execute()` is asynchronous: it
1678/// sends the message through `RemoteServer::handle` and resolves the returned
1679/// `Completion` when the reply arrives.

1692 /// exercise connection-scoped state (rate limiting, connection-drop
1693 /// recovery, shared-instance attach/detach across connections)

1696 /// not owned: it must outlive this backend — a backend holding
1697 /// a `RemoteServer&` that has been destroyed is a

1957 } catch (...) {
