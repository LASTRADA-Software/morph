Detailed Description

The server's preferences model: reads and writes the calling person's choices through a store.

The person is the principal of the verified session (session::current()), which RemoteServer stamps from the authoriser before dispatch. The authoriser sees the model and the action, never the body, so the model is where the key is decided: no request names a person, and one that tries reaches only its own caller's entries. With no verified principal there is no key that belongs to the caller alone, so load answers nothing and set and remove are refused.
