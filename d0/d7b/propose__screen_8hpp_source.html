26/// @brief The `propose_screen` tool: the assistant proposes a complete `ui/1` document for the open screen, which the
27/// server checks as it checks a save and, once accepted, hands to the client as the window's draft.
28///
29/// - **Offered** only on a screen whose document is known and within `ChatLimits::maxProposalBytes`: the turn's draft,
30/// else the bundle's own text for an application screen, else the person's custom screen as @p screens answers it.
31/// On any other screen it is not offered, and the system text says the assistant cannot edit the screen.
32/// - **Its context** is that document, written as one JSON string literal inside a block named as the screen being
33/// edited and as data, never as instructions (a shared custom screen is text someone else may have written), what
34/// the base rule allows a screen based on the same base, and a short reference to the vocabulary.
35/// - **A call** carries the whole document. It is refused as a tool error, with the pointer to the refused part,
36/// when it is malformed, too large, names another screen id than the open one, or fails the checks of a save under
37/// the turn's session. Only an accepted document becomes the turn's draft. The refusal that is the
38/// `ChatLimits::maxProposalsPerTurn`th of a turn ends the turn, and the screen stays as it was.
39/// - **The conversation** keeps that a draft was proposed and its content hash, not the document.
40///
41/// The tool saves nothing, and runs as the turn's session.
42/// @param screens The handle `registerCustomScreens` returned: the checks and the store.
43/// @param app The application's id, as @p screens serves it.
44/// @param executor Where the tool's checks run. Borrowed: it outlives every turn.
45/// @return The tool, for `ChatOptions::tools`.
46[[nodiscard]] MORPH_API ChatTool customScreensChatTool(std::shared_ptr<CustomScreens> const& screens,
47 std::string const& app, exec::IExecutor& executor);
48
