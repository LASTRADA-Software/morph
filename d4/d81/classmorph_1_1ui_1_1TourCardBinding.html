Detailed Description

Connects the card document and tour.start to the frame's controller through a HostVocabulary.

For the card document alone (kTourCardId): the values tour.title, tour.stepTitle, tour.body, tour.waitingFor (strings), tour.position, tour.count (ints), tour.waiting, tour.canBack, tour.last (flags), and the commands tour.next, tour.back and tour.end. For every document: tour.start with {id}, refused, and reported by the interpreter, for an id the app offers no tour for. Every command is safe for an untrusted connection: it changes nothing on the server and shows only what the application declared. The commands' work is posted, since a step can open a screen and a screen must not be replaced inside one of its widgets' handlers; when the posted tour.start finds no controller or a controller that refuses the id (the frame was rebuilt after the refusal check), that is reported too. A shell makes one binding, which outlives frames, and calls refresh after each change of the controller's view. The registered commands stay in the host vocabulary after the binding is gone, and posted work may still be queued: both check a token the destructor clears, so after destruction a command does nothing and a posted command's work is dropped, and a refusal check allows nothing. Neither copyable nor movable; on the runtime's owner.
