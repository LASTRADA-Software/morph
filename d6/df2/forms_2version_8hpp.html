Detailed Description

morph::forms::FieldVersion, the ordered version a field or a screen element first ships in, and the field-inventory check an application runs over its actions in its own tests.

Its own header, free of glaze and of the schema emitters, because both forms.hpp (FieldMeta::since) and the ui documents (an element's since, a custom screen's knownVersion) use the same ordering.

◆ checkFieldInventory()

std::vector< FieldInventoryProblem > morph::forms::checkFieldInventory ( std::span< FieldInventoryEntry const > previous,
std::span< FieldInventoryEntry const > current )
inlinenodiscard

Checks an action's current fields against the snapshot of its last release.

The application keeps the snapshot (nextFieldInventory gives the one to keep at a release) and runs this in its own tests; morph keeps none. A problem is reported for:

  • an entry of either list whose since is not a version (InvalidSince);
  • a current field absent from the snapshot whose since is not above the highest since the snapshot records, removed fields included (AddedWithoutNewerSince); an empty snapshot is the first release and checks no addition;
  • a current field the snapshot holds whose since is another version (SinceChanged);
  • a current field the snapshot records as removed (Reappeared).

A field of the snapshot that is gone from current is a removal, which is allowed. An entry of current marked removed is not a field of the action and is skipped.

Parameters
previousThe snapshot of the last release, removed fields included.
currentThe action's fields now, fieldInventory<A>().
Returns
Every problem, in the order of current (invalid snapshot entries first); empty when there is none.
