78/// @brief One *bind* request: everything needed to acquire a model instance.
79///
80/// The request half of the structural registration surface
81/// (`IBackend::bindModel`). It replaces the three separate acquire verbs
82/// (`registerModelWithContext`, `registerModelShared`, `attachModel`) with one
83/// request whose *shape* selects the behaviour, because the three differ only
84/// in which fields are populated:
85///
86/// | `primary` | `current` | Equivalent legacy verb |
87/// |---|---|---|
88/// | empty | `0` | `registerModelWithContext(typeId, factory, contextKey)` |
89/// | non-empty | `0` | `registerModelShared(typeId, factory, identity)` |
90/// | non-empty | non-zero | `attachModel(typeId, factory, identity, current)` |
91///
92/// Unlike `InstanceIdentity`, every string here is **owned**. That is not a
93/// style preference: a bind may outlive the frame that issued it, so a
94/// `string_view` into the caller's stack is a dangling read waiting for a
95/// backend that copies its envelope after the dispatch call returns rather
96/// than before it. The synchronous verbs below take views and are safe only
97/// because they do not return until the backend has finished with them.
98struct BindRequest {
99 /// @brief String type-id of the model to instantiate (from `ModelTraits`).
100 std::string typeId;
101
102 /// @brief Callable that constructs the `IModelHolder`. Local path only; a
103 /// wire backend never calls it, and an attach to a live shared
104 /// instance does not call it either.
105 std::function<std::unique_ptr<::morph::model::detail::IModelHolder>()> factory;
106
107 /// @brief Entity key for the action log; empty if none. See `journal::LogEntry::entityKey`.
108 std::string contextKey;
109
110 /// @brief Canonical string encoding of the primary key. Empty means "no
111 /// identity": the bind produces a private instance that never enters
112 /// the shared directory.
113 std::string primary;
114
115 /// @brief Instance currently held, or `ModelId{0}` if none. Non-zero makes
116 /// this bind a *re-point*: the backend names what it is re-pointing
117 /// from, exactly as `attachModel` does.
118 ::morph::exec::detail::ModelId current{};
119};

137/// @brief Whether a caller holding an unsettled `bindModel`/`promoteModel`
138/// `Completion` may block its own thread until that `Completion`
139/// settles.
140///
141/// This is the one thing `bindModel`'s signature cannot say, and morph#593 is
142/// what happens when it is not said: two shipped backends both return an
143/// unsettled `Completion` from `bindModel`, and `Bridge::registerHandlerImpl`
144/// — a synchronous entry point that hands its caller a `BridgeHandler` usable
145/// on the next line — must wait for one of them and must not wait for the
146/// other. From the `Completion` alone the two are indistinguishable.
147///
148/// It is deliberately **not** the `bool` the surface removed (see "The
149/// structural registration surface" below, point 1). That `bool` chose
150/// *which verb to call*, so every call site carried two paths and a backend
151/// could be half-migrated. This one chooses nothing: there is still exactly
152/// one verb, called unconditionally, and exactly one continuation. It says
153/// only whether the thread that issued the call is allowed to stop and wait
154/// for the continuation it already registered.
155enum class BindWait : std::uint8_t {
156 /// @brief The completion settles without the calling thread's
157 /// participation — inside the call, or on a thread the caller does
158 /// not own. A caller may block until it settles.
159 ///
160 /// The default, and correct for every backend that has not overridden
161 /// `bindModel` (the default settles before it returns) as well as for
162 /// `SocketBackend`, whose I/O thread settles the completion. A backend
163 /// that returns this **must** settle every `Completion` it hands out
164 /// exactly once without further calls from the caller — including on
165 /// transport failure and on `cancelPending`/destruction — or a caller that
166 /// waits will wait forever.
167 kCallerMayBlock,
168
169 /// @brief The completion cannot settle while the calling thread is blocked
170 /// in a wait, or blocking it would defeat the point of this
171 /// backend. A caller must register its continuation and return.
172 ///
173 /// Two backends say this, for two different reasons:
174 ///
175 /// - `QtWebSocketBackend` with `Config::asyncRegistrationEnabled` set: the
176 /// reply arrives through the Qt event loop of the thread that issued the
177 /// call, so waiting is a deadlock. On a WASM main thread it aborts the
178 /// page (morph#568), which is the case that surface exists for.
179 /// - `SynchronousBackendAdapter`: it exists precisely to move a blocking
180 /// call off the caller's thread, so a caller that then waits for it has
181 /// bought nothing — and if the caller happens to be running on the
182 /// adapter's own executor, has deadlocked.
183 kCallerMustNotBlock,
184};

221 /// @brief Registers or attaches to the shared instance holding @p primary.
222 ///
223 /// A *register-or-attach*: if an instance for `(typeId, primary)` is already
224 /// live in the backend's shared directory, its id is returned and its attach

231 /// enters the directory and can never be shared.

234 /// `registerModelWithContext`, so a backend that has not implemented sharing

248 /// @brief Re-points from @p current to the shared instance holding @p primary.
249 ///
250 /// The default implementation acquires the replacement via
251 /// `registerModelShared` first and only then releases @p current (when
252 /// non-zero), so a same-key re-attach never destroys and recreates the
253 /// instance it already holds, and a throwing acquire never strands the
254 /// caller with neither instance. Backends behind a wire protocol override
255 /// this with the single `attach` request so a re-pointing client cannot
256 /// lose its slot to `LimitPolicy::maxLiveModels` between the release and
257 /// the acquire.
258 ///
259 /// @param typeId String type-id of the model.
260 /// @param factory Callable that constructs the `IModelHolder` (local path only).
261 /// @param identity Entity key for the action log plus the directory primary key.
262 /// @param current Instance currently held, or `ModelId{0}` if none.
263 /// @return Id of the instance now attached to.
264 virtual ::morph::exec::detail::ModelId attachModel(
265 const std::string& typeId, std::function<std::unique_ptr<::morph::model::detail::IModelHolder>()> factory,
266 InstanceIdentity identity, ::morph::exec::detail::ModelId current) {
267 // Acquire the replacement before releasing `current`, not after: a
268 // same-key re-attach (registerModelShared finds `current` already
269 // live in the directory and takes a second reference to it) then
270 // hands back the identical id instead of destroying and recreating
271 // it, and a throwing acquire never touches `current` at all, so the
272 // caller's existing instance is never stranded by a failed attach.
273 // Either way, exactly one reference on `current` needs releasing
274 // afterward: the genuinely old instance's, if this re-pointed to a
275 // different key; or the redundant one registerModelShared just took,
276 // if it did not.
277 auto next = registerModelShared(typeId, std::move(factory), identity);
278 if (current.v != 0U) {
279 deregisterModel(current);
280 }
281 return next;
282 }

284 /// @brief Enters an already-live instance into the directory under @p primary.
285 ///
286 /// The *promotion* half of keyed instances, and what makes a result-sourced
287 /// key work without losing state: an action that creates its own entity runs
288 /// on an instance that does not yet have a key, and the key only exists once
289 /// the result comes back. Re-pointing to a freshly created instance would
290 /// strand everything the create just did, so instead the instance the action
291 /// ran on is given the generated key in place.
292 ///
293 /// A no-op when @p primary is empty, when @p mid is not live, when another
294 /// instance already holds that key, when @p mid itself already holds a
295 /// *different* real key, or when @p mid was *created* for a key — even one
296 /// it has since been evicted from as poisoned. The existing holder of a key
297 /// always wins (a promotion can never silently displace a directory entry
298 /// other handlers are attached to), and an instance that was ever keyed
299 /// never changes key (a promotion can never silently move one out from
300 /// under handlers already attached to it, nor hand later attachers a model
301 /// that still identifies itself as the entity it was built for) — only an
302 /// instance that has never held a key can be promoted.
303 ///
304 /// @param mid Live instance to promote.
305 /// @param typeId Model type id — the directory's first key component.
306 /// @param primary Canonical string encoding of the key to file it under.
307 virtual void assignPrimary(::morph::exec::detail::ModelId mid, const std::string& typeId,
308 std::string_view primary) {
309 (void)mid;
310 (void)typeId;
311 (void)primary;

314 // ── The structural registration surface ──────────────────────────────
315 //
316 // `bindModel`/`promoteModel` are what the five verbs above become once the
317 // continuation stops being optional. Two differences carry the whole
318 // change, and both are visible in the signature rather than in a comment:
319 //
320 // 1. **The continuation is not opt-in.** There is no `bool` saying "I
321 // have no async path, call the other one" — so no call site carries a
322 // second path, and a backend cannot be *half* migrated. A blocking
323 // backend satisfies the surface unchanged through the default
324 // implementations below, or without blocking the caller at all
325 // through `SynchronousBackendAdapter`.
326 //
327 // What morph#593 established is that removing *that* bool also
328 // removed something else the call site needed and that is not the
329 // same question: whether the thread that called `bindModel` is
330 // allowed to wait for the continuation it just registered. Two
331 // shipped backends return an unsettled `Completion` and give opposite
332 // answers (`SocketBackend`: yes, its I/O thread settles it;
333 // `QtWebSocketBackend` under `asyncRegistrationEnabled`: no, waiting
334 // deadlocks the event loop the reply arrives on). `bindWaitPolicy()`
335 // below restores exactly that one bit and nothing else — it never
336 // selects a verb, so the "second path" the removed bool created does
337 // not come back with it.
338 //
339 // 2. **The delivery thread is a parameter.** `Completion<T>` posts its
340 // handlers to the executor it was built with, so the continuation runs
341 // where @p cbExec says and nowhere else — the backend does not choose.
342 // That is the whole of the threading contract the four `*Async`
343 // twins morph#571 removed could only state in prose: they asked
344 // every backend author to deliver on a thread from which `~Bridge`
345 // could not run concurrently, and nothing could check it. See
346 // docs/spec/core/backend.md, "The threading contract, and the half
347 // the surface does not close".
348 // It does not by itself make a `~Bridge` race impossible: it moves the
349 // choice of delivery thread from fifteen backend implementors, none of
350 // which knows what the caller's teardown looks like, to the one caller
351 // that does. `cbExec` is a reference precisely so that "deliver
352 // nowhere" cannot be expressed — a null executor would silently drop
353 // every continuation (see `Completion`'s constructor).
354 //
355 // morph#571 retired the four optional `*Async` twins. The synchronous
356 // verbs above remain, but no longer as a surface any caller chooses:
357 // they are what `bindModelBlocking` — and therefore the *default*
358 // `bindModel` — dispatches to, one request shape at a time. Nothing in
359 // the tree calls them directly any more, which is why a backend that
360 // overrides only `registerModel` still works through `bindModel`
361 // unchanged.

363 /// @brief Acquires a model instance: the structural counterpart of
364 /// `registerModelWithContext` / `registerModelShared` / `attachModel`.
365 ///
366 /// One verb for all three, selected by @p request's shape — see
367 /// `BindRequest`'s table. The default implementation dispatches to exactly
368 /// the legacy verb each shape corresponds to and settles the returned
369 /// `Completion` from this thread, so a backend that has not overridden
370 /// anything keeps its current behaviour bit for bit, including its current
371 /// blocking behaviour: the default **blocks the calling thread** for as
372 /// long as the underlying synchronous verb does. A backend with a genuine
373 /// non-blocking path (morph#568's `QtWebSocketBackend`) overrides this and
374 /// settles the `Completion` when its reply arrives; a blocking backend that
375 /// must not block its caller is wrapped in `SynchronousBackendAdapter`,
376 /// which moves the blocking call to an executor it names.
377 ///
378 /// An exception thrown by the underlying verb is delivered to the
379 /// `Completion`'s `onError` rather than propagated, so a caller has one
380 /// failure channel instead of two.
381 ///
382 /// @param request Owning bind request; moved from.
383 /// @param cbExec Executor the continuation is delivered on. Borrowed: it
384 /// must outlive the returned `Completion`.
385 /// @return A `Completion` resolved with the bound `ModelId`, or rejected
386 /// with the failure.
387 virtual ::morph::async::Completion<::morph::exec::detail::ModelId> bindModel(BindRequest request,
388 ::morph::exec::IExecutor& cbExec) {
389 auto [completion, promise] =
390 ::morph::async::Completion<::morph::exec::detail::ModelId>::makeSettleable(&cbExec);
391 try {
392 promise.resolve(bindModelBlocking(std::move(request)));
393 } catch (...) {
394 promise.reject(std::current_exception());
395 }
396 return std::move(completion);
397 }

432 /// @brief Whether a caller may block until this backend's
433 /// `bindModel`/`promoteModel` completions settle.
434 ///
435 /// Answers the one question `Completion` cannot: an unsettled `Completion`
436 /// looks the same whether the reply is coming from a thread the caller does
437 /// not own or from the caller's own event loop. Only a frame that would
438 /// otherwise stop and wait asks it — `Bridge::registerHandlerImpl` (a
439 /// synchronous entry point that must hand back a *bound* instance),
440 /// `Bridge::switchBackend`'s staging phase, and
441 /// `Bridge::installReconnectHandler`'s handler, which is the one that runs
442 /// on the backend's own transport thread and so is the one a wrong answer
443 /// deadlocks outright (morph#615). The asynchronous entry points never wait
444 /// and never consult it.
445 ///
446 /// A backend that returns `kCallerMayBlock` (the default) commits to
447 /// settling every `Completion` it returns exactly once without any further
448 /// call from the caller. Every backend that does not override `bindModel`
449 /// satisfies that trivially: the default settles before it returns.
450 ///
451 /// @return `BindWait::kCallerMayBlock` unless overridden.
452 [[nodiscard]] virtual BindWait bindWaitPolicy() const noexcept { return BindWait::kCallerMayBlock; }

454 /// @brief Runs @p request against the legacy synchronous verbs, blocking.
455 ///
456 /// Factored out of `bindModel`'s default implementation so that
457 /// `SynchronousBackendAdapter` runs the *same* dispatch on its own executor
458 /// instead of restating it — one definition of "which legacy verb does this
459 /// request shape mean", not two that can drift apart.
460 ///
461 /// Each branch is the verb the corresponding call site uses today, so
462 /// routing a plain registration through `attachModel` (which would also
463 /// have worked, since its default degrades) cannot change behaviour for a
464 /// backend that overrides only some of the three.
465 ///
466 /// @param request Owning bind request; moved from.
467 /// @return The bound `ModelId`.
468 ::morph::exec::detail::ModelId bindModelBlocking(BindRequest request) {
469 InstanceIdentity const identity{.contextKey = request.contextKey, .primary = request.primary};
470 if (request.current.v != 0U) {
471 return attachModel(request.typeId, std::move(request.factory), identity, request.current);
472 }
473 if (!request.primary.empty()) {
474 return registerModelShared(request.typeId, std::move(request.factory), identity);
475 }
476 return registerModelWithContext(request.typeId, std::move(request.factory), request.contextKey);
477 }

657/// @brief Makes a blocking backend satisfy the structural registration surface
658/// without blocking the caller — and without touching the backend.
659///
660/// A decorator, not a base class: it wraps an existing `IBackend` and forwards
661/// every verb to it, overriding only `bindModel`/`promoteModel` to run the
662/// wrapped backend's *synchronous* control call on an executor this adapter
663/// names, then settle the returned `Completion`. That is the whole trick, and
664/// it is why migrating the rest of morph#522's set is a set of migrations
665/// rather than a set of rewrites: a backend with no non-blocking path of its
666/// own (every backend in the tree except `QtWebSocketBackend`) reaches the new
667/// surface by being wrapped, not by being rewritten.
668///
669/// @par What it does and does not change
670/// The wrapped backend still blocks — nothing here makes a nested event loop
671/// or a socket round trip non-blocking. What changes is **which thread pays**:
672/// the blocking call happens on the executor passed at construction, so the
673/// caller's thread returns from `bindModel` immediately with an unresolved
674/// `Completion`. A single-threaded WASM main thread has no such executor to
675/// offer and is therefore not what this adapter is for; that case needs a
676/// backend with a genuinely non-blocking path (morph#568).
677///
678/// @par Why the executor is required rather than optional
679/// "Where does the blocking happen" is the only question this class exists to
680/// answer, so it is a constructor parameter with no default. An adapter that
681/// silently ran the call inline when handed nothing would be a `bindModel`
682/// that blocks on some configurations and not others — the same
683/// contract-by-configuration the surface is replacing.
684///
685/// @par Ordering
686/// Control calls are serialised onto one strand, so the wrapped backend sees
687/// them one at a time, as it did when the blocking call itself serialised
688/// callers. `~SynchronousBackendAdapter` waits for any in-flight control call
689/// to finish (`StrandExecutor`'s destructor does), so a reply can never land
690/// in a destroyed adapter; the executor must therefore still be running tasks
691/// when this adapter is destroyed, on the same terms as `StrandExecutor`'s own
692/// `base` (see docs/spec/concurrency_and_lifetimes.md, "Destruction ordering").
693///
694/// @par Reconnect handlers
695/// A control call issued from a reconnect handler runs on the strand, never on
696/// the wrapped backend's transport thread, so a backend whose reply can only
697/// be delivered by the thread that is running the reconnect handler does not
698/// wait on itself. Whether that is enough to settle `SocketBackend`'s
699/// documented reconnect hazard is morph#569's question, not a claim made here.
700// NOLINTNEXTLINE(cppcoreguidelines-special-member-functions)

867 /// @brief Rejects the completions *this adapter* produced, then forwards.
868 ///
869 /// Not a plain forward, unlike everything else in this block, and for the
870 /// same reason `bindWaitPolicy()` is not: the two verbs this adapter
871 /// reshapes produce completions the wrapped backend has never heard of.
872 /// A `bindModel` here settles from a task on `_control`, so
873 /// `_inner->cancelPending` reaches nothing of it — before morph#619 a bind
874 /// dispatched through this adapter went on to resolve **successfully**
875 /// after cancellation, which is the exact opposite of what
876 /// `IBackend::cancelPending` promises ("after this call, any later
877 /// `setValue`/`setException` on those states is a no-op").
878 ///
879 /// The adapter's own promises are rejected first and the forward happens
880 /// second: the strand task is still running `op()` while this executes, and
881 /// rejecting before handing control to the wrapped backend keeps that
882 /// window as short as the caller's own call. A task that finished first
883 /// wins — its completion was not "still pending" — and a task that finishes
884 /// after finds the promise settled, which `CompletionState::setValue`'s
885 /// `if (ready) return;` makes a no-op.
886 ///
887 /// **What this does not do:** a task already queued on `_control` still
888 /// runs its blocking control call against the wrapped backend after this
889 /// returns. The caller is told the bind was cancelled, but the registration
890 /// may still happen — morph#636, since stopping it needs the task to check
891 /// before calling `op()`, not the promise to be settled after it.
892 /// @param exc Exception delivered to every still-pending completion, this
893 /// adapter's own and then the wrapped backend's.
894 void cancelPending(const std::exception_ptr& exc) override {
895 std::vector<std::weak_ptr<BindPromise>> snapshot;
896 {
897 std::scoped_lock const lock{_pendingMtx};
898 snapshot.swap(_pending);
899 _compactAt = kPendingCompactFloor;
900 }
901 for (auto& weak : snapshot) {
902 if (auto promise = weak.lock()) {
903 promise->reject(exc);
904 }
905 }
906 _inner->cancelPending(exc);
907 }

926 /// @brief Posts @p op to the control strand and settles a `Completion` with its outcome.
927 ///
928 /// The posted task captures the wrapped backend's `shared_ptr` and the
929 /// promise, never `this`, so nothing it touches depends on the adapter
930 /// still existing.
931 /// @tparam Op Callable returning the `ModelId` the completion resolves with.
932 /// @param cbExec Executor the continuation is delivered on.
933 /// @param op The blocking control call to run on the strand.
934 /// @return A `Completion` settled by @p op's outcome.
935 template <typename Op>
936 ::morph::async::Completion<::morph::exec::detail::ModelId> dispatch(::morph::exec::IExecutor& cbExec, Op op) {
937 using Settled = ::morph::async::Completion<::morph::exec::detail::ModelId>;
938 auto [completion, promise] = Settled::makeSettleable(&cbExec);
939 auto shared = std::make_shared<Settled::Promise>(std::move(promise));
940 // Tracked *before* the post, not after: a `cancelPending` that lands in
941 // between would otherwise find an empty list and leave a completion
942 // that is genuinely pending uncancelled. Rejecting a promise whose task
943 // has not started yet is safe — the task's own `resolve` then finds the
944 // state ready and returns (morph#619).
945 trackPending(shared);
946 _control.post(kControlStrand, [shared, op = std::move(op)]() mutable {
947 try {
948 shared->resolve(op());
949 } catch (...) {
950 shared->reject(std::current_exception());
951 }
952 });
953 return std::move(completion);
954 }
955
956 /// @brief Records @p promise as cancellable until its task settles it.
957 ///
958 /// The strand task holds the only `shared_ptr` to the promise, so an entry
959 /// here expires exactly when that task is destroyed — "still pending" needs
960 /// no separate bookkeeping and no erase on the success path.
961 ///
962 /// Swept on the same amortised schedule as `LocalBackend::trackPending`
963 /// (morph#528): dead entries are reclaimed only when the list reaches
964 /// `_compactAt`, which each sweep re-arms at twice the surviving count, so
965 /// the per-dispatch cost is O(1) and the list stays bounded at twice the
966 /// live count plus the floor. Control calls are serialised onto one strand,
967 /// so in practice the live count is one and the floor is never reached;
968 /// without the sweep the list would still grow without bound on an adapter
969 /// whose `cancelPending` is never called.
970 /// @param promise Promise to reject if `cancelPending` runs before its task settles it.
971 void trackPending(const std::shared_ptr<BindPromise>& promise) {
972 std::scoped_lock const lock{_pendingMtx};
973 if (_pending.size() >= _compactAt) {
974 std::erase_if(_pending, [](const auto& weak) { return weak.expired(); });
975 _compactAt = std::max(kPendingCompactFloor, _pending.size() * 2);
976 }
977 _pending.emplace_back(promise);
978 }
979
980 /// @brief The single strand key every control call shares, so they run one
981 /// at a time. Not a real model id: this `StrandExecutor` is private
982 /// to the adapter and shares no key space with any backend's own.
983 static constexpr ::morph::exec::detail::ModelId kControlStrand{1};
984
985 /// @brief Smallest size at which `trackPending` sweeps; see `LocalBackend`'s.
986 static constexpr std::size_t kPendingCompactFloor = 32;
987
988 std::shared_ptr<detail::IBackend> _inner;
989 ::morph::exec::detail::StrandExecutor _control;
990 mutable std::mutex _pendingMtx;
991 // Every `bindModel`/`promoteModel` promise handed to a `_control` task and
992 // not yet settled by it. Weak, so a settled task's promise drops out on its
993 // own; guarded by `_pendingMtx`, because `cancelPending` is called from
994 // `Bridge`'s thread while `dispatch` runs on whichever thread called it.
995 std::vector<std::weak_ptr<BindPromise>> _pending;
996 // Size at which `trackPending` next sweeps `_pending`; re-armed at twice
997 // the surviving count. Guarded by `_pendingMtx` with `_pending` itself.
998 std::size_t _compactAt = kPendingCompactFloor;
999};

1107 /// @brief Schedules `onBackendChanged()` on each change-aware model's strand. Thread-safe.
1108 ///
1109 /// Only models recorded in `_changeAware` — maintained by `createAndTrack`/

1112 /// `dynamic_cast` and no scan of models that never opted in. Each such
1113 /// model's `onBackendChanged()` (the `IModelHolder` base virtual) is
1114 /// **posted onto that model's own strand** (the same per-`ModelId` serial
1115 /// queue `execute` uses), rather than invoked inline on the caller's thread.
1116 /// Two properties follow, and they are the whole point:
1117 ///
1118 /// - **Strand-serialised, lock-free model code.** `onBackendChanged()` runs
1119 /// on the pool inside the model's strand, so it never overlaps an
1120 /// `execute()` on the same model. A model reacting to a backend switch
1121 /// (e.g. draining an offline queue and mutating counters) needs no locking
1122 /// of its own state — exactly what `offline.md` promises.
1123 /// - **Not under `Bridge::_mtx`.** `Bridge::switchBackend` calls this while
1124 /// holding `_mtx`, but only the cheap `post()` runs there; the model body
1125 /// runs later on a pool thread. A model that re-enters the bridge from
1126 /// `onBackendChanged()` (`switchBackend`/`registerHandler`/`deregisterHandler`)
1127 /// therefore acquires `_mtx` freshly on the strand thread instead of
1128 /// deadlocking on a lock the switch caller still holds.
1129 ///

1131 /// concurrent `deregisterModel` cannot free the model out from under its
1132 /// pending notification (mirrors `execute`'s holder capture).

1150 /// @brief Schedules `call.localOp` on the model's strand and returns a `Completion`.
1151 ///
1152 /// The completion resolves with the opaque result on the strand thread and
1153 /// the callbacks are delivered via @p cbExec.
1154 ///
1155 /// @param mid Target model id.
1156 /// @param call Bundled action; `localOp` is the only field used here.
1157 /// @param cbExec Executor for delivering callbacks.
1158 /// @return Completion that will carry the result or an exception.
1159 ::morph::async::Completion<std::shared_ptr<void>> execute(::morph::exec::detail::ModelId mid,
1160 detail::ActionCall call,
1161 ::morph::exec::IExecutor* cbExec) override {
1162 auto compState = std::make_shared<::morph::async::detail::CompletionState<std::shared_ptr<void>>>();
1163 ::morph::async::Completion<std::shared_ptr<void>> comp{compState, cbExec};
1164
1165 std::shared_ptr<::morph::model::detail::IModelHolder> holder;
1166 std::shared_ptr<detail::HydrationState> hydration;
1167 {
1168 std::scoped_lock const lock{_regMtx};
1169 // One lookup for the holder and its hydration state together: they
1170 // are fields of one record now, not entries in two maps kept in
1171 // lockstep by convention.
1172 if (const auto* inst = _instances.find(mid)) {
1173 holder = inst->holder;
1174 hydration = inst->hydration;
1175 }
1176 }
1177 if (!holder) {
1178 compState->setException(
1179 std::make_exception_ptr(std::runtime_error("model not found: id=" + std::to_string(mid.v))));
1180 return comp;
1181 }
1182 trackPending(compState);
1183 auto localOp = std::move(call.localOp);
1184 auto session = std::move(call.session);
1185 auto modelTypeId = std::move(call.modelTypeId);
1186 auto actionTypeId = std::move(call.actionTypeId);
1187 // Captured by shared_ptr, never by raw `this`: see the Global
1188 // Constraints note on `~StrandExecutor`'s member-destruction-order
1189 // subtlety. A shared_ptr copy has its own lifetime, independent of
1190 // LocalBackend's, so it stays valid even if the backend is torn down
1191 // while this task is still queued or running. `hydration` follows the
1192 // same rule and may be null (a private instance has no entry).
1193 auto inFlightCounter = _inFlight;
1194 auto const inFlightAfterInc = inFlightCounter->fetch_add(1, std::memory_order_relaxed) + 1;
1195 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeInFlight,
1196 static_cast<double>(inFlightAfterInc));
1197 _strand.post(mid, [localOp = std::move(localOp), holder = std::move(holder), compState,
1198 session = std::move(session), modelTypeId = std::move(modelTypeId),
1199 actionTypeId = std::move(actionTypeId), inFlightCounter, hydration]() mutable {
1200 auto const start = std::chrono::steady_clock::now();
1201 auto const spanId = ::morph::observe::detail::beginSpan(session.requestId, modelTypeId, actionTypeId);
1202 bool ok = false;
1203 // Resolve `compState` only after every metric and `endSpan` below are
1204 // recorded — nothing synchronizes a `.then()`/`.onError()` callback
1205 // (delivered via `cbExec`, which may run inline/synchronously) with
1206 // anything after `setValue`/`setException` returns, so resolving first
1207 // would let the caller observe completion before these metrics are
1208 // emitted. This is a real race, not just a theoretical one.
1209 std::shared_ptr<void> value;
1210 std::exception_ptr error;
1211 try {
1212 ::morph::session::detail::ScopedContext const scoped{session};
1213 value = localOp(*holder);
1214 ok = true;
1215 } catch (...) {
1216 error = std::current_exception();
1217 }
1218 // Settle hydration the moment the first action's outcome is known —
1219 // before `endSpan`, before any metric, and before the `Completion`
1220 // resolves. Each of those hands control to host code that is free
1221 // to attach to this instance's key, and an attacher reaching the
1222 // directory while the outcome is known but unrecorded is handed an
1223 // instance whose first action has already failed — exactly what
1224 // docs/spec/core/shared_instances.md's Failure modes section says
1225 // must not happen. Only the *first* action settles it; `settle` is
1226 // a single compare-exchange and ignores every later call.
1227 if (hydration) {
1228 hydration->settle(ok);
1229 }
1230 ::morph::observe::detail::endSpan(spanId, ok);
1231 auto const elapsedMs =
1232 std::chrono::duration<double, std::milli>(std::chrono::steady_clock::now() - start).count();
1233 std::array<std::pair<std::string_view, std::string_view>, 2> const tags{
1234 {{"modelType", modelTypeId}, {"actionType", actionTypeId}}};
1235 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeLatencyMs, elapsedMs, tags);
1236 if (!ok) {
1237 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeErrors, 1.0, tags);
1238 }
1239 auto const inFlightAfterDec = inFlightCounter->fetch_sub(1, std::memory_order_relaxed) - 1;
1240 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeInFlight,
1241 static_cast<double>(inFlightAfterDec));
1242 // Resolve last: the Completion is still settled exactly once, only
1243 // its position relative to the now-recorded instrumentation moved.
1244 if (ok) {
1245 compState->setValue(std::move(value));
1246 } else {
1247 compState->setException(error);
1248 }
1249 });
1250 return comp;
1251 }

1319 /// @brief Records @p state in the pending list, compacting it amortised-O(1).
1320 ///
1321 /// The list is append-only between compactions; dead entries are swept only
1322 /// when its size reaches `_compactAt`, which each sweep re-arms at twice the
1323 /// number of entries that survived it. Doubling the threshold off the live
1324 /// count is what makes the sweep amortised: a sweep costs O(size), and at
1325 /// least `_compactAt / 2` appends must happen before the next one, so the
1326 /// per-append cost is O(1) however deep the queue gets. The list is
1327 /// correspondingly bounded at twice the live count (plus the floor), which
1328 /// is the whole price of dropping the per-dispatch scan.
1329 ///
1330 /// Before morph#528 this swept on *every* append, so admitting one call with
1331 /// `n` in flight cost `n` atomic `weak_ptr::expired()` loads under
1332 /// `_pendingMtx` and a burst of `n` cost O(n²) — measured at 362ms of pure
1333 /// admission time for 32k queued executes against one slow model, against
1334 /// 7.6ms without the sweep.
1335 ///
1336 /// Purely a cost change: `cancelPending` still sees every live state,
1337 /// because a dead entry is one whose `CompletionState` is already gone and
1338 /// which `cancelPending`'s `weak.lock()` has always skipped. Carrying dead
1339 /// entries for longer changes nothing it observes.
1340 /// @param state Completion state to track until it expires or is cancelled.
1341 void trackPending(const std::shared_ptr<::morph::async::detail::CompletionState<std::shared_ptr<void>>>& state) {
1342 std::scoped_lock const lock{_pendingMtx};
1343 if (_pending.size() >= _compactAt) {
1344 std::erase_if(_pending, [](const auto& weak) { return weak.expired(); });
1345 _compactAt = std::max(kPendingCompactFloor, _pending.size() * 2);
1346 }
1347 _pending.emplace_back(state);
1348 }
