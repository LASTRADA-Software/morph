35/// @brief All the information needed to dispatch one action call through a backend.
36///
37/// Backends that execute locally use `localOp` directly. Remote backends
38/// serialize via `serializeAction` and deserialize replies via `deserializeResult`.
39///
40/// @par Why function *pointers*, and why the action travels beside them
41/// The three callables are plain function pointers and the action object they
42/// operate on rides in `action`, rather than each callable capturing its own
43/// handle to it. That is a deliberate allocation decision, not a style
44/// preference. `Bridge::executeVia` builds an `ActionCall` on **every** call,
45/// including one that a `LocalBackend` will serve and that will therefore never
46/// touch `serializeAction` or `deserializeResult`. A `std::function` whose
47/// target is not trivially copyable cannot use libstdc++'s small-object buffer,
48/// so a lambda capturing a `shared_ptr<Action>` heap-allocates — three captured
49/// callables cost up to three allocations per dispatch whichever path the call
50/// takes. Stateless operations parameterised on the action cost none: the
51/// per-`(Model, Action)` behaviour is a compile-time constant, addressed rather
52/// than copied. Measured with `morph_bench_alloc`: this shape and the two
53/// `string_view` ids below together account for 3 of the allocations a local
54/// round trip would otherwise make, out of 17.
55///
56/// @par Lifetime contract for the callables
57/// `serializeAction` and `localOp` take the action as an opaque pointer and do
58/// **not** own it: `action` does. A backend that defers either call past the
59/// `ActionCall`'s own lifetime must carry a copy of the `action` handle with
60/// it — `LocalBackend::execute` does exactly that when it posts to the strand.
61/// `deserializeResult` never reads the action and so may outlive it, which is
62/// what lets the remote backends store it in their pending-reply table.
63struct ActionCall {
64 /// @brief String id of the target model type (from `ModelTraits`).
65 ///
66 /// A view, not a copy. `ModelTraits<Model>::typeId()` is `constexpr` and
67 /// returns a view of the string literal `BRIDGE_REGISTER_MODEL` was given,
68 /// so the referent has static storage duration and outlives every call.
69 /// A hand-built `ActionCall` must observe the same rule: the id must
70 /// outlive the dispatch, which a string literal does and a temporary
71 /// `std::string` does not.
72 std::string_view modelTypeId;
73
74 /// @brief String id of the action type (from `ActionTraits`).
75 ///
76 /// Same storage rule as `modelTypeId`.
77 std::string_view actionTypeId;
78
79 /// @brief Type-erased owner of the action object `serializeAction` and
80 /// `localOp` read.
81 ///
82 /// Null only for a hand-built call whose callables ignore their action
83 /// argument.
84 std::shared_ptr<void> action;
85
86 /// @brief Serialises `action` to JSON. Called only on the remote path.
87 std::string (*serializeAction)(const void* action) = nullptr;
88
89 /// @brief Deserialises a JSON reply into the opaque result `shared_ptr<void>`.
90 std::shared_ptr<void> (*deserializeResult)(std::string_view json) = nullptr;
91
92 /// @brief Executes `action` directly against a model holder. Used on the local path.
93 ///
94 /// Takes the action as a mutable pointer because the local path recomputes
95 /// an action's computed fields in place before the validator or the model
96 /// sees it (`Bridge::executeVia`, `morph::forms::recomputeAll`).
97 std::shared_ptr<void> (*localOp)(::morph::model::detail::IModelHolder& holder, void* action) = nullptr;
98
99 /// @brief Session context attached to this call.
100 ///
101 /// Local backends thread it through a thread-local before invoking `localOp`;
102 /// remote backends serialise it into the wire envelope.
103 ::morph::session::Context session;
104
105 /// @brief Invokes `serializeAction` on the action this call owns.
106 ///
107 /// The one place the borrow in `serializeAction`'s signature is closed, so
108 /// no remote backend has to remember to pair the pointer with its owner --
109 /// and the one place the null check lives. An empty `std::function` used to
110 /// raise `std::bad_function_call` here; a null function pointer would be
111 /// undefined behaviour instead, so the check is explicit and names the
112 /// field.
113 ///
114 /// @return The JSON body for the wire envelope.
115 /// @throws std::runtime_error if `serializeAction` is null.
116 [[nodiscard]] std::string serializeBody() const {
117 if (serializeAction == nullptr) {
118 throw std::runtime_error{"ActionCall::serializeAction is null: nothing to serialise"};
119 }
120 return serializeAction(action.get());
121 }
122};

140/// @brief One *bind* request: everything needed to acquire a model instance.
141///
142/// The request half of the structural registration surface
143/// (`IBackend::bindModel`). It replaces the three separate acquire verbs
144/// (`registerModelWithContext`, `registerModelShared`, `attachModel`) with one
145/// request whose *shape* selects the behaviour, because the three differ only
146/// in which fields are populated:
147///
148/// | `primary` | `current` | Equivalent legacy verb |
149/// |---|---|---|
150/// | empty | `0` | `registerModelWithContext(typeId, factory, contextKey)` |
151/// | non-empty | `0` | `registerModelShared(typeId, factory, identity)` |
152/// | non-empty | non-zero | `attachModel(typeId, factory, identity, current)` |
153///
154/// Unlike `InstanceIdentity`, every string here is **owned**. That is not a
155/// style preference: a bind may outlive the frame that issued it, so a
156/// `string_view` into the caller's stack is a dangling read waiting for a
157/// backend that copies its envelope after the dispatch call returns rather
158/// than before it. The synchronous verbs below take views and are safe only
159/// because they do not return until the backend has finished with them.
160struct BindRequest {
161 /// @brief String type-id of the model to instantiate (from `ModelTraits`).
162 std::string typeId;
163
164 /// @brief Callable that constructs the `IModelHolder`. Local path only; a
165 /// wire backend never calls it, and an attach to a live shared
166 /// instance does not call it either.
167 std::function<std::unique_ptr<::morph::model::detail::IModelHolder>()> factory;
168
169 /// @brief Entity key for the action log; empty if none. See `journal::LogEntry::entityKey`.
170 std::string contextKey;
171
172 /// @brief Canonical string encoding of the primary key. Empty means "no
173 /// identity": the bind produces a private instance that never enters
174 /// the shared directory.
175 std::string primary;
176
177 /// @brief Instance currently held, or `ModelId{0}` if none. Non-zero makes
178 /// this bind a *re-point*: the backend names what it is re-pointing
179 /// from, exactly as `attachModel` does.
180 ::morph::exec::detail::ModelId current{};
181};

199/// @brief Whether a caller holding an unsettled `bindModel`/`promoteModel`
200/// `Completion` may block its own thread until that `Completion`
201/// settles.
202///
203/// This is the one thing `bindModel`'s signature cannot say, and it has to be
204/// said: two shipped backends both return an unsettled `Completion` from
205/// `bindModel`, and `Bridge::registerHandlerImpl` — a synchronous entry point
206/// that hands its caller a `BridgeHandler` usable on the next line — must wait
207/// for one of them and must not wait for the other. From the `Completion`
208/// alone the two are indistinguishable.
209///
210/// It is deliberately **not** a `bool` selecting a verb (see "The structural
211/// registration surface" below, point 1). Such a `bool` would make every call
212/// site carry two paths and let a backend be half-migrated. This chooses
213/// nothing: there is still exactly
214/// one verb, called unconditionally, and exactly one continuation. It says
215/// only whether the thread that issued the call is allowed to stop and wait
216/// for the continuation it already registered.
217enum class BindWait : std::uint8_t {
218 /// @brief The completion settles without the calling thread's
219 /// participation — inside the call, or on a thread the caller does
220 /// not own. A caller may block until it settles.
221 ///
222 /// The default, and correct for every backend that has not overridden
223 /// `bindModel` (the default settles before it returns) as well as for
224 /// `SocketBackend`, whose I/O thread settles the completion. A backend
225 /// that returns this **must** settle every `Completion` it hands out
226 /// exactly once without further calls from the caller — including on
227 /// transport failure and on `cancelPending`/destruction — or a caller that
228 /// waits will wait forever.
229 kCallerMayBlock,
230
231 /// @brief The completion cannot settle while the calling thread is blocked
232 /// in a wait, or blocking it would defeat the point of this
233 /// backend. A caller must register its continuation and return.
234 ///
235 /// Two backends say this, for two different reasons:
236 ///
237 /// - `QtWebSocketBackend` with `Config::asyncRegistrationEnabled` set: the
238 /// reply arrives through the Qt event loop of the thread that issued the
239 /// call, so waiting is a deadlock. On a WASM main thread it aborts the
240 /// page, which is the case this surface exists for.
241 /// - `SynchronousBackendAdapter`: it exists precisely to move a blocking
242 /// call off the caller's thread, so a caller that then waits for it has
243 /// bought nothing — and if the caller happens to be running on the
244 /// adapter's own executor, has deadlocked.
245 kCallerMustNotBlock,
246};

310 /// @brief Re-points from @p current to the shared instance holding @p primary.
311 ///
312 /// The default implementation acquires the replacement via
313 /// `registerModelShared` first and only then releases @p current (when
314 /// non-zero), so a same-key re-attach never destroys and recreates the
315 /// instance it already holds, and a throwing acquire never strands the
316 /// caller with neither instance. Backends behind a wire protocol override
317 /// this with the single `attach` request so a re-pointing client cannot
318 /// lose its slot to `LimitPolicy::maxLiveModels` between the release and
319 /// the acquire.
320 ///
321 /// @param typeId String type-id of the model.
322 /// @param factory Callable that constructs the `IModelHolder` (local path only).
323 /// @param identity Entity key for the action log plus the directory primary key.
324 /// @param current Instance currently held, or `ModelId{0}` if none.
325 /// @return Id of the instance now attached to.
326 virtual ::morph::exec::detail::ModelId attachModel(
327 const std::string& typeId, std::function<std::unique_ptr<::morph::model::detail::IModelHolder>()> factory,
328 InstanceIdentity identity, ::morph::exec::detail::ModelId current) {
329 // Acquire the replacement before releasing `current`, not after: a
330 // same-key re-attach (registerModelShared finds `current` already
331 // live in the directory and takes a second reference to it) then
332 // hands back the identical id instead of destroying and recreating
333 // it, and a throwing acquire never touches `current` at all, so the
334 // caller's existing instance is never stranded by a failed attach.
335 // Either way, exactly one reference on `current` needs releasing
336 // afterward: the genuinely old instance's, if this re-pointed to a
337 // different key; or the redundant one registerModelShared just took,
338 // if it did not.
339 auto next = registerModelShared(typeId, std::move(factory), identity);
340 if (current.v != 0U) {
341 deregisterModel(current);
342 }
343 return next;
344 }

347 ///

349 /// key work without losing state: an action that creates its own entity runs

376 // ── The structural registration surface ──────────────────────────────
377 //
378 // `bindModel`/`promoteModel` are the five verbs above with the continuation
379 // made mandatory. Two properties carry the design, and both are visible in
380 // the signature rather than only in a comment:
381 //
382 // 1. **The continuation is not opt-in.** There is no `bool` saying "I
383 // have no async path, call the other one" — so no call site carries a
384 // second path, and a backend cannot be *half* migrated. A blocking
385 // backend satisfies the surface through the default implementations
386 // below, or without blocking the caller at all through
387 // `SynchronousBackendAdapter`.
388 //
389 // Whether the *calling thread* may wait for that continuation is a
390 // separate question, and the signature cannot answer it either: two
391 // shipped backends return an unsettled `Completion` and give opposite
392 // answers (`SocketBackend`: yes, its I/O thread settles it;
393 // `QtWebSocketBackend` under `asyncRegistrationEnabled`: no, waiting
394 // deadlocks the event loop the reply arrives on). `bindWaitPolicy()`
395 // below carries exactly that one bit and nothing else — it never
396 // selects a verb, so it creates no second path.
397 //
398 // 2. **The delivery thread is a parameter.** `Completion<T>` posts its
399 // handlers to the executor it was built with, so the continuation runs
400 // where @p cbExec says and nowhere else — the backend does not choose.
401 // A threading contract stated only in prose would ask every backend
402 // author to deliver on a thread from which `~Bridge` cannot run
403 // concurrently, and nothing could check it. See
404 // docs/spec/core/backend.md, "The threading contract, and the half
405 // the surface does not close".
406 // It does not by itself make a `~Bridge` race impossible: it moves the
407 // choice of delivery thread from fifteen backend implementors, none of
408 // which knows what the caller's teardown looks like, to the one caller
409 // that does. `cbExec` is a reference precisely so that "deliver
410 // nowhere" cannot be expressed — a null executor would silently drop
411 // every continuation (see `Completion`'s constructor).
412 //
413 // The synchronous verbs above remain, but not as a surface any caller
414 // chooses: they are what `bindModelBlocking` — and therefore the *default*
415 // `bindModel` — dispatches to, one request shape at a time. Nothing in the
416 // tree calls them directly, which is why a backend that overrides only
417 // `registerModel` still works through `bindModel`.
418
419 /// @brief Acquires a model instance: the structural counterpart of
420 /// `registerModelWithContext` / `registerModelShared` / `attachModel`.
421 ///
422 /// One verb for all three, selected by @p request's shape — see
423 /// `BindRequest`'s table. The default implementation dispatches to exactly
424 /// the legacy verb each shape corresponds to and settles the returned
425 /// `Completion` from this thread, so a backend that has not overridden
426 /// anything keeps its current behaviour bit for bit, including its current
427 /// blocking behaviour: the default **blocks the calling thread** for as
428 /// long as the underlying synchronous verb does. A backend with a genuine
429 /// non-blocking path (`QtWebSocketBackend`) overrides this and
430 /// settles the `Completion` when its reply arrives; a blocking backend that
431 /// must not block its caller is wrapped in `SynchronousBackendAdapter`,
432 /// which moves the blocking call to an executor it names.
433 ///
434 /// An exception thrown by the underlying verb is delivered to the
435 /// `Completion`'s `onError` rather than propagated, so a caller has one
436 /// failure channel instead of two.
437 ///
438 /// @param request Owning bind request; moved from.
439 /// @param cbExec Executor the continuation is delivered on. Borrowed: it
440 /// must outlive the returned `Completion`.
441 /// @return A `Completion` resolved with the bound `ModelId`, or rejected
442 /// with the failure.
443 virtual ::morph::async::Completion<::morph::exec::detail::ModelId> bindModel(BindRequest request,
444 ::morph::exec::IExecutor& cbExec) {
445 auto [completion, promise] =
446 ::morph::async::Completion<::morph::exec::detail::ModelId>::makeSettleable(&cbExec);
447 try {
448 promise.resolve(bindModelBlocking(std::move(request)));
449 } catch (...) {
450 promise.reject(std::current_exception());
451 }
452 return std::move(completion);
453 }

488 /// @brief Whether a caller may block until this backend's
489 /// `bindModel`/`promoteModel` completions settle.
490 ///
491 /// Answers the one question `Completion` cannot: an unsettled `Completion`
492 /// looks the same whether the reply is coming from a thread the caller does
493 /// not own or from the caller's own event loop. Only a frame that would
494 /// otherwise stop and wait asks it — `Bridge::registerHandlerImpl` (a
495 /// synchronous entry point that must hand back a *bound* instance),
496 /// `Bridge::switchBackend`'s staging phase, and
497 /// `Bridge::installReconnectHandler`'s handler, which is the one that runs
498 /// on the backend's own transport thread and so is the one a wrong answer
499 /// deadlocks outright. The asynchronous entry points never wait and never
500 /// consult it.
501 ///
502 /// A backend that returns `kCallerMayBlock` (the default) commits to
503 /// settling every `Completion` it returns exactly once without any further
504 /// call from the caller. Every backend that does not override `bindModel`
505 /// satisfies that trivially: the default settles before it returns.
506 ///
507 /// @return `BindWait::kCallerMayBlock` unless overridden.
508 [[nodiscard]] virtual BindWait bindWaitPolicy() const noexcept { return BindWait::kCallerMayBlock; }

511 ///
512 /// Factored out of `bindModel`'s default implementation so that
513 /// `SynchronousBackendAdapter` runs the *same* dispatch on its own executor

515 /// request shape mean", not two that can drift apart.
516 ///
517 /// Each branch is the verb the corresponding call site uses today, so
518 /// routing a plain registration through `attachModel` (which would also
519 /// have worked, since its default degrades) cannot change behaviour for a
520 /// backend that overrides only some of the three.
521 ///

529 if (!request.primary.empty()) {
530 return registerModelShared(request.typeId, std::move(request.factory), identity);
531 }
532 return registerModelWithContext(request.typeId, std::move(request.factory), request.contextKey);
533 }

566 /// @brief Dispatches @p call and settles @p sink with its outcome.
567 ///
568 /// The same dispatch as `execute`, with the result delivered to a sink the
569 /// caller already owns instead of to a fresh `Completion` the caller then
570 /// has to forward into its own. `Bridge::executeVia` hands down a sink that
571 /// **is** the typed completion state the caller was given, so there is no
572 /// forwarding block between the two — no erased `CompletionState`, no
573 /// `.then`/`.onError` closures, no second pair of handler vectors, and one
574 /// posted settle task instead of two.
575 ///
576 /// @par Why this has a default rather than being pure
577 /// `IBackend::execute` is implemented by five production backends and
578 /// roughly ten test doubles. A pure virtual here would be a fifteen-site
579 /// change to gain an allocation on one path. The default below is exactly
580 /// the forwarding block it replaces, so a backend that does not override it
581 /// costs precisely what it costs today — no gain, no regression — and a
582 /// backend that does gets the whole saving. `LocalBackend` overrides it;
583 /// nothing else does yet.
584 ///
585 /// @par Contract
586 /// Settles @p sink exactly once, through `settleValue` or `settleException`,
587 /// on the same thread and at the same point in the sequence the `execute`
588 /// overload would have resolved its completion. A backend that also has to
589 /// answer `cancelPending` must track the sink, not a state of its own.
590 /// Throwing out of this call is permitted and means the dispatch never
591 /// started — `Bridge::executeVia` undoes its pending count and its deadline
592 /// on that path, exactly as it does for `execute`.
593 ///
594 /// @param mid Target model id.
595 /// @param call Bundled action; moved from.
596 /// @param cbExec Executor for delivering callbacks attached to the caller's
597 /// own completion. A backend passes it along unchanged.
598 /// @param sink Where to settle the outcome. Never null.
599 virtual void executeInto(::morph::exec::detail::ModelId mid, ActionCall call, ::morph::exec::IExecutor* cbExec,
600 std::shared_ptr<::morph::async::detail::ISettleSink> sink) {
601 // Deliberately built from this class's own `execute`, not duplicated:
602 // one definition of what a dispatch is, whichever entry point a caller
603 // uses.
604 execute(mid, std::move(call), cbExec)
605 .then([sink](const std::shared_ptr<void>& value) { sink->settleValue(value); })
606 .onError([sink = std::move(sink)](const std::exception_ptr& exc) { sink->settleException(exc); });
607 }

756/// @brief Makes a blocking backend satisfy the structural registration surface
757/// without blocking the caller — and without touching the backend.
758///
759/// A decorator, not a base class: it wraps an existing `IBackend` and forwards
760/// every verb to it, overriding only `bindModel`/`promoteModel` to run the
761/// wrapped backend's *synchronous* control call on an executor this adapter
762/// names, then settle the returned `Completion`. That is the whole trick, and
763/// it is why a backend with no non-blocking path of its own (every backend in
764/// the tree except `QtWebSocketBackend`) reaches the structural surface by
765/// being wrapped rather than by being rewritten.
766///
767/// @par What it does and does not change
768/// The wrapped backend still blocks — nothing here makes a nested event loop
769/// or a socket round trip non-blocking. What changes is **which thread pays**:
770/// the blocking call happens on the executor passed at construction, so the
771/// caller's thread returns from `bindModel` immediately with an unresolved
772/// `Completion`. A single-threaded WASM main thread has no such executor to
773/// offer and is therefore not what this adapter is for; that case needs a
774/// backend with a genuinely non-blocking path.
775///
776/// @par Why the executor is required rather than optional
777/// "Where does the blocking happen" is the only question this class exists to
778/// answer, so it is a constructor parameter with no default. An adapter that
779/// silently ran the call inline when handed nothing would be a `bindModel`
780/// that blocks on some configurations and not others — the same
781/// contract-by-configuration the surface is replacing.
782///
783/// @par Ordering
784/// Control calls are serialised onto one strand, so the wrapped backend sees
785/// them one at a time, as it did when the blocking call itself serialised
786/// callers. `~SynchronousBackendAdapter` waits for any in-flight control call
787/// to finish (`StrandExecutor`'s destructor does), so a reply can never land
788/// in a destroyed adapter; the executor must therefore still be running tasks
789/// when this adapter is destroyed, on the same terms as `StrandExecutor`'s own
790/// `base` (see docs/spec/concurrency_and_lifetimes.md, "Destruction ordering").
791///
792/// @par Reconnect handlers
793/// A control call issued from a reconnect handler runs on the strand, never on
794/// the wrapped backend's transport thread, so a backend whose reply can only
795/// be delivered by the thread that is running the reconnect handler does not
796/// wait on itself. Whether that is enough to settle `SocketBackend`'s
797/// documented reconnect hazard is not a claim made here.
798// NOLINTNEXTLINE(cppcoreguidelines-special-member-functions)

965 /// @brief Rejects the completions *this adapter* produced, then forwards.
966 ///
967 /// Not a plain forward, unlike everything else in this block, and for the
968 /// same reason `bindWaitPolicy()` is not: the two verbs this adapter
969 /// reshapes produce completions the wrapped backend has never heard of.
970 /// A `bindModel` here settles from a task on `_control`, so
971 /// `_inner->cancelPending` reaches nothing of it: without this override a
972 /// bind dispatched through this adapter goes on to resolve **successfully**
973 /// after cancellation, which is the exact opposite of what
974 /// `IBackend::cancelPending` promises ("after this call, any later
975 /// `setValue`/`setException` on those states is a no-op").
976 ///
977 /// The adapter's own promises are rejected first and the forward happens
978 /// second: the strand task is still running `op()` while this executes, and
979 /// rejecting before handing control to the wrapped backend keeps that
980 /// window as short as the caller's own call. A task that finished first
981 /// wins — its completion was not "still pending" — and a task that finishes
982 /// after finds the promise settled, which `CompletionState::setValue`'s
983 /// `if (ready) return;` makes a no-op.
984 ///
985 /// Settling the promise is only half of it, because it cannot stop work the
986 /// strand has already been handed. Each dispatched task therefore carries a
987 /// cancellation flag next to its promise, and this verb **sets that flag
988 /// before rejecting**: a task still queued on `_control` sees it when it
989 /// reaches the head of the strand and returns without calling `op()`, so
990 /// the blocking control call never reaches the wrapped backend at all.
991 /// Without the flag the caller is told the bind was cancelled while the
992 /// registration goes through anyway — a live instance on a backend whose
993 /// `Bridge` is gone, which nothing will ever `deregisterModel`.
994 ///
995 /// **What this still does not do:** a task already *inside* `op()` cannot
996 /// be recalled. Only the queued-but-not-started window is closed, which is
997 /// all this adapter can close — it has no way to interrupt a blocking verb
998 /// it does not implement. A task that wins the race by a few instructions
999 /// (flag read, then this store) registers exactly as one that had already
1000 /// entered `op()`, and its completion stays rejected either way.
1001 /// @param exc Exception delivered to every still-pending completion, this
1002 /// adapter's own and then the wrapped backend's.
1003 void cancelPending(const std::exception_ptr& exc) override {
1004 std::vector<std::weak_ptr<PendingControl>> snapshot;
1005 {
1006 std::scoped_lock const lock{_pendingMtx};
1007 snapshot.swap(_pending);
1008 _compactAt = kPendingCompactFloor;
1009 }
1010 for (auto& pendingWeak : snapshot) {
1011 if (auto pending = pendingWeak.lock()) {
1012 // Flag first, promise second. A task that reads the flag after
1013 // this store declines to run; one that read it just before
1014 // finds its promise already rejected by the line below. That
1015 // is the narrowest window this ordering leaves.
1016 pending->cancelled.store(true, std::memory_order_release);
1017 pending->promise.reject(exc);
1018 }
1019 }
1020 _inner->cancelPending(exc);
1021 }

1077 /// @return A `Completion` settled by @p op's outcome.
1078 template <typename Op>
1079 ::morph::async::Completion<::morph::exec::detail::ModelId> dispatch(::morph::exec::IExecutor& cbExec, Op op) {
1080 using Settled = ::morph::async::Completion<::morph::exec::detail::ModelId>;
1081 auto [completion, promise] = Settled::makeSettleable(&cbExec);
1082 auto pending = std::make_shared<PendingControl>(std::move(promise));
1083 // Tracked *before* the post, not after: a `cancelPending` that lands in
1084 // between would otherwise find an empty list and leave a completion
1085 // that is genuinely pending uncancelled. Rejecting a promise whose task
1086 // has not started yet is safe — the task's own `resolve` then finds the
1087 // state ready and returns.
1088 trackPending(pending);
1089 _control.post(kControlStrand, [pending, op = std::move(op)]() mutable {
1090 // Checked *before* `op()`: a
1091 // promise settled by `cancelPending` makes the reply a no-op but
1092 // says nothing about the call, and this task is the last place that
1093 // can decline to make it. Read with acquire against
1094 // `cancelPending`'s release store, so a task that observes the flag
1095 // also observes everything the cancelling thread did before setting
1096 // it.
1097 if (pending->cancelled.load(std::memory_order_acquire)) {
1098 return;
1099 }
1100 try {
1101 pending->promise.resolve(op());
1102 } catch (...) {
1103 pending->promise.reject(std::current_exception());
1104 }
1105 });
1106 return std::move(completion);
1107 }

1109 /// @brief Records @p pending as cancellable until its task settles it.
1110 ///
1111 /// The strand task holds the only `shared_ptr` to the record, so an entry
1112 /// here expires exactly when that task is destroyed — "still pending" needs
1113 /// no separate bookkeeping and no erase on the success path.
1114 ///
1115 /// Swept on the same amortised schedule as `LocalBackend::trackPending`:
1116 /// dead entries are reclaimed only when the list reaches
1117 /// `_compactAt`, which each sweep re-arms at twice the surviving count, so
1118 /// the per-dispatch cost is O(1) and the list stays bounded at twice the
1119 /// live count plus the floor. Control calls are serialised onto one strand,
1120 /// so in practice the live count is one and the floor is never reached;
1121 /// without the sweep the list would still grow without bound on an adapter
1122 /// whose `cancelPending` is never called.
1123 /// @param pending Record to cancel and reject if `cancelPending` runs before
1124 /// its task settles it.
1125 void trackPending(const std::shared_ptr<PendingControl>& pending) {
1126 std::scoped_lock const lock{_pendingMtx};
1127 if (_pending.size() >= _compactAt) {
1128 std::erase_if(_pending, [](const auto& weak) { return weak.expired(); });
1129 _compactAt = std::max(kPendingCompactFloor, _pending.size() * 2);
1130 }
1131 _pending.emplace_back(pending);
1132 }

1134 /// @brief The single strand key every control call shares, so they run one
1135 /// at a time. Not a real model id: this `StrandExecutor` is private
1136 /// to the adapter and shares no key space with any backend's own.
1137 static constexpr ::morph::exec::detail::ModelId kControlStrand{1};
1138
1139 /// @brief Smallest size at which `trackPending` sweeps; see `LocalBackend`'s.
1140 static constexpr std::size_t kPendingCompactFloor = 32;
1141
1142 std::shared_ptr<detail::IBackend> _inner;
1143 ::morph::exec::detail::StrandExecutor _control;
1144 mutable std::mutex _pendingMtx;
1145 // Every `bindModel`/`promoteModel` record handed to a `_control` task and
1146 // not yet settled by it. Weak, so a settled task's record drops out on its
1147 // own; guarded by `_pendingMtx`, because `cancelPending` is called from
1148 // `Bridge`'s thread while `dispatch` runs on whichever thread called it.
1149 std::vector<std::weak_ptr<PendingControl>> _pending;
1150 // Size at which `trackPending` next sweeps `_pending`; re-armed at twice
1151 // the surviving count. Guarded by `_pendingMtx` with `_pending` itself.
1152 std::size_t _compactAt = kPendingCompactFloor;
1153};

1261 /// @brief Schedules `onBackendChanged()` on each change-aware model's strand. Thread-safe.
1262 ///
1263 /// Only models recorded in `_changeAware` — maintained by `createAndTrack`/
1264 /// `deregisterModel` from `IModelHolder::isBackendChangeAware()`, a
1265 /// compile-time answer per model type — are visited; there is no
1266 /// `dynamic_cast` and no scan of models that never opted in. Each such
1267 /// model's `onBackendChanged()` (the `IModelHolder` base virtual) is
1268 /// **posted onto that model's own strand** (the same per-`ModelId` serial
1269 /// queue `execute` uses), rather than invoked inline on the caller's thread.
1270 /// Two properties follow, and they are the whole point:
1271 ///
1272 /// - **Strand-serialised, lock-free model code.** `onBackendChanged()` runs
1273 /// on the pool inside the model's strand, so it never overlaps an
1274 /// `execute()` on the same model. A model reacting to a backend switch
1275 /// (e.g. draining an offline queue and mutating counters) needs no locking
1276 /// of its own state — exactly what `offline.md` promises.
1277 /// - **Not under `Bridge::_mtx`.** `Bridge::switchBackend` calls this while
1278 /// holding `_mtx`, but only the cheap `post()` runs there; the model body
1279 /// runs later on a pool thread. A model that re-enters the bridge from
1280 /// `onBackendChanged()` (`switchBackend`/`registerHandler`/`deregisterHandler`)
1281 /// therefore acquires `_mtx` freshly on the strand thread instead of
1282 /// deadlocking on a lock the switch caller still holds.
1283 ///
1284 /// A `shared_ptr` copy of each holder is captured into the posted task so a
1285 /// concurrent `deregisterModel` cannot free the model out from under its
1286 /// pending notification (mirrors `execute`'s holder capture).

1288 std::vector<std::pair<::morph::exec::detail::ModelId, std::shared_ptr<::morph::model::detail::IModelHolder>>>
1289 aware;
1290 {
1291 std::scoped_lock const lock{_regMtx};
1292 aware.reserve(_changeAware.size());
1293 for (auto modelId : _changeAware) {
1294 if (const auto* inst = _instances.find(modelId)) {
1295 aware.emplace_back(modelId, inst->holder);
1296 }
1297 }
1298 }
1299 for (auto& [modelId, holder] : aware) {
1300 _strand.post(modelId, [h = std::move(holder)]() mutable { h->onBackendChanged(); });
1301 }

1304 /// @brief Schedules `call.localOp` on the model's strand and returns a `Completion`.
1305 ///
1306 /// The completion resolves with the opaque result on the strand thread and
1307 /// the callbacks are delivered via @p cbExec.

1310 /// one definition of what a local dispatch does whichever entry point a

1313 /// `executeInto` exists to let `Bridge` avoid.

1315 /// @par Why this is `final`
1316 /// `Bridge::executeVia` calls `executeInto`, not `execute`. A subclass that
1317 /// overrode `execute` alone would therefore be bypassed for every bridge

1319 /// silently, with every test it has still passing on the paths it does
1320 /// reach. `final` turns that into a compile error naming the fix: **derive
1321 /// from `LocalBackend` and override `executeInto`**, which is the primitive
1322 /// both entry points now share. (A backend deriving straight from
1323 /// `IBackend` is unaffected: it overrides `execute` and inherits the
1324 /// default `executeInto`, which forwards to it.)

1327 /// @param call Bundled action; `localOp` is the only field used here.
1328 /// @param cbExec Executor for delivering callbacks.

1331 detail::ActionCall call,
1332 ::morph::exec::IExecutor* cbExec) final {

1334 ::morph::async::Completion<std::shared_ptr<void>> comp{compState, cbExec};
1335 executeInto(mid, std::move(call), cbExec,
1336 std::make_shared<::morph::async::detail::CompletionSettleSink>(compState));
1337 return comp;

1340 /// @brief Schedules `call.localOp` on the model's strand and settles @p sink.
1341 ///
1342 /// @param mid Target model id.
1343 /// @param call Bundled action; `localOp` is the only field used here.
1344 /// @param cbExec Unused here: a sink carries its own delivery. Accepted so
1345 /// the signature matches `IBackend::executeInto`, whose remote
1346 /// implementations do need it.
1347 /// @param sink Settled on the strand thread with the result or the
1348 /// exception, exactly once.
1349 void executeInto(::morph::exec::detail::ModelId mid, detail::ActionCall call, ::morph::exec::IExecutor* cbExec,
1350 std::shared_ptr<::morph::async::detail::ISettleSink> sink) override {
1351 (void)cbExec;
1352
1353 std::shared_ptr<::morph::model::detail::IModelHolder> holder;
1354 std::shared_ptr<detail::HydrationState> hydration;
1355 {
1356 std::scoped_lock const lock{_regMtx};
1357 // One lookup for the holder and its hydration state together: they
1358 // are fields of one record now, not entries in two maps kept in
1359 // lockstep by convention.
1360 if (const auto* inst = _instances.find(mid)) {
1361 holder = inst->holder;
1362 hydration = inst->hydration;
1363 }
1364 }
1365 if (!holder) {
1366 sink->settleException(
1367 std::make_exception_ptr(std::runtime_error("model not found: id=" + std::to_string(mid.v))));
1368 return;
1369 }
1370 trackPending(sink);
1371 auto* const localOp = call.localOp;
1372 // The action handle travels with `localOp` into the strand task, not
1373 // just as far as this function: `ActionCall::localOp` borrows the
1374 // action rather than owning it (see that struct), and `call` is gone
1375 // long before the task runs.
1376 auto action = std::move(call.action);
1377 auto session = std::move(call.session);
1378 auto const modelTypeId = call.modelTypeId;
1379 auto const actionTypeId = call.actionTypeId;
1380 // Captured by shared_ptr, never by raw `this`: see the Global
1381 // Constraints note on `~StrandExecutor`'s member-destruction-order
1382 // subtlety. A shared_ptr copy has its own lifetime, independent of
1383 // LocalBackend's, so it stays valid even if the backend is torn down
1384 // while this task is still queued or running. `hydration` follows the
1385 // same rule and may be null (a private instance has no entry).
1386 auto inFlightCounter = _inFlight;
1387 auto const inFlightAfterInc = inFlightCounter->fetch_add(1, std::memory_order_relaxed) + 1;
1388 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeInFlight,
1389 static_cast<double>(inFlightAfterInc));
1390 _strand.post(
1391 mid, [localOp, holder = std::move(holder), sink = std::move(sink), session = std::move(session),
1392 modelTypeId, actionTypeId, inFlightCounter, hydration, action = std::move(action)]() mutable {
1393 auto const start = std::chrono::steady_clock::now();
1394 auto const spanId = ::morph::observe::detail::beginSpan(session.requestId, modelTypeId, actionTypeId);
1395 bool succeeded = false;
1396 // Resolve the sink only after every metric and `endSpan` below are
1397 // recorded — nothing synchronizes a `.then()`/`.onError()` callback
1398 // (delivered via `cbExec`, which may run inline/synchronously) with
1399 // anything after `setValue`/`setException` returns, so resolving first
1400 // would let the caller observe completion before these metrics are
1401 // emitted. This is a real race, not just a theoretical one.
1402 std::shared_ptr<void> value;
1403 std::exception_ptr error;
1404 try {
1405 ::morph::session::detail::ScopedContext const scoped{session};
1406 // Explicit, because `localOp` is a function pointer now and
1407 // a null one is undefined behaviour rather than the
1408 // `std::bad_function_call` an empty `std::function` used to
1409 // raise. Same outcome for the caller -- the completion
1410 // resolves through its error sink -- with a diagnostic that
1411 // names the field instead of the library.
1412 if (localOp == nullptr) {
1413 throw std::runtime_error{"ActionCall::localOp is null: nothing to execute"};
1414 }
1415 value = localOp(*holder, action.get());
1416 succeeded = true;
1417 } catch (...) {
1418 error = std::current_exception();
1419 }
1420 // Settle hydration the moment the first action's outcome is known —
1421 // before `endSpan`, before any metric, and before the `Completion`
1422 // resolves. Each of those hands control to host code that is free
1423 // to attach to this instance's key, and an attacher reaching the
1424 // directory while the outcome is known but unrecorded is handed an
1425 // instance whose first action has already failed — exactly what
1426 // docs/spec/core/shared_instances.md's Failure modes section says
1427 // must not happen. Only the *first* action settles it; `settle` is
1428 // a single compare-exchange and ignores every later call.
1429 if (hydration) {
1430 hydration->settle(succeeded);
1431 }
1432 ::morph::observe::detail::endSpan(spanId, succeeded);
1433 auto const elapsedMs =
1434 std::chrono::duration<double, std::milli>(std::chrono::steady_clock::now() - start).count();
1435 std::array<std::pair<std::string_view, std::string_view>, 2> const tags{
1436 {{"modelType", modelTypeId}, {"actionType", actionTypeId}}};
1437 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeLatencyMs, elapsedMs, tags);
1438 if (!succeeded) {
1439 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeErrors, 1.0, tags);
1440 }
1441 auto const inFlightAfterDec = inFlightCounter->fetch_sub(1, std::memory_order_relaxed) - 1;
1442 ::morph::observe::detail::emitMetric(::morph::observe::Metric::executeInFlight,
1443 static_cast<double>(inFlightAfterDec));
1444 // Resolve last: the sink is still settled exactly once, only its
1445 // position relative to the now-recorded instrumentation moved.
1446 if (succeeded) {
1447 sink->settleValue(std::move(value));
1448 } else {
1449 sink->settleException(error);
1450 }
1451 });
1452 }

1524 /// @brief Records @p state in the pending list, compacting it amortised-O(1).
1525 ///
1526 /// The list is append-only between compactions; dead entries are swept only
1527 /// when its size reaches `_compactAt`, which each sweep re-arms at twice the
1528 /// number of entries that survived it. Doubling the threshold off the live
1529 /// count is what makes the sweep amortised: a sweep costs O(size), and at
1530 /// least `_compactAt / 2` appends must happen before the next one, so the
1531 /// per-append cost is O(1) however deep the queue gets. The list is
1532 /// correspondingly bounded at twice the live count (plus the floor), which
1533 /// is the whole price of dropping the per-dispatch scan.
1534 ///
1535 /// Sweeping on *every* append instead would cost `n` atomic
1536 /// `weak_ptr::expired()` loads under `_pendingMtx` to admit one call with
1537 /// `n` in flight, so a burst of `n` costs O(n²) — measured at 362ms of pure
1538 /// admission time for 32k queued executes against one slow model, against
1539 /// 7.6ms without the sweep.
1540 ///
1541 /// Purely a cost change: `cancelPending` still sees every live state,
1542 /// because a dead entry is one whose `CompletionState` is already gone and
1543 /// which `cancelPending`'s `weak.lock()` has always skipped. Carrying dead
1544 /// entries for longer changes nothing it observes.
1545 /// @param sink Settle sink to track until it expires or is cancelled.
1546 void trackPending(const std::shared_ptr<::morph::async::detail::ISettleSink>& sink) {
1547 std::scoped_lock const lock{_pendingMtx};
1548 if (_pending.size() >= _compactAt) {
1549 std::erase_if(_pending, [](const auto& weak) { return weak.expired(); });
1550 _compactAt = std::max(kPendingCompactFloor, _pending.size() * 2);
1551 }
1552 _pending.emplace_back(sink);
1553 }
