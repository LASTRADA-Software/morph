36/// @brief Moves committed-but-unrelayed rows from a model's own outbox table to
37/// a durable `IActionLog`, then marks them relayed in the model's own
38/// store.
39///
40/// Closes the "two independent writes" gap between a model's own transactional
41/// store and the action log: a store-backed model writes its business tables
42/// *and* an outbox row (shaped like `LogEntry`, including a stable
43/// `idempotencyKey`) in one local transaction — see
44/// `IModelHolder::setOutboxManaged` — and `OutboxRelay` is the separate,
45/// asynchronous step that moves that row into the real durable sink.
46///
47/// `drainOutbox`/`markRelayed` are injected callables against the model's own
48/// store, exactly as `morph::offline::ReconnectCoordinator::Deps` and
49/// `morph::offline::SyncWorker::ReplayFunction` inject their side effects —
50/// `morph::journal` never touches the model's database. Mirroring
51/// `ReconnectCoordinator::Deps`, a null member is logged (via
52/// `morph::log::logError`) at the start of every `relay()` call but is not
53/// rejected — invoking a null member still throws (`std::bad_function_call`) or
54/// crashes as usual.
55///
56/// @par Crash safety
57/// `relay()` is idempotent and safe to call repeatedly: it appends every row
58/// `drainOutbox()` currently reports to `sink`, flushes `sink`, and only then
59/// calls `markRelayed` with the whole batch. A crash between the sink append and
60/// `markRelayed` committing simply means the next `relay()` call sees the same
61/// row again from `drainOutbox()` — appending it again is a safe no-op as long
62/// as `sink` dedups by `LogEntry::idempotencyKey` (`InMemoryActionLog` and
63/// `FileActionLog` do this out of the box — see their class docs; `SessionLog`
64/// deliberately does not, since its contract is full fidelity with nothing
65/// dropped). This is at-least-once-plus-dedup, not a two-phase commit: `sink`
66/// and the model's own store are never committed as a single distributed
67/// transaction.
68struct OutboxRelay {
69 /// @brief Pulls committed-but-unrelayed rows from the model's own store.
70 /// Must be non-destructive: the same rows are re-drained until
71 /// `markRelayed` records them, including across process restarts.
72 std::function<std::vector<LogEntry>()> drainOutbox;
73
74 /// @brief Marks @p rows relayed in the model's own store (by identity or
75 /// `LogEntry::idempotencyKey`) so a later `drainOutbox()` call no
76 /// longer returns them.
77 std::function<void(std::span<const LogEntry>)> markRelayed;
78
79 /// @brief Durable audit sink rows are forwarded to.
80 std::shared_ptr<IActionLog> sink;
81
82 /// @brief Moves every row `drainOutbox()` currently reports to `sink`, then
83 /// marks the whole batch relayed via `markRelayed`.
84 ///
85 /// A no-op (returns `{.relayed = 0}` without touching `sink` or calling
86 /// `markRelayed`) if `drainOutbox()` returns no rows.
87 ///
88 /// `markRelayed` runs only after `sink->flush()` returns normally. An
89 /// `IActionLog` that cannot make the batch durable throws (see
90 /// `IActionLog::flush`), which propagates out of here *before* the rows are
91 /// marked — so they stay in the outbox and a later `relay()` retries them.
92 /// This is what keeps the relay at-least-once instead of at-most-once: were
93 /// the failure swallowed, the rows would be recorded as relayed while
94 /// nothing reached the sink, and nothing would ever surface the loss.
95 ///
96 /// @return The number of rows relayed in this call.
97 /// @throws NullSinkError if `sink` is null and `drainOutbox()` reports at
98 /// least one row — thrown before `sink` is ever dereferenced, so
99 /// no row is lost or marked relayed. A null `sink` with nothing
100 /// to relay is still a no-op, exactly like an empty outbox with a
101 /// real `sink`: nothing would touch `sink` either way.
102 /// @throws std::exception propagated from `sink->append()` or `sink->flush()`;
103 /// the batch is left unmarked and therefore retryable.
104 OutboxRelayResult relay() {
105 logIfAnyDepNull();
106 auto rows = drainOutbox();
107 if (rows.empty()) {
108 return {};
109 }
110 if (!sink) {
111 throw NullSinkError("journal::OutboxRelay::relay: sink is null");
112 }
113 for (const auto& row : rows) {
114 sink->append(row);
115 }
116 sink->flush();
117 markRelayed(rows);
118 return OutboxRelayResult{.relayed = rows.size()};
119 }
120
121private:
122 // Logs any null member, mirroring ReconnectCoordinator::assertDepsNonNull —
123 // a diagnostic, not a rejection; construction/assignment of OutboxRelay
124 // itself is never intercepted (it is a plain aggregate), so the check runs
125 // at the start of every relay() call instead.
126 void logIfAnyDepNull() const {
127 if (!drainOutbox) {
128 ::morph::log::logError("[journal::OutboxRelay] null drainOutbox");
129 }
130 if (!markRelayed) {
131 ::morph::log::logError("[journal::OutboxRelay] null markRelayed");
132 }
133 if (!sink) {
134 ::morph::log::logError("[journal::OutboxRelay] null sink");
135 }
136 // This branch itself is unit-tested (test_outbox.cpp asserts the
137 // warning fires). relay() itself throws NullSinkError right after
138 // this call if sink is null and there is at least one row to relay
139 // (see LASTRADA-Software/morph#95) -- a null drainOutbox/markRelayed
140 // still throws std::bad_function_call as usual, invoking a null
141 // std::function.
142 }
143};
