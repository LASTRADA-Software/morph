# `IoLoopDriver::Caller` and `morph::tui` — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an `exec::IoLoop` be turned by the thread that built it, then ship `morph::tui`: a compiled, optional
terminal frontend that renders a `morph::ui` view tree through core-cpp's `core::tui`, passes the backend
conformance suite, and runs a whole application (UI, sockets, timers, bridge callbacks) on that one caller-driven
loop.

**Spec:** `docs/superpowers/specs/2026-10-04-declarative-ui-tui-design.md` (spec 1) §2 (`morph::tui` packaging),
§5b, §6, §7 ("tui", "backend conformance"), §9; `docs/superpowers/specs/2026-10-04-core-cpp-mouse-design.md`
(spec 0). Issue: #901. Program: #885.

**Starting point.** Spec 0 is delivered: core-cpp `v0.7.0` (2026-10-05) carries `MouseTracking`,
`Terminal::setMouseTracking`, pointer capture with `Screen::releasePointer`, and a public `Screen::componentAt`.
The 2026-10-04 part-3 plan (`29ca9b1f:docs/superpowers/plans/2026-10-04-declarative-ui-tui-3-tui.md`) was
executed on `origin/feature/declarative-ui` as `wip(...)` commits: the pin (`7bb681f`), `IoLoopDriver::Caller`
(`d72e512`), and `morph::tui` (`include/morph/tui/`, `src/tui/`, `tests/tui/`, about 14,000 lines). That code
predates the backend contract on `master`, which has since gained ten widget kinds and the common setters. It is
taken as the base; where it and the specs on `master` disagree, the specs win, unless this plan amends one.

**Delivery.** Two pull requests to `master`, in order. The second closes #901.

- **A — `feature/901-tui`:** this plan, the core-cpp 0.7 pin and `IoLoopDriver::Caller`. Nothing in it needs a
  terminal, so it lands on its own and every later `IoLoop` user can rely on it.
- **B — the terminal frontend:** `morph::tui`, the terminal `IViewBackend`, its conformance probe, `LoopExecutor`,
  the frontend and the packaging.

## Global Constraints

- SPDX line first, `#pragma once`, naming per `.clang-tidy`, present-tense comments with no history or issue
  numbers (AGENTS.md), full Doxygen on every public symbol (`WARN_AS_ERROR`), the strict warning set, clang-tidy
  and clang-format 22 clean, and every test naming the mutation that makes it fail.
- `morph::tui`'s public headers (`include/morph/tui/`) may name `core::tui` types but no private `src/tui/` type.
- `core::tui` holds raw pointers to components (children, focus, overlays, the pointer capture); no widget may
  leave one dangling when it is destroyed.

## PR A — the pin and `IoLoopDriver::Caller`

- [ ] **A1. Pin core-cpp 0.7.** `MORPH_CORE_CPP_VERSION 0.7`, `GIT_TAG v0.7.0`; the config template follows
  through the variable. Review core-cpp's 0.5.1, 0.6.0 and 0.7.0 changelogs for what morph depends on:
  - 0.6.0 reports exhaustion as `NetErrorCode::ResourceExhausted`, not `SystemError`. `SocketServer`'s
    `acceptListenerIsDead` already treats every code but `BadHandle`, `Unsupported` and a dead-listener
    `SystemError` as retryable; its comment and test name the new code.
  - 0.6.0's `serve()` and `IListener::doClose()` changes: morph calls neither.
  - 0.7.0 is additive for morph.
- [ ] **A2. `IoLoopDriver::Caller`.** Port `d72e512`: `IoLoop(IoLoopDriver)`, `driver()`, `runningHere()` true on
  a `Caller` loop's thread between turns, `runAndWait` inline there inside the loop's `ExecutorScope`,
  `runAndWait` rethrowing a task's exception and ending its wait on a task dropped unrun, debug assertions for a
  `Caller` loop turned or destroyed wrongly. The `IoLoop` tests run under both drivers; `TimeoutScheduler` and a
  `SocketBackend` round trip run on a `Caller` loop. `docs/spec/core/executor.md` describes the mode.
- [ ] **A3. Checks.** Full `morph_tests` and `ctest` (net on), ASan+UBSan and TSan over `[io_loop]`,
  `[timeout_scheduler]` and `[net]`, each named mutation applied and run, clang-tidy, clang-format, Doxygen.

## PR B — `morph::tui`

- [ ] **B1. Packaging.** `MORPH_BUILD_TUI` (default OFF): `morph_tui` STATIC, alias `morph::tui`, linking
  `core::tui` and `morph` PUBLIC; core-cpp with `CORE_CPP_WITH_TUI ON` and `CORE_CPP_WITH_IMAGES OFF`;
  libunicode 0.9.3 found first, else fetched. Optional-components list, header-set check, install and export,
  `morphConfig.cmake.in`, sanitizers, strict warnings, the presets and a CI leg. Native only.
- [ ] **B2. Port the base.** Bring `src/tui/`, `include/morph/tui/` and `tests/tui/` from the WIP onto `master`'s
  `ui::IViewBackend`, and make it compile and pass its own tests.
- [ ] **B3. The common setters** every widget now takes: `setAccessibleName`, `setAccessibleRole`, `setTestId`,
  `setTooltip` (core::tui's hover tooltip), `setSurface` (a theme token set), `setKeys` (innermost declarer wins),
  `focus`; on fields `setReadOnly`, `setRequired`, `setErrors`, `setStale`; `TextInputWidget::setOnCommit`;
  `MenuWidget::setItems(MenuEntry tree)`.
- [ ] **B4. The ten further widgets:** banner, badge, progress, steps, key-value, empty state, drawer (an overlay
  with a dialog's rules, from its side), splitter (keyboard and pointer-drag handles), collapsible (header stays
  live while closed) and drop zone (a terminal has no OS file drop: the zone renders and refuses nothing it is
  never given; the conformance probe delivers paths through its own entry point).
- [ ] **B5. Conformance.** A `ConformanceProbe` over the terminal backend that drives it through real
  `core::tui` input events (keys, SGR mouse) and reads what is rendered; all 34 cases of
  `ui::testing::conformanceCases()` pass, and the suite fails on a broken terminal backend (a fault switch as
  `RecordingProbe` has).
- [ ] **B6. `LoopExecutor` and the frontend.** `tui::LoopExecutor` posts to the loop and drops posts after its
  destruction. `tui::Frontend` and `tui::frontendOption(ui::ShellFactory)`, named `"tui"`, usable when stdin is
  a terminal: `IoLoop{Caller}`, `LoopExecutor`, the runtime, `Screen` and `TuiRuntime` with interrupt handling,
  so Ctrl+C and SIGINT quit with 130 after restoring the terminal; `run` goes through `ui::runApp`.
- [ ] **B7. Docs and checks.** `docs/spec/tui/` (backend, frontend), ARCHITECTURE, README, CONTRIBUTING's
  packaging rule, CHANGELOG; the frontend end to end through `ScriptedInputSource`; the same checks as A3 over
  the tui suite.

## Spec amendments

- **T1 (spec 1 §6).** `tui::frontendOption()` takes the `ui::ShellFactory` that mounts the application's shell.
  The document interpreter and the hosting layer that would supply a default shell have not landed, and
  `ui::runApp` needs one; when hosting lands it can give the parameter a default.
