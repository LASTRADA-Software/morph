# Messages: implementation plan (part 8, slice b3, #893)

**Goal.** A client resolves every `t` from the message catalogues its verified bundle carries, switches locale
with `{"setLocale": …}`, shows the `fallback` where a catalogue or key is missing, and can find a title in every
locale the manifest lists. Part of #893.

**Specs.** Spec 6 (`docs/superpowers/specs/2026-10-08-app-hosting-design.md`) §19 "Messages" and the §12 "Settings
and messages" tests; spec 5 (`2026-10-07-ui-document-design.md`) §4 (`t`, the MessageFormat 2 subset) and §12
(delivery). In-tree: `include/morph/render/i18n.hpp` (`TranslationProvider`), `include/morph/ui/expression.hpp`
(`FormatContext`, `t`), `include/morph/ui/message.hpp`, `include/morph/ui/service.hpp` (`UiRegistry::addFile`),
`include/morph/ui/service_client.hpp` (`LoadedBundle`), `include/morph/ui/interpreter.hpp` (`Session::setLocale`,
the `setLocale` command).

## What planning found

1. **Locale switching and its persistence hook exist.** `{"setLocale": "de"}` calls `Session::setLocale`, which
   replaces the reactive formatting facts with the new locale and keeps the provider, so every `t` re-evaluates;
   then it calls `InterpreterHost::setLocale`, the hook an application stores the choice through. `t` asks the
   provider for `(key, locale)` and formats the `fallback` on a miss. What is missing is a provider: nothing reads
   a bundle's `messages` files, and nothing defines their id or shape.
2. **A catalogue is checked nowhere.** `UiRegistry::addFile` serves a `messages` file as opaque bytes, and `t` parses
   a pattern at every evaluation, reporting one outside the subset then. Spec 5 §4 says a pattern outside the subset
   is refused when the catalogue loads, and the fallback is shown.
3. **The provider has no per-locale lookup to search with.** `TranslationProvider` maps one `(key, locale)`; a
   search over titles in every locale needs the list of locales, which only the manifest knows.

## Design

### The catalogue (`ui/catalogue.hpp`)

- **Id and locale.** A `messages` file's id is `i18n/<locale>.json`, the locale a BCP 47 tag of letters, digits and
  `-`. `catalogueLocale(id)` reads it back.
- **Shape.** A JSON object of key to pattern text, flat. `parseCatalogue(text)` refuses text that is not JSON or
  nests deeper than `kMaxJsonDepth`, a must-understand (`!`) key, a value that is not a string, an empty key or one
  longer than 256 bytes, and more than 16384 keys. Each pattern is parsed with `parseMessage`; one outside the
  subset is dropped and reported, so its key shows the fallback (spec 5 §4), and the rest of the catalogue loads.
- **`MessageCatalogues`.** `add(locale, catalogue)`, `locales()`, `provider()`: a `TranslationProvider` over shared,
  immutable catalogues. A lookup tries the exact locale, then its language (`de-AT`, then `de`); a miss is
  `std::nullopt`, and `t` shows the fallback.
- **From a bundle.** `loadCatalogues(manifest, files)` reads every `messages` file the manifest lists from the
  verified files (`LoadedBundle::manifest`, `LoadedBundle::files`). A catalogue whose id is not `i18n/<locale>.json`,
  that is missing from the files, or that `parseCatalogue` refuses, is left out and reported; its locale shows the
  fallbacks. Loading never fails at first use.
- **Search.** `textInEveryLocale(catalogues, key, fallback)` formats a key's message in every locale the catalogues
  hold, the fallback where one has no entry; `matchesInAnyLocale(…, query)` is true when any of those texts contains
  the query, ASCII letters compared without case. The navigator that uses it is the workspace shell's (slice d).

### The server (`UiRegistry::addFile`)

A `messages` file is refused at registration when its id is not `i18n/<locale>.json` or `parseCatalogue` refuses
it or drops a pattern: the server is where an author learns a catalogue is wrong.

### The session (`interpreter.hpp`, the formatting region)

`Session::setTranslations(provider)` replaces the provider and keeps the other formatting facts, as `setLocale`
keeps the provider: an application installs the bundle's catalogues once it opens, and every `t` re-resolves.

## Not in this slice

- **Storing the chosen locale.** The interpreter already calls `InterpreterHost::setLocale`; the application's host
  stores it, through the preferences glue once that lands. Nothing here depends on it.
- **The navigator's search UI** is the workspace shell's (slice d).
