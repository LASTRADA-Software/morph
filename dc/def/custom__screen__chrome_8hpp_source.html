68/// @brief The window chrome of custom screens over one workspace, built from backend nodes so every frontend shows it.
69///
70/// For each document screen's tab, `chromeFor` gives a draft bar, shown while the tab holds a draft (Save for a draft
71/// of the person's own custom screen, Save as…, Source and Discard, and the last refusal of a save), and a row with
72/// the **Source** button, shown while it does not. **Source** opens the source view, an overlay with the document's
73/// JSON pretty-printed: read only while custom screens are not offered. **Preview** loads the text in the client, asks
74/// the server's `check`, and mounts what passes as the tab's draft (`DocumentScreenHost::mountDraft`); a refusal is
75/// shown with the line its pointer names, and choosing it moves the cursor there; the editor is read only while the
76/// check runs, so the draft is exactly the text previewed. **Save as…** asks a name, saves, and opens the saved screen
77/// in the tab's place. A reply to a save acts only on the draft that was saved: a tab that holds a newer draft, or
78/// none, keeps it and the person is told. Everything runs on the runtime's owner. Neither copyable nor movable.
79class MORPH_API CustomScreenChrome {
80public:

269 // Wraps @p fn so it does nothing once the chrome is gone: replies arrive through the sync, which may outlive it.
270 template <typename F>
271 [[nodiscard]] auto guarded(F fn) const {
272 // Tab ids are issued per workspace, so a reply made under a workspace that has been replaced does nothing too.
273 return
274 [this, epoch = _epoch, alive = std::weak_ptr<bool>{_alive}, fn = std::move(fn)](auto&&... args) mutable {
275 if (auto const live = alive.lock(); live != nullptr && *live && _epoch == epoch) {
276 fn(std::forward<decltype(args)>(args)...);
277 }
278 };
279 }
