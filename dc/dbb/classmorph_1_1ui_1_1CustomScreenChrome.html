Detailed Description

The window chrome of custom screens over one workspace, built from backend nodes so every frontend shows it.

For each document screen's tab, chromeFor gives a draft bar, shown while the tab holds a draft (Save for a draft of the person's own custom screen, Save as…, Source and Discard, and the last refusal of a save), and a row with the Source button, shown while it does not. Source opens the source view, an overlay with the document's JSON pretty-printed: read only while custom screens are not offered. Preview loads the text in the client, asks the server's check, and mounts what passes as the tab's draft (DocumentScreenHost::mountDraft); a refusal is shown with the line its pointer names, and choosing it moves the cursor there; the editor is read only while the check runs, so the draft is exactly the text previewed. Save as… asks a name, saves, and opens the saved screen in the tab's place. A reply to a save acts only on the draft that was saved: a tab that holds a newer draft, or none, keeps it and the person is told. Remove, on a screen of the person's own, asks once and removes it; a tab that showed it opens its base.

It is a view over a CustomScreenController, which holds every tab's draft and runs every command: the chrome draws the controller's state, and words its outcomes and refusals. Its fixed words are English; they are the view's, so localising them is the view's too. An application with controls of its own draws them over a controller of its own instead. Everything runs on the runtime's owner. Neither copyable nor movable.
