Detailed Description

The framework's ScreenHost over UI documents: it mounts them through an Interpreter, closes them by the protocol of spec 6 §3, and hands a document's navigate to onNavigate, which the deriving host implements.

It is the interpreter's InterpreterHost for navigate; every other command goes to the application's host, if one was given. Everything runs on the runtime's owner.

◆ prefetch()

void morph::ui::DocumentScreenHost::prefetch ( std::string_view screenId,
ParamMap const & params )
inline

Starts the requests of a screen's prefetch queries before it mounts (spec 5 §5), so the screen mounts on a warm cache: what a shell does when the pointer rests on an entry for a screen that is not open.

Each named query's body is evaluated over params alone and its entry warmed through the session's cache, under the token the mounted screen's alias will have. A keyed alias's token follows from its key, and a stateless model's is shared. A private alias gets a fresh token when the screen mounts, so nothing could read what a prefetch warmed: its queries are skipped, as are evaluations, a key or body that reads more than the params, and an entry that is already fresh or in flight.

Parameters
screenIdThe screen id; an unknown one does nothing.
paramsThe params it would mount with.
