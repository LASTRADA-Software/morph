Detailed Description

Sequences reconnect → activate → bind → replay when connectivity returns.

All side effects are injected via Deps. The coordinator contains only the retry loop, the ordering guarantees, and the abort checks. It performs no I/O and owns no thread; onOnline() / onOffline() run synchronously on the calling thread.

Ordering guarantee (the reason this class exists)
Within a successful onOnline(), the steps run in this strict order:
  1. tryReconnect() returns true (backend usable)
  2. activatePrimary() (make primary the active backend)
  3. bindContext() (rebind per-connection / per-session state)
  4. replay() (drain + replay the offline queue) Step 4 MUST NOT run before step 3 completes, and step 3 MUST NOT run before step 2. Implementations and tests should treat this as an invariant.
Thread safety
onOnline() and onOffline() are mutually serialised by an internal mutex, mirroring SyncWorker::run(). Calling them concurrently is safe; the second caller blocks. They are intended to be posted onto a worker executor by the host (see the wiring note in the design doc), not called on the probe thread.
