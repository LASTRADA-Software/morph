5/// @file util/quantity.hpp
6/// @brief Unit-tagged, optionally-empty exact values with a derivation trail.
7///
8/// `morph::units::Quantity<U>` wraps an *optional* `morph::math::Rational` and
9/// knows three things about itself: its **unit** (a compile-time template tag),
10/// its **exactness** (an exact `Rational`, with a declared and a runtime notion
11/// of precision, and `std::nullopt` as a real "not entered" state), and **how
12/// it was computed** — its derivation, exposed through `equation()`.
13///
14/// See `docs/spec/util/quantity_type.md` for the full design. The essentials:
15///
16/// - **Units are types.** `Quantity<Unit::kg>` and `Quantity<Unit::m3>` cannot
17/// be mixed; `operator*` / `operator/` deduce the result unit from the
18/// application-defined `consteval` algebra on the unit enum. Within-dimension
19/// scaling is declared as `UnitTraits<E>::relations` (a flat list of exact
20/// `UnitRelation` ratios), which drive `convert`, conversion *chaining*, and
21/// the schema's display-unit selector.
22/// - **Precision is declared in the type; actual precision is runtime data.**
23/// `Quantity<Unit::m3, 4>` overrides the unit default; the value's actual
24/// precision is the runtime `DecimalPlaces` tag inside the `Rational` and
25/// max-propagates through arithmetic. Magnitude is bounded by `int64`;
26/// overflow is a documented limitation, only division-by-zero yields empty.
27/// - **Empty propagates** (SQL-NULL semantics). `==` is total; relational
28/// ordering has a precondition that both operands are engaged.
29/// - **Provenance** is a build-wide toggle, `MORPH_QUANTITY_PROVENANCE`
30/// (default `1`). With it `0`, no derivation nodes are allocated and the
31/// provenance API returns empty results; `Quantity<U>` is the same type
32/// either way.
33/// - **Wire.** On the morph JSON wire a quantity is its nullable `Rational`
34/// payload; the unit lives in generated schemas (`ExtUnits`) and C++ types.
35
36/// @brief Build-wide provenance toggle. Default on; define to `0` to compile
37/// the derivation DAG out (no `ASTNode` allocations).

68/// @brief Renders a `Rational` as a shortest exact decimal at its own
69/// `DecimalPlaces` (trailing zeros and a bare point trimmed) — the form
70/// `Quantity` formatting and `equation()` use everywhere.
71///
72/// The decimal is produced by **exact integer long division** of the canonical
73/// `numerator/denominator` to `decimalPlaces` digits — the value never passes
74/// through `double`, so both large exact integers (beyond the 2^53 double
75/// mantissa) and non-terminating quotients render without floating-point drift.
76/// Non-terminating quotients are rounded **half away from zero** at
77/// `decimalPlaces` (matching `Rational::toDouble`'s `std::round`), and the
78/// rounding carry is allowed to propagate into the integer part. Trailing zeros
79/// and a bare decimal point are then trimmed to the shortest form.
80///
81/// The division is a **digit-at-a-time** long division: the integer part comes
82/// from `|numerator| / denominator` in 64-bit, and each fractional digit from
83/// `remainder * 10 / denominator`, carrying the exact integer remainder forward.
84/// `remainder * 10` can exceed 64 bits when the denominator is near `INT64_MAX`,
85/// so each fractional step is computed with `mulTenDivMod` — a portable helper
86/// that never forms `remainder * 10` at all: since the quotient digit is in
87/// 0..9, it accumulates `remainder` ten times, reducing modulo the denominator
88/// as it goes, so every step stays within 64 bits (no 128-bit type, no
89/// `__udivti3` runtime dependency) and behaves identically under MSVC and clang-cl.
90/// @param value The rational to render.
91/// @return The decimal string (`"2"`, `"0.3"`, `"1.36"`, `"-4.2"`).
92[[nodiscard]] inline std::string formatRationalDecimal(const morph::math::Rational& value) {
93 // Work on magnitudes; the sign is reattached at the end. The canonical
94 // invariant guarantees denominator > 0, so only the numerator carries sign.
95 bool const negative = value.numerator < 0;
96 // Negating INT64_MIN would overflow int64; widen before taking the absolute
97 // value so the magnitude is always representable.
98 auto const num =
99 negative ? static_cast<std::uint64_t>(-static_cast<std::int64_t>(static_cast<std::uint64_t>(value.numerator)))
100 : static_cast<std::uint64_t>(value.numerator);
101 auto const den = static_cast<std::uint64_t>(value.denominator);
102 auto const places = static_cast<std::uint32_t>(value.decimalPlaces.value);
103
104 // Integer part and the exact running remainder (both < den, so 64-bit safe).
105 std::uint64_t const integerPart = num / den;
106 std::uint64_t remainder = num % den;
107
108 // floor(rem*10 / den) and (rem*10 % den) with `rem < den`. `rem*10` can need
109 // up to 67 bits, but we never form it: the digit q = floor(rem*10/den) is in
110 // 0..9 (because rem < den), so we compute it by adding `rem` ten times and
111 // reducing modulo `den` as we go. The running accumulator stays below `den`
112 // before each add and below `2*den <= 2^64` after, so every step is exact in
113 // 64-bit with no overflow and no 128-bit type — identical under MSVC and
114 // clang-cl (whose MSVC runtime lacks the `__udivti3` 128-bit divide helper).
115 auto const mulTenDivMod = [den](std::uint64_t rem, std::uint64_t& quotientDigit) -> std::uint64_t {
116 std::uint64_t acc = 0;
117 std::uint64_t q = 0;
118 for (int k = 0; k < 10; ++k) {
119 acc += rem; // acc < den before the add (rem < den), so acc < 2*den <= 2^64 after
120 while (acc >= den) {
121 acc -= den;
122 ++q;
123 }
124 }
125 quotientDigit = q;
126 return acc;
127 };
128
129 std::string frac;
130 frac.reserve(places);
131 for (std::uint32_t i = 0; i < places; ++i) {
132 std::uint64_t digit = 0;
133 remainder = mulTenDivMod(remainder, digit);
134 frac.push_back(static_cast<char>('0' + static_cast<int>(digit)));
135 }
136
137 // Round half away from zero at `places`: if twice the leftover remainder is
138 // >= den, the truncated result rounds up. Propagate the carry through the
139 // fractional digits and, if it reaches the top, into the integer part.
140 std::uint64_t roundedInteger = integerPart;
141 if (remainder * 2 >= den) {
142 bool carry = true;
143 for (std::size_t i = frac.size(); i-- > 0 && carry;) {
144 if (frac[i] == '9') {
145 frac[i] = '0';
146 } else {
147 ++frac[i];
148 carry = false;
149 }
150 }
151 if (carry) {
152 ++roundedInteger;
153 }
154 }
155
156 std::string text = std::to_string(roundedInteger);
157 if (places > 0) {
158 text.push_back('.');
159 text += frac;
160 }
161
162 // Trim trailing zeros and a now-bare decimal point (shortest form).
163 if (auto const dot = text.find('.'); dot != std::string::npos) {
164 std::size_t last = text.find_last_not_of('0');
165 if (last == dot) {
166 --last;
167 }
168 text.erase(last + 1);
169 }
170
171 // A rounded-to-zero magnitude must not print as "-0".
172 if (negative && text != "0") {
173 text.insert(text.begin(), '-');
174 }
175 return text;
176}

204/// @brief One exact within-dimension conversion ratio between two peer units.
205///
206/// `1` unit of `from` equals `fromTo` units of `to`. `fromTo` must be strictly
207/// positive; `from` and `to` must differ. Declared in `UnitTraits<E>::relations`
208/// and used in both directions (the reverse multiplies by the reciprocal).
209/// @tparam E The application's unit enum type.

212 /// @brief Source unit of the ratio.
213 E from{};
214
215 /// @brief Target unit of the ratio.
216 E to{};
217
218 /// @brief Exact ratio: `1 from == fromTo · to`. Strictly positive.
219 morph::math::Rational fromTo{};
220};

287/// @brief Result of a compile-time conversion-ratio search.
288/// @tparam E The unit enum type.
289template <typename E>
290struct RatioResult {
291 /// @brief Whether a connecting path exists in the relation graph.
292 bool found{false};
293
294 /// @brief Composed ratio `k` such that `value_to = value_from · k`.
295 morph::math::Rational ratio{};
296};
297
298/// @brief Compile-time guard that a `UnitRelation::fromTo` ratio is strictly
299/// positive (both numerator and denominator > 0).
300///
301/// A `UnitRelation` declares `1 from == fromTo · to`; a zero or negative ratio
302/// is physically meaningless and, worse, silently corrupts conversions: a zero
303/// numerator makes the reverse edge's denominator `0`, which `Rational` clamps
304/// to `1` (see rational.hpp), and a negative ratio inverts the direction of the
305/// conversion — either way `den:0`/garbage leaks into `x-unitAlternatives`.
306///
307/// This is invoked from the `consteval` `conversionRatio` search for every
308/// relation edge it touches, so a bad ratio is a **compile error** (the
309/// `throw` in a constant-evaluation context is ill-formed) rather than silent
310/// runtime corruption. `fromTo` is a canonicalised `Rational` whose denominator
311/// is already `> 0` by the type invariant, so the failing case in practice is a
312/// numerator `<= 0` (a `0`/negative ratio the application declared).
313/// @param ratio The declared `fromTo` ratio to validate.
314/// @return `true` when @p ratio is strictly positive; otherwise the call is
315/// ill-formed in a constant-evaluation context (a compile error).
316[[nodiscard]] consteval bool requirePositiveRatio(const morph::math::Rational& ratio) {
317 // Rational canonicalises so denominator > 0 always; the numerator carries
318 // the sign and can be zero/negative if the application declared a bad ratio.
319 if (ratio.numerator <= 0 || ratio.denominator <= 0) {
320 throw "UnitRelation::fromTo must be strictly positive (numerator > 0 and denominator > 0)";
321 }
322 return true;
323}
324
325/// @brief Reciprocal of a strictly-positive rational (swaps numerator and
326/// denominator), keeping its precision tag.
327///
328/// Guards, at compile time, that @p value is strictly positive: a zero or
329/// negative input would otherwise produce a degenerate reciprocal (a `0`
330/// denominator that `Rational` clamps to `1`, or a sign-flipped ratio). Because
331/// this is `consteval`, a non-positive @p value is a **compile error** at the
332/// relation-consuming call site rather than silent corruption.
333/// @param value A strictly-positive rational.
334/// @return `1 / value`.
335[[nodiscard]] consteval morph::math::Rational reciprocal(const morph::math::Rational& value) {
336 static_cast<void>(requirePositiveRatio(value)); // compile error on a bad ratio
337 return morph::math::Rational{morph::math::Numerator{value.denominator}, morph::math::Denominator{value.numerator},
338 value.decimalPlaces};
339}

341/// @brief Breadth-first search of the relation graph for a `from → to` ratio.
342///
343/// Treats `UnitTraits<E>::relations` as an undirected graph (each entry usable
344/// forward with `fromTo` and backward with its reciprocal), returning the
345/// fewest-hops composed ratio. Ties break by declaration order.
346/// @tparam E The unit enum type (must satisfy `HasUnitRelations`).
347/// @param from Source unit.
348/// @param to Target unit.
349/// @return The composed ratio and whether a path was found.
350template <typename E>
351[[nodiscard]] consteval RatioResult<E> conversionRatio(E from, E to) {
352 using morph::math::Rational;
353 if (from == to) {
354 return RatioResult<E>{true, Rational::one(morph::math::DecimalPlaces{1})};
355 }
356 constexpr std::size_t relationCount = UnitTraits<E>::relations.size();
357 constexpr std::size_t capacity = 2 * relationCount + 1;
358 std::array<E, capacity> nodes{};
359 std::array<Rational, capacity> ratios{};
360 std::size_t count = 0;
361 std::size_t head = 0;
362 nodes[count] = from;
363 ratios[count] = Rational::one(morph::math::DecimalPlaces{1});
364 ++count;
365 while (head < count) {
366 E const current = nodes[head];
367 Rational const currentRatio = ratios[head];
368 ++head;
369 for (auto const& relation : UnitTraits<E>::relations) {
370 E neighbour{};
371 Rational edge{};
372 bool touches = false;
373 if (relation.from == current) {
374 neighbour = relation.to;
375 static_cast<void>(requirePositiveRatio(relation.fromTo)); // compile error on a bad ratio
376 edge = relation.fromTo;
377 touches = true;
378 } else if (relation.to == current) {
379 neighbour = relation.from;
380 edge = reciprocal(relation.fromTo); // reciprocal also guards positivity
381 touches = true;
382 }
383 if (!touches) {
384 continue;
385 }
386 bool seen = false;
387 for (std::size_t i = 0; i < count; ++i) {
388 if (nodes[i] == neighbour) {
389 seen = true;
390 break;
391 }
392 }
393 if (seen) {
394 continue;
395 }
396 Rational const neighbourRatio = currentRatio * edge;
397 if (neighbour == to) {
398 return RatioResult<E>{true, neighbourRatio};
399 }
400 nodes[count] = neighbour;
401 ratios[count] = neighbourRatio;
402 ++count;
403 }
404 }
405 return RatioResult<E>{false, Rational{}};
406}

408/// @brief Number of `UnitAlternative`s directly convertible to unit `U`.
409/// @tparam U The canonical unit enumerator.
410/// @return Count of relation entries touching `U`.
411template <auto U>
412[[nodiscard]] consteval std::size_t alternativeCount() {
413 using E = decltype(U);
414 std::size_t total = 0;
415 if constexpr (HasUnitRelations<E>) {
416 for (auto const& relation : UnitTraits<E>::relations) {
417 if (relation.from == U || relation.to == U) {
418 ++total;
419 }
420 }
421 }
422 return total;
423}

425/// @brief Builds the derived `UnitAlternative` view for unit `U` from
426/// `relations` (direct neighbours, both directions).
427/// @tparam U The canonical unit enumerator.
428/// @return The alternatives array (empty when the unit system declares none).
429template <auto U>
430[[nodiscard]] consteval std::array<UnitAlternative<decltype(U)>, alternativeCount<U>()> makeAlternatives() {
431 using E = decltype(U);
432 std::array<UnitAlternative<E>, alternativeCount<U>()> result{};
433 if constexpr (HasUnitRelations<E>) {
434 std::size_t index = 0;
435 for (auto const& relation : UnitTraits<E>::relations) {
436 if (relation.to == U) {
437 result[index] =
438 UnitAlternative<E>{relation.from, relation.fromTo.numerator, relation.fromTo.denominator};
439 ++index;
440 } else if (relation.from == U) {
441 result[index] =
442 UnitAlternative<E>{relation.to, relation.fromTo.denominator, relation.fromTo.numerator};
443 ++index;
444 }
445 }
446 }
447 return result;
448}

670 /// within this field's unit-declared bounds (`UnitTraits<E>::bounds`),
671 /// when the unit declares any. An empty payload, or a unit with no
672 /// declared `bounds()` (`HasUnitBounds` not satisfied), is always
673 /// within bounds — this is an *opt-in* check, not a new default
674 /// restriction, so a unit system that declares no bounds behaves
675 /// exactly as it did before this feature existed.
676 ///
677 /// Comparison is on the exact `Rational` value only (never a lossy
678 /// `double`), consistent with every other exact comparison in this
679 /// header.
680 /// @return `true` when empty, when the unit declares no bounds, or when
681 /// the engaged value satisfies `min <= value <= max`.

712 /// @brief Retags the value's *runtime* precision (the exact value itself is
713 /// unchanged — precision only affects rounding and formatting).
714 ///
715 /// This is the **display-hint** half of the pair: after it, the value shown
716 /// at @p newPrecision and the value stored may differ. Use
717 /// `roundedToDecimalPlaces` when the stored value must be the one displayed.
718 /// @param newPrecision Runtime precision; silently clamped to the valid range.
719 /// @return The retagged quantity, or empty if this is empty.
720 [[nodiscard]] Quantity withDecimalPlaces(math::DecimalPlaces newPrecision) const {
721 if (!payload) {
722 return *this;
723 }
724 auto adjusted = *payload;
725 adjusted.decimalPlaces = math::DecimalPlaces{math::detail::clampWireDecimalPlaces(newPrecision.value)};
726 Quantity out;

728#if MORPH_QUANTITY_PROVENANCE

730#endif

735 /// value** as well as the tag — unlike `withDecimalPlaces`, which
736 /// retags only and leaves display and storage free to disagree.

738 /// Delegates to `math::roundToDecimalPlaces`, and so shares its saturation
739 /// behaviour: a value whose scaled form leaves `int64` range clamps and logs
740 /// instead of overflowing. A value already representable at @p newPrecision
741 /// is unchanged apart from its tag.
742 /// @param newPrecision Runtime precision; silently clamped to the valid range.
743 /// @param mode Tie-breaking rule; defaults to half away from zero, matching
744 /// the decimal display path.
745 /// @return The rounded quantity, or empty if this is empty.
746 [[nodiscard]] Quantity roundedToDecimalPlaces(
747 math::DecimalPlaces newPrecision, math::RoundingMode mode = math::RoundingMode::HalfAwayFromZero) const {
748 if (!payload) {
749 return *this;

751 Quantity out;
752 out.payload = math::roundToDecimalPlaces(*payload, newPrecision, mode);
753#if MORPH_QUANTITY_PROVENANCE
754 out._ctx = _ctx;
755#endif
756 return out;
757 }

760 /// the generated schema advertises as `x-decimalPlaces`.

763 /// becomes the value that renders at the declared precision, so a handler
764 /// never persists digits the form does not show. Rounds half away from zero,
765 /// the rule the decimal formatter uses.
766 /// @return The rounded quantity, or empty if this is empty.
767 [[nodiscard]] Quantity atDeclaredPrecision() const { return roundedToDecimalPlaces(declaredPrecision()); }

769 /// @brief Seals this value with a name: `equation()` shows the name instead
770 /// of expanding its derivation. Builds a fresh node (never mutates a
771 /// shared one); a no-op returning empty on empty or with tracing off.
772 /// @param label The symbol name.
773 /// @return A same-unit quantity carrying the name.
774 [[nodiscard]] Quantity named([[maybe_unused]] std::string label) const {
775 Quantity out;

777#if MORPH_QUANTITY_PROVENANCE

781 node->current.lhs = payload;

786#endif
787 return out;
788 }

793 /// (empty, named root, bare leaf, or tracing off).
794 [[nodiscard]] std::vector<std::string> equation() const
795#if MORPH_QUANTITY_PROVENANCE
796 ;
797#else

799 return {detail::formatOptionalDecimal(payload)};

801#endif

803 /// @brief Implicit within-dimension conversion to another unit; delegates to
804 /// `convert`, propagates empty, and records a provenance step.
805 /// @tparam To Target unit enumerator (same enum, different value, convertible).
806 /// @return The converted quantity in unit `To`.
807 template <auto To>
808 requires Convertible<U, To>

817 }

820 std::string{Quantity<To>::unitMeta().id},
821 payload, std::nullopt, out.payload, MORPH_Q_NODE(*this), nullptr);
822 }
823 return out;
824 }

1083/// @brief Renders @p quantity's exact decimal **alone**, with no unit suffix
1084/// (`"5.2"`, `"6"`, `"N/A"`).
1085///
1086/// The numeric half of `toString`, and the only public way to obtain it. A view
1087/// that places the number and the unit separately — a table with the unit in
1088/// its column header, a right-aligned suffix, an editable field whose adjacent
1089/// label carries the unit — asks for the two halves independently instead of
1090/// concatenating them and then chopping the suffix back off. The unit half is
1091/// `Quantity::unitMeta().display`.
1092///
1093/// This is the same exact-decimal path `std::format("{}", quantity)` takes: an
1094/// integer long division of the canonical `Rational` at its **runtime**
1095/// `DecimalPlaces`, trailing zeros trimmed. It is deliberately **not**
1096/// `std::format("{}", *quantity.value())` (which prints a `num/den` fraction)
1097/// nor `std::format("{:.Nf}", *quantity.value())` (which delegates to
1098/// `std::formatter<double>` via `toDouble()` and so leaves the exact domain —
1099/// `9007199254740993` renders as `…992` there and as itself here).
1100///
1101/// **An empty quantity renders as the fixed literal `"N/A"`, not as an empty
1102/// string.** That keeps the identity `toString(q) == toDecimalString(q) +
1103/// unitMeta().display` true for every value, engaged or not, so `toString` can
1104/// be — and is — implemented in terms of this function rather than growing a
1105/// second rendering path that can drift from it. Rendering an absent value as
1106/// blank is a presentation policy and belongs to the layer that has a layout to
1107/// decide it for; the value type only reports the fact that nothing is there.
1108/// A caller that wants a blank writes `q.hasValue() ? toDecimalString(q) : ""`.
1109/// @tparam U Unit enumerator.
1110/// @tparam Dec Declared decimals.
1111/// @param quantity The value to render.
1112/// @return The exact decimal text, or `"N/A"` when the quantity is empty.
1113template <auto U, std::uint32_t Dec>
1114[[nodiscard]] inline std::string toDecimalString(const Quantity<U, Dec>& quantity) {
1115 return detail::formatOptionalDecimal(quantity.value());
1116}

1118/// @brief Renders @p quantity as value + unit (`5.2kW`, `N/A%`) — the same
1119/// text `std::format("{}", quantity)` produces via the `std::formatter`
1120/// specialization just below, exposed as a plain function so a caller
1121/// can render a `Quantity` without going through `std::format` itself.
1122///
1123/// Exists because Emscripten's bundled libc++ (older than the Linux/Windows
1124/// standard library this project otherwise builds against — see
1125/// `.github/workflows/wasm-ladder.yml`'s `EMSDK_VERSION`) has a known
1126/// limitation recognising `std::formatter` partial specializations
1127/// parameterized over an `auto` non-type template parameter (`U` here) for
1128/// `std::format`'s compile-time formattability check — `std::format("{}",
1129/// someQuantity)` fails to compile there with "the supplied type is not
1130/// formattable" even though the specialization is valid and the identical
1131/// call compiles and runs correctly on every other toolchain this project
1132/// targets. `toString()` bypasses that check entirely: it calls the same
1133/// underlying logic directly instead of through `std::format`'s trait
1134/// machinery, so it works identically everywhere, WASM included.
1135///
1136/// Defined as `toDecimalString(quantity) + unitMeta().display` — the number and
1137/// the unit are one concatenation with a single implementation of each half, so
1138/// a caller that needs them apart calls `toDecimalString` rather than undoing
1139/// the join.
1140/// @tparam U Unit enumerator.
1141/// @tparam Dec Declared decimals.
1142/// @param quantity The value to render.
1143/// @return The formatted text.
1144template <auto U, std::uint32_t Dec>
1145[[nodiscard]] inline std::string toString(const Quantity<U, Dec>& quantity) {
1146 constexpr auto display = UnitTraits<decltype(U)>::meta(U).display;
1147 return toDecimalString(quantity) + std::string{display};
1148}
