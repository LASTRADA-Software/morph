13/// @brief `IExecutor` implementation that posts tasks to a Qt event loop.
14///
15/// Uses `QMetaObject::invokeMethod` with `Qt::QueuedConnection` so the callable
16/// always runs on the thread that owns the configured context object — by
17/// default `QCoreApplication::instance()`, i.e. the GUI thread.
18///
19/// Thread-safe: `post()` may be called from any thread. No `QObject` subclass is
20/// required by the caller.
21///
22/// **A task still queued when this executor is destroyed is dropped, not run.**
23/// `post()` enqueues and returns; it does not run the callable, and the queued
24/// Qt event outlives the `post()` call that created it. Joining the worker pool
25/// that made the call proves the `post()` *happened* — never that the event was
26/// *delivered*. Without a guard, an event still on the Qt queue at teardown is
27/// delivered against a freed executor and reads `_context` off freed memory.
28///
29/// That is not hypothetical. `Bridge::executeVia` chains three `Completion`
30/// objects per dispatched action, each settled from inside the previous one's
31/// delivered callback, so a caller waiting only on its own top-level completion
32/// can observe "done" while an intermediate post is still queued. When that
33/// stale event is finally pumped, its body calls `post()` for the next link in
34/// the chain — against an executor that no longer exists. It segfaults on an
35/// ordinary uninstrumented build, not only under a sanitizer.
36///
37/// Each queued task therefore carries a weak observer of this executor's
38/// lifetime and does nothing if the executor is already gone. Dropping is the
39/// correct outcome rather than a lesser evil: a chain being torn down has
40/// nobody left to observe its result, and `Completion`'s orphan logging already
41/// covers a completion that never resolves.
42///
43/// **Boundary of the guarantee.** The check assumes this executor is destroyed
44/// on the same thread that runs its context's event loop, which holds for every
45/// owner in this repository. Destroying one from another thread while its loop
46/// is mid-delivery still needs external synchronisation: this closes the "torn
47/// down with events still queued" hole, not a genuine cross-thread race.
48class QtExecutor : public ::morph::exec::IExecutor {
49public:
50 /// @brief Constructs an executor that posts tasks to @p context's thread.
51 ///
52 /// @param context `QObject` whose owning thread's event loop runs posted
53 /// tasks; `QMetaObject::invokeMethod` dispatches to whichever thread
54 /// `context->thread()` reports at the time each task is posted, so tasks
55 /// posted after `context` is moved to a different thread run there.
56 /// Defaults to `QCoreApplication::instance()`, preserving the previous
57 /// GUI-thread-only behaviour. Passing `nullptr` (e.g. when constructed
58 /// before `QCoreApplication` exists) makes `post()` a no-op, matching
59 /// `QMetaObject::invokeMethod`'s own handling of a null target.
60 explicit QtExecutor(QObject* context = QCoreApplication::instance())
61 : _context{context}, _alive{std::make_shared<char>()} {}
62
63 QtExecutor(const QtExecutor&) = delete;
64 QtExecutor& operator=(const QtExecutor&) = delete;
65 QtExecutor(QtExecutor&&) = delete;
66 QtExecutor& operator=(QtExecutor&&) = delete;
67
68 /// @brief Destroys the lifetime token, so any still-queued task becomes a no-op.
69 ~QtExecutor() override = default;
70
71 /// @brief Posts @p fn to the Qt event loop for execution on the context's thread.
72 ///
73 /// Returns immediately. @p fn is invoked asynchronously once the event loop
74 /// processes the queued event.
75 ///
76 /// Runs only if this executor is still alive when the event is delivered;
77 /// see the class docstring.
78 ///
79 /// @param fn Callable to execute on the context object's thread.
80 void post(std::function<void()> fn) override {
81 QMetaObject::invokeMethod(
82 _context,
83 [alive = std::weak_ptr<const char>{_alive}, fn = std::move(fn)]() mutable {
84 if (alive.expired()) {
85 return;
86 }
87 fn();
88 },
89 Qt::QueuedConnection);
90 }
91
92private:
93 QObject* _context;
94
95 // The pointee is never read -- only the control block matters, so that a
96 // queued task can ask whether this executor still exists. `make_shared`
97 // keeps it to a single allocation.
98 std::shared_ptr<const char> _alive;
99};
