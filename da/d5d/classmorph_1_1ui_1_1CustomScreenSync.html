Detailed Description

The client of a server's custom screens model (morph.customScreens) for one application, through the interpreter's own Dispatcher, so it travels the same bridge, session and backend as the screens' models.

No call names a person: the server keys every screen by the verified session's principal. Every reply arrives on the runtime's owner. Replies still in flight when the sync is destroyed or reset are dropped.

◆ probe()

void morph::ui::CustomScreenSync::probe ( std::function< void(bool offered)> done = {})

Asks whether the server offers custom screens, by calling list.

The list answering makes the offer Offered, keeps the list, tells setOnListed's handler and has the session watch the record. Any refusal makes it Off: a server that never registered the model refuses its registration with unknown model type: morph.customScreens, which is how a client learns custom screens are not offered; any other failure is logged at warn too, worded by its cause (refused, unreadable reply, or the transport), since it is a misconfiguration or an outage rather than an absence.

Parameters
doneCalled once with whether they are offered; may be empty.

◆ relist()

void morph::ui::CustomScreenSync::relist ( )

Calls list again, while the offer is Offered: the cache drops what the list shows changed, and setOnListed's handler is told. A refusal is logged at warn and keeps the last list.

The replies of one sync's calls arrive in the order the calls were made, because every call goes through the one private channel; a list never overtakes a later one.
