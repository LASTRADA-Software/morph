3/// @file
4/// @brief Opt-in, compiler-independent shape tag for a type with a custom
5/// Glaze codec.
6///
7/// `morph::model::payloadShape` decomposes a payload struct from `std::` type
8/// traits and Glaze's *reflected key strings*, never from a compiler-spelled
9/// type name — that portability is the whole reason a journal written by one
10/// build is readable by another. The cost is that a type carrying its own
11/// `glz::meta` has no reflected members to decompose, so it renders as the
12/// single opaque tag `x`, and a retype between two such types (`Rational` for
13/// `Timestamp`, `Quantity<Gram>` for `Quantity<Litre>`) changes nothing about
14/// the fingerprint. For `Quantity` that is the *only* place such a swap could
15/// be caught at all: neither the unit nor the declared precision travels on
16/// the wire, so the JSON is byte-identical either way.
17///
18/// This header is the seam that closes it. A custom-codec type specialises
19/// `PayloadShapeTag` to declare a short, stable, author-written name, and
20/// `payloadShape` renders that name instead of the bare `x`. The name is
21/// spelled in this repository's own sources, so it does not vary with the
22/// compiler, the standard library, or the platform — which a `glz::name_v`
23/// tag would, and a journal readable only by the compiler that wrote it is
24/// the worse failure.
25///
26/// It is opt-in, and therefore incomplete by construction: a *new* custom-codec
27/// type that declares nothing still renders as `x`. That is the residual
28/// boundary, and `docs/spec/journal/journal.md`'s "What the fingerprint does
29/// not catch" states it.
30///
31/// The trait lives in its own header, separate from `core/payload_schema.hpp`,
32/// so that `morph/util/rational.hpp` and its peers can declare their tags
33/// without any of them depending on the journal machinery.
34///
35/// **Visibility rule.** A specialisation must be visible wherever
36/// `payloadShape` is instantiated for that type, or two translation units
37/// would render the same payload differently. In practice this is automatic:
38/// a payload struct with a `Rational` member is only a complete type where
39/// `morph/util/rational.hpp` has been included, and that header carries the
40/// specialisation.
41

48/// @brief Declares a stable shape tag for a type `T` whose JSON shape
49/// `payloadShape` cannot decompose.
50///
51/// The primary template is deliberately empty: an unspecialised type has no
52/// declared tag and keeps rendering as the opaque `x`. A specialisation
53/// provides
54///
55/// ```cpp
56/// static std::string_view name(); // required
57/// using Inner = <type>; // optional
58/// ```
59///
60/// `name()` must return a name that is stable for the lifetime of the returned
61/// view (a literal, or a function-local `static const std::string`), and must
62/// be spelled in these sources rather than derived from a compiler builtin.
63/// `Inner`, when present, names a type whose shape is rendered *inside* the
64/// tag — for a transparent wrapper such as `Tagged<T, Tag>`, whose JSON simply
65/// *is* `T`'s, that keeps the underlying shape visible instead of hiding it
66/// behind the wrapper's name.
67///
68/// @tparam T Type the tag is declared for.
69template <typename T>
70struct PayloadShapeTag {};
71
72/// @brief Satisfied when `T` declares a stable shape tag.
73template <typename T>
74concept HasPayloadShapeTag = requires {
75 { PayloadShapeTag<T>::name() } -> std::convertible_to<std::string_view>;
76};
77
78/// @brief Satisfied when `T`'s tag also names an inner type to render inside
79/// it (a transparent wrapper).
80template <typename T>
81concept HasPayloadShapeInner = HasPayloadShapeTag<T> && requires { typename PayloadShapeTag<T>::Inner; };
82
83} // namespace morph::model
