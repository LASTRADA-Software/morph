Detailed Description

The client side of the UI service (spec 5 §12, "Content addressing"): UiClient runs ui-hello, ui-catalog and ui-fetch over a transport the caller supplies, verifies every file against the manifest and the manifest against the ui-hello digest, and keeps what it verified in a VerifiedCache.

Specified in docs/spec/ui/service.md.

◆ exchangeOver()

Exchange morph::ui::exchangeOver ( ::morph::backend::IEnvelopeTransport & backend,
::morph::exec::IExecutor & cbExec )
inlinenodiscard

An Exchange over a transport: each request is one IEnvelopeTransport::request, and its reply, ok or err, is the exchange's reply; a failure to deliver either is the error, as its message.

Call it on cbExec's thread, where its replies arrive: UiClient sends each request from the reply before it, so a client opened there stays there.

Parameters
backendThe transport: SocketBackend or QtWebSocketBackend. Borrowed: it must outlive every request sent through the exchange, so a caller that may destroy it first guards the exchange itself.
cbExecThe executor replies are delivered on: the interpreter runtime's owner. Borrowed.
Returns
The exchange.

inlinenodiscard

A watcher over the server (spec 8 §7): each watch or unwatch is one request of that kind through exchange, carrying the session currentSession returns when it is sent. What SessionOptions::watcher takes.

The session is read at each send, not fixed when the watcher is built, because a watch must carry whoever is signed in now: the exchange does not stamp it, and the server refuses an unsigned one.

Parameters
exchangeThe transport.
currentSessionThe session to stamp on each request, read when it is sent.
cbExecThe executor the completion is delivered on: the interpreter runtime's owner. Borrowed.
Returns
The watcher: the kind and the WatchBody JSON in; the reply body out, or the transport's or the server's reason as the failure.
