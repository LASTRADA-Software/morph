17/// @file
18/// @brief Per-model execute-ordering gate, extracted out of `RemoteServer`.
19///
20/// The per-model execute-ordering gate `RemoteServer` dispatches through. Its
21/// contract — hand out monotonic tickets per `ModelId`; block a ticket until
22/// its predecessor releases; tolerate releases arriving out of order; erase the
23/// gate when drained; tolerate a gate already erased — touches no wire format,
24/// no authorizer, no model, no executor and no strand, so it lives here rather
25/// than inside the server.
26///
27/// `takeAndPost` takes a ticket and enqueues the work in one atomic step, the
28/// `Ticket` it returns is bound to the exact `Gate` it was issued from (so a
29/// drain-and-recreate cannot redirect a later `awaitTurn`), and a gate-wide
30/// `std::recursive_mutex` is held across the caller's `postFn`. Read
31/// `takeAndPost`'s doc before reasoning about lock order here: it is
32/// `_enqueueMtx` then `_mtx`, never the reverse. One mutex *per model* instead
33/// deadlocks two threads against each other.
34namespace morph::backend::detail {
35
36/// @brief Hands out monotonic per-`ModelId` tickets and lets callers block
37/// until their ticket's turn comes, tolerating releases that arrive
38/// out of ticket order.
39///
40/// Keyed by `ModelId`, not held forever: a model with no outstanding tickets
41/// has no entry in the internal map at all (erased once its last ticket is
42/// released), so this never grows unbounded across the gate's lifetime the
43/// way a per-model map with no cleanup would.
44class ExecuteOrderGate {
45private:
46 struct Gate; // Forward-declared; full definition is below, in the private section.
47
48public:
49 /// @brief Opaque handle to one outstanding ticket, bound to the specific
50 /// `Gate` instance it was issued from.
51 ///
52 /// `take(mid)` plus a later `awaitTurn(mid, ticket)`/`release(mid, ticket)`
53 /// re-derive "the gate for `mid`" by a fresh map lookup each time — correct
54 /// only if the entry found is still the same `Gate` the ticket came from.
55 /// It might not be: a model's entry is erased once it fully drains (see
56 /// `releaseOnGateLocked`), and a *later* ticket for the same `mid`, still
57 /// in-flight (its dispatch task enqueued but not yet reached by a worker --
58 /// easy to hit under load once `takeAndPost` lets the producer run well
59 /// ahead of the workers), can find a *newer* `Gate` already sitting where
60 /// the old one used to be. Its `awaitTurn` then waits on that new gate's
61 /// independent counter for a ticket number it will never produce --
62 /// permanently. The atomic `takeAndPost` is what makes this reachable: a
63 /// two-step `take()`-then-post() throttles the producer just enough that a
64 /// gate essentially never drains mid-burst, and `takeAndPost` removes that
65 /// throttle. `Ticket` closes the hole by carrying the exact `Gate`
66 /// `shared_ptr` a ticket was issued from, so `awaitTurn(Ticket)` and
67 /// `release(Ticket)` operate on that object directly -- never a fresh
68 /// lookup, so a drain-and-recreate of the map entry cannot redirect them.
69 ///
70 /// Default-constructed to the empty state (`empty()` true), mirroring a
71 /// disengaged `std::optional` -- `handleImpl`'s non-`execute` path passes
72 /// one of these to mean "no ticket was ever taken".
73 class Ticket {
74 public:
75 /// @brief Constructs the empty ticket (no ticket taken).
76 Ticket() = default;
77
78 /// @brief True if this handle carries no ticket.
79 [[nodiscard]] bool empty() const noexcept { return _gate == nullptr; }
80
81 private:
82 friend class ExecuteOrderGate;
83
84 /// @param mid The model this ticket orders against.
85 /// @param number The ticket number minted for it.
86 /// @param gate The exact `Gate` it was issued from.
87 /// @param released The shared "already released" flag. Passed in rather
88 /// than allocated here so the caller can allocate it *before*
89 /// minting @p number: `make_shared` can throw `bad_alloc`, and a
90 /// throw between `nextTicket++` and the ticket becoming owned
91 /// strands that number forever -- `nextToRun` can then never
92 /// reach `nextTicket`, the gate entry is never erased, and every
93 /// later ticket for the model parks in the deadline-less
94 /// `awaitTurn`.
95 Ticket(::morph::exec::detail::ModelId mid, std::uint64_t number, std::shared_ptr<Gate> gate,
96 std::shared_ptr<std::atomic<bool>> released)
97 : _mid{mid}, _number{number}, _gate{std::move(gate)}, _released{std::move(released)} {}
98
99 ::morph::exec::detail::ModelId _mid{};
100 std::uint64_t _number{0};
101 std::shared_ptr<Gate> _gate;
102 // Shared across every copy of this logical ticket -- `Ticket` is
103 // freely copyable and both `ExecuteTicketGuard` (via `dispatchMessage`)
104 // and `takeAndPost`'s own exception path can independently decide to
105 // release the "same" ticket (a non-`std::exception` throw escaping
106 // dispatchMessage's `catch (const std::exception&)` unwinds through
107 // both). `release(Ticket)` claims this flag with `exchange(true)`
108 // before doing any work, so only the first caller actually runs the
109 // release logic -- a second call is a silent no-op instead of
110 // inserting an already-passed ticket number into `releasedOutOfOrder`
111 // a second time, which would sit there as the set's permanent
112 // minimum and quietly break every future out-of-order release for
113 // this gate.
114 std::shared_ptr<std::atomic<bool>> _released;
115 };

117 /// @brief Hands out the next ticket for @p mid, in call order.
118 ///
119 /// Intended to be called synchronously, on whatever thread received the
120 /// request, before anything asynchronous happens -- the ticket numbers
121 /// two calls receive for the same `mid` are therefore always in the
122 /// order this was called in.
123 ///
124 /// This bare-number ticket, and the by-`ModelId` `awaitTurn`/`release`
125 /// overloads below that go with it, still carry the exact erase-and-
126 /// recreate hazard `Ticket`'s own doc comment describes: nothing here
127 /// stops @p mid's gate from fully draining and being replaced by a new
128 /// one between this call and a later `awaitTurn(mid, ticket)` or
129 /// `release(mid, ticket)` on the same number. Do not use this trio to
130 /// drive a ticket across an asynchronous gap -- take it via `takeTicket`
131 /// or `takeAndPost` instead, and drive it through the `Ticket`-typed
132 /// overloads. This overload exists for tests that exercise the gate's
133 /// raw counter/out-of-order-release state machine directly, and for
134 /// `takeAndPost`'s own internals, which never let this gap open.
135 /// @param mid The model the upcoming turn is for.
136 /// @return This call's ticket number.
137 [[nodiscard]] std::uint64_t take(::morph::exec::detail::ModelId mid) {
138 std::scoped_lock const lock{_mtx};
139 return getOrCreateGateLocked(mid)->nextTicket++;
140 }
141
142 /// @brief Hands out the next ticket for @p mid, in call order, as a
143 /// `Ticket` bound to the gate it came from.
144 ///
145 /// Not atomic with any enqueue step the way `takeAndPost` is -- this is
146 /// for callers that only need a valid, correctly-bound `Ticket` to test
147 /// or drive `awaitTurn(Ticket)`/`release(Ticket)`/`ExecuteTicketGuard`
148 /// directly, without a real dispatch pipeline behind it.
149 /// @param mid The model the upcoming turn is for.
150 /// @return This call's ticket, bound to @p mid's current gate.
151 [[nodiscard]] Ticket takeTicket(::morph::exec::detail::ModelId mid) {
152 // Allocated before the number is minted -- same reason as `takeAndPost`:
153 // a throw between `nextTicket++` and the owning `Ticket` strands that
154 // number, and nothing can ever release it.
155 auto released = std::make_shared<std::atomic<bool>>();
156 std::shared_ptr<Gate> gate;
157 std::uint64_t number = 0;
158 {
159 std::scoped_lock const lock{_mtx};
160 gate = getOrCreateGateLocked(mid);
161 number = gate->nextTicket++;
162 }
163 return Ticket{mid, number, std::move(gate), std::move(released)};
164 }

166 /// @brief Atomically hands out the next ticket for @p mid and invokes
167 /// @p postFn with a `Ticket` bound to it, holding the gate's
168 /// take-then-enqueue window open for the whole call.
169 ///
170 /// `take()` followed by a separate, unlocked enqueue (e.g. to a worker
171 /// pool) lets two concurrent callers' ticket numbers and enqueue order
172 /// diverge: caller A can take ticket 0 and then be pre-empted before
173 /// enqueueing, while caller B takes ticket 1 and enqueues immediately — so
174 /// a pool worker picks up ticket 1 first, blocks in `awaitTurn` waiting for
175 /// ticket 0, and A's own enqueued work never gets a worker to run on --
176 /// reachable with `RemoteServer::handleImpl` and its worker pool.
177 /// Folding the enqueue into the same critical section as `take`
178 /// makes that divergence impossible: whichever caller's `takeAndPost` runs
179 /// first for a given model gets both the lower ticket number and the
180 /// earlier enqueue slot, for any thread scheduling, because a second
181 /// concurrent caller *for that same model* cannot even take its ticket
182 /// until the first has finished enqueueing.
183 ///
184 /// The gate's **one** enqueue mutex is acquired first, with no other lock
185 /// held, and `_mtx` only after — never the other way round.
186 ///
187 /// @par Why one mutex and not one per model
188 /// `enqueueLock` is deliberately held across `postFn`, and `postFn` is
189 /// opaque: on a `ThreadPoolExecutor` it only enqueues, but on a synchronous
190 /// executor it runs the entire dispatch chain inline, including any
191 /// re-entrant `takeAndPost` that chain triggers. With a mutex *per model*
192 /// that gave two threads two locks to take in opposite orders — thread A
193 /// inside model 1's callback reaching for model 2, thread B the mirror —
194 /// and they deadlocked. Measured, not theorised: a two-thread probe against
195 /// the per-model version hung every time, while `master` (which held no
196 /// lock across a caller callback at all) could not exhibit it.
197 ///
198 /// One mutex cannot form a cycle with itself, so that class of deadlock is
199 /// gone by construction. `std::recursive_mutex` because a synchronous
200 /// executor can re-enter `takeAndPost` on the *same* thread, which a plain
201 /// mutex would self-deadlock on.
202 ///
203 /// The cost is real and accepted: `takeAndPost` now serialises across every
204 /// model rather than per model, and on a synchronous executor that means
205 /// serialising the dispatch those callbacks perform.
206 ///
207 /// @par What this buys back
208 /// Because the enqueue mutex is taken *before* `_mtx` and never inside it,
209 /// the gate fetch and the ticket increment can share one continuous `_mtx`
210 /// hold again. That closes the window a split hold left open — a concurrent
211 /// `release()` draining and erasing this exact gate between "fetched" and
212 /// "ticket assigned", minting this ticket on an orphaned generation while a
213 /// racing `takeAndPost(mid)` gets a fresh one — with no re-check or retry
214 /// loop needed.
215 ///
216 /// @param mid The model the upcoming turn is for.
217 /// @param postFn Invoked synchronously, with a `Ticket` for this call,
218 /// while the enqueue mutex is held — but *not* while `_mtx`
219 /// (the ticket-bookkeeping lock `awaitTurn` and `release`
220 /// use) is held. If it throws, the ticket is released before
221 /// the exception propagates, exactly as if it had never been
222 /// taken.
223 template <typename PostFn>
224 void takeAndPost(::morph::exec::detail::ModelId mid, PostFn&& postFn) {
225 // Allocated before a ticket number exists, so nothing between the mint
226 // and the owning `Ticket` can throw. See `Ticket`'s constructor.
227 auto released = std::make_shared<std::atomic<bool>>();
228
229 // First, and with no other lock held. Held across postFn, including any
230 // re-entrant takeAndPost it triggers.
231 std::scoped_lock const enqueueLock{_enqueueMtx};
232
233 std::shared_ptr<Gate> gate;
234 std::uint64_t number = 0;
235 {
236 std::scoped_lock const lock{_mtx};
237 gate = getOrCreateGateLocked(mid);
238 number = gate->nextTicket++;
239 }
240 Ticket const ticket{mid, number, gate, std::move(released)};
241 try {
242 std::forward<PostFn>(postFn)(ticket);
243 } catch (...) {
244 release(ticket);
245 throw;
246 }
247 // `enqueueLock` releases here, at the end of scope -- after postFn,
248 // including any reentrant takeAndPost(mid) it triggered, is done.
249 }

251 /// @brief Blocks until @p ticket is next in line for @p mid, then returns.
252 /// @param mid The model @p ticket was taken for.
253 /// @param ticket This call's ticket, from `take`.
254 void awaitTurn(::morph::exec::detail::ModelId mid, std::uint64_t ticket) {
255 std::unique_lock lock{_mtx};
256 auto iter = _gates.find(mid);
257 if (iter == _gates.end()) {
258 return; // Nothing left to wait for -- every ticket for mid already released.
259 }
260 auto gate = iter->second; // Keep it alive even if release() erases the map entry mid-wait.
261 gate->cv.wait(lock, [&gate, ticket] { return gate->nextToRun == ticket; });
262 }
263
264 /// @brief Blocks until @p ticket's turn comes, on the exact `Gate` it was
265 /// issued from -- immune to that model's map entry being erased
266 /// and recreated while this ticket was in flight (see `Ticket`'s
267 /// own doc comment). A no-op if @p ticket is empty.
268 /// @param ticket A ticket from `takeAndPost`.
269 void awaitTurn(const Ticket& ticket) {
270 if (ticket.empty()) {
271 return;
272 }
273 std::unique_lock lock{_mtx};
274 auto& gate = *ticket._gate;
275 // `>=`, not `==`. `nextToRun` is the lowest ticket not yet released, so
276 // once it has moved *past* this ticket's number the turn has come and
277 // gone and there is nothing left to wait for. An exact match parks
278 // forever in that case, and it is reachable: `Ticket` is deliberately
279 // copyable with two owners that can each release it, so if
280 // `takeAndPost`'s `catch (...)` releases after `postFn` already enqueued
281 // a task holding its own copy, that task's `awaitTurn` would wait on a
282 // number `nextToRun` has already passed. There is no deadline here, so
283 // "wait forever" means a parked pool worker for the life of the process.
284 // Mirrors the by-ModelId overload, which returns immediately once the
285 // gate entry is gone.
286 gate.cv.wait(lock, [&gate, &ticket] { return gate.nextToRun >= ticket._number; });
287 }

289 /// @brief Releases @p ticket for @p mid, letting the next ticket (if any) proceed.
290 ///
291 /// Must be called exactly once per ticket taken. A ticket that is taken
292 /// but never released would permanently stall every later ticket for the
293 /// same `mid`, since `awaitTurn` waits with no deadline. (`RemoteServer`
294 /// enforces the "exactly once" half of that contract structurally, via
295 /// `ExecuteTicketGuard` below -- see its own doc comment.)
296 /// @param mid The model @p ticket was taken for.
297 /// @param ticket The ticket to release.
298 void release(::morph::exec::detail::ModelId mid, std::uint64_t ticket) {
299 std::scoped_lock const lock{_mtx};
300 auto iter = _gates.find(mid);
301 if (iter == _gates.end()) {
302 // A supported call, not an impossibility: the file-level contract
303 // above lists "tolerate a gate already erased" as a first-class
304 // element, and tests/test_execute_order_gate.cpp names the case
305 // ("releasing a ticket for a model with no gate entry is a
306 // harmless no-op").
307 return;
308 }
309 // `iter` already names the exact entry `gate` came from, so pass it
310 // straight through -- no need to re-derive it by another `_gates.find`
311 // the way `release(const Ticket&)` has to (there, `ticket._gate` may
312 // no longer be the current entry at all; see `releaseOnGateLocked`).
313 releaseOnGateLocked(iter, ticket);
314 }
315
316 /// @brief Releases @p ticket on the exact `Gate` it was issued from --
317 /// immune to that model's map entry being erased and recreated
318 /// while this ticket was in flight (see `Ticket`'s own doc
319 /// comment). A no-op if @p ticket is empty **or already released**
320 /// -- `Ticket` is copyable and two independent owners of the same
321 /// logical ticket (`ExecuteTicketGuard` and `takeAndPost`'s own
322 /// exception path both can be, when a non-`std::exception` throw
323 /// escapes `dispatchMessage`'s narrower catch) can each decide to
324 /// release it; only the first one actually does (see `Ticket`'s
325 /// own doc comment on `_released`).
326 /// @param ticket A ticket from `takeAndPost`.
327 void release(const Ticket& ticket) {
328 if (ticket.empty()) {
329 return;
330 }
331 std::scoped_lock const lock{_mtx};
332 // Claimed *under* `_mtx` and *after* the bookkeeping, not before it.
333 // Every release serialises on this mutex, so a plain load/store here is
334 // still exactly-once -- but claiming the flag first meant a throw in the
335 // locked section below (the `releasedOutOfOrder` node allocation can
336 // throw `bad_alloc`) left the ticket permanently un-releasable by every
337 // owner, with `nextToRun` never reaching `nextTicket`, the gate entry
338 // never erased, and every later `awaitTurn` for that model blocked
339 // forever. Leaving the flag clear on a throw lets the other owner retry.
340 if (ticket._released->load()) {
341 return;
342 }
343 Gate& gate = *ticket._gate;
344 bool const drained = advanceOnReleaseLocked(gate, ticket._number);
345 ticket._released->store(true);
346 if (!drained) {
347 return;
348 }
349 // Unlike `release(mid, ticket)`, which already holds the exact
350 // iterator `gate` came from, `ticket._gate` may no longer be the
351 // entry currently sitting at `_gates[ticket._mid]` -- it is immune to
352 // being *misdirected* by an erase-and-recreate (that is the whole
353 // point of `Ticket`), but that immunity means it must independently
354 // re-check whether it is still current before erasing it. Comparing
355 // the stored pointer is a cheap, explicit invariant check rather than
356 // a silent assumption.
357 auto iter = _gates.find(ticket._mid);
358 if (iter != _gates.end() && iter->second.get() == &gate) {
359 _gates.erase(iter);
360 }
361 }

363 /// @brief Number of models with at least one outstanding (unreleased) ticket.
364 ///
365 /// Test-only observability, mirroring `PendingCallTable::size()` --
366 /// stale the moment the lock is released, so it must not drive a
367 /// check-then-act decision.
368 /// @return Current map size.
369 [[nodiscard]] std::size_t gateCount() const {
370 std::scoped_lock const lock{_mtx};
371 return _gates.size();
372 }

374private:
375 struct Gate {
376 std::uint64_t nextTicket = 0;
377 std::uint64_t nextToRun = 0;
378 // Tickets released *before* their turn came, held aside until every
379 // ticket ahead of them has released too. Not an optimisation: it is
380 // what makes `nextToRun` mean "the lowest ticket not yet released"
381 // rather than "one past whichever ticket released last". See
382 // `releaseOnGateLocked`. Ordered, because the release
383 // loop consumes it from the front; small by construction (it holds at
384 // most the tickets in flight for one model, minus one).
385 std::set<std::uint64_t> releasedOutOfOrder;
386 std::condition_variable cv;
387 };

389 /// @brief Returns @p mid's `Gate`, creating it if this is its first ticket.
390 /// Assumes `_mtx` is already held by the caller.
391 /// @param mid The model to find or create a gate for.
392 /// @return The (possibly just-created) gate for @p mid.
393 [[nodiscard]] std::shared_ptr<Gate>& getOrCreateGateLocked(::morph::exec::detail::ModelId mid) {
394 auto& slot = _gates[mid];
395 if (!slot) {
396 slot = std::make_shared<Gate>();
397 }
398 return slot;
399 }

401 /// @brief Advances @p gate's ticket bookkeeping for @p ticket's release,
402 /// assuming `_mtx` is already held by the caller. Shared by both
403 /// `release()` overloads.
404 /// @param gate The gate @p ticket was issued from.
405 /// @param ticket The ticket to release.
406 /// @return `true` if this was the release that leaves every ticket
407 /// `gate` has ever handed out released (i.e. `gate` is now fully
408 /// drained and its map entry, if it still has one, may be
409 /// erased); `false` otherwise, in which case any waiter is
410 /// notified instead.
411 [[nodiscard]] static bool advanceOnReleaseLocked(Gate& gate, std::uint64_t ticket) {
412 // `nextToRun` is the lowest ticket that has *not* released yet, which
413 // is exactly what `awaitTurn`'s `nextToRun == ticket` predicate needs
414 // it to be. Advancing it to `ticket + 1` unconditionally was only
415 // correct if tickets released in order, and callers deliberately do
416 // not guarantee that: a caller may need to release a ticket
417 // immediately, without ever waiting for its turn, precisely so that
418 // ticket cannot hold up the live work behind it (`RemoteServer`'s
419 // rejection paths -- model not found, unauthorized, over limit, a
420 // shutdown gate -- all do exactly this). Applying a later ticket's
421 // release directly would push `nextToRun` straight past an earlier
422 // ticket's number, leaving that ticket's waiter with a predicate that
423 // can never become true again -- a caller parked forever.
424 //
425 // So an out-of-order release is recorded rather than applied, and
426 // `nextToRun` walks forward only over a contiguous run of released
427 // tickets. `ticket < nextToRun` cannot happen: every ticket is
428 // released exactly once, and `nextToRun` only moves past tickets that
429 // have already released.
430 if (ticket == gate.nextToRun) {
431 ++gate.nextToRun;
432 while (!gate.releasedOutOfOrder.empty() && *gate.releasedOutOfOrder.begin() == gate.nextToRun) {
433 gate.releasedOutOfOrder.erase(gate.releasedOutOfOrder.begin());
434 ++gate.nextToRun;
435 }
436 } else {
437 gate.releasedOutOfOrder.insert(ticket);
438 }
439 // Notify before the drained-path return, not only on the other branch.
440 // "Fully drained" means every ticket handed out has released -- but a
441 // waiter can still be parked on one of them (see `awaitTurn`'s note on
442 // the two owners of a `Ticket`), and returning without a notify left it
443 // asleep on a predicate that had already become true.
444 gate.cv.notify_all();
445 // True means: safe to drop the entry, so a model with no in-flight
446 // tickets leaves no trace in this map. Reaching `nextTicket` this way
447 // means every ticket handed out has released, so `releasedOutOfOrder`
448 // is necessarily empty here.
449 return gate.nextToRun == gate.nextTicket;
450 }

452 /// @brief `release(mid, ticket)`'s implementation, assuming `_mtx` is
453 /// already held by the caller and @p iter names the exact entry
454 /// `iter->second` was issued from -- so, unlike
455 /// `release(const Ticket&)`, no identity re-check is needed before
456 /// erasing: nothing could have replaced `*iter` since the caller
457 /// looked it up, still under the same `_mtx` critical section.
458 /// @param iter Iterator into `_gates`, naming @p ticket's gate.
459 /// @param ticket The ticket to release.
460 void releaseOnGateLocked(std::unordered_map<::morph::exec::detail::ModelId, std::shared_ptr<Gate>,
461 ::morph::exec::detail::ModelIdHash>::iterator iter,
462 std::uint64_t ticket) {
463 if (advanceOnReleaseLocked(*iter->second, ticket)) {
464 _gates.erase(iter);
465 }
466 }
467
468 // Serialises `takeAndPost` from first lock to after `postFn` returns, so a
469 // ticket number and the enqueue that follows it cannot interleave with
470 // another call's. **One mutex for the whole gate, not one per model** --
471 // see `takeAndPost` for the two-thread cross-model deadlock a per-model
472 // mutex allowed, and for what the single lock costs.
473 //
474 // Recursive because a synchronous executor can run `postFn`'s whole
475 // dispatch chain inline, including a re-entrant `takeAndPost` on this same
476 // thread, which a plain mutex would self-deadlock on. Same-thread
477 // re-entrancy is never concurrent with itself, so it needs no ordering
478 // against itself -- only against other threads, which is exactly what a
479 // recursive mutex still provides.
480 //
481 // Lock order: this, then `_mtx`. Never the reverse.
482 mutable std::recursive_mutex _enqueueMtx;
483 mutable std::mutex _mtx;
484 std::unordered_map<::morph::exec::detail::ModelId, std::shared_ptr<Gate>, ::morph::exec::detail::ModelIdHash>
485 _gates;
486};

488/// @brief Owns a taken `ExecuteOrderGate` ticket and releases it on every exit
489/// path, unless ownership was explicitly handed on.
490///
491/// A ticket handed out by `ExecuteOrderGate::takeAndPost` must be released
492/// exactly once by whatever path took it: an unreleased ticket permanently
493/// stalls every later ticket for the same model, because `awaitTurn` is a
494/// `cv.wait` with no deadline. In `RemoteServer` (the sole caller today) that
495/// rule used to be a per-call-site convention, and the convention was missed
496/// two ways: by a shutdown gate that returns before the one place that
497/// releases a ticket, and by an exception that unwinds past a dispatch
498/// function's early returns. This holder makes the rule
499/// structural instead of remembered: the ticket is owned from the moment it
500/// is taken until the guard dies, so every exit path -- `return`, `throw`,
501/// and any branch a later change adds -- releases it. Two members opt out
502/// deliberately:
503///
504/// - `release()`, for the paths that want the ticket freed *before* some
505/// later, possibly-slow step, so that step never holds a later same-model
506/// ticket up; and
507/// - `disarm()`, for the one place ownership is genuinely handed on to
508/// another owner (e.g. a task posted to a different executor).
509///
510/// Neither copyable nor movable: it is only ever a local of the frame that
511/// owns the ticket.
512class ExecuteTicketGuard {
513public:
514 /// @brief Adopts @p ticket on behalf of @p gate.
515 /// @param gate Gate @p ticket belongs to. Borrowed: a guard is always a
516 /// local of a frame that does not outlive the gate.
517 /// @param ticket This call's ticket from `ExecuteOrderGate::takeAndPost`,
518 /// or the empty `Ticket` if it took none, in which case the
519 /// guard is inert.
520 ExecuteTicketGuard(ExecuteOrderGate& gate MORPH_LIFETIMEBOUND, ExecuteOrderGate::Ticket ticket) noexcept
521 : _gate{gate}, _ticket{std::move(ticket)} {}
522
523 ExecuteTicketGuard(const ExecuteTicketGuard&) = delete;
524 ExecuteTicketGuard(ExecuteTicketGuard&&) = delete;
525 ExecuteTicketGuard& operator=(const ExecuteTicketGuard&) = delete;
526 ExecuteTicketGuard& operator=(ExecuteTicketGuard&&) = delete;
527
528 /// @brief Releases the ticket if it is still held -- the backstop that
529 /// covers every path which did not release explicitly.
530 ~ExecuteTicketGuard() { release(); }
531
532 /// @brief Releases the held ticket now, letting the next ticket for the
533 /// same model proceed. Idempotent: a no-op if no ticket was taken,
534 /// or if it has already been released or disarmed.
535 void release() {
536 if (_ticket.empty()) {
537 return;
538 }
539 // Cleared before the release, not after: this guard owes nothing
540 // further from here on, so the destructor cannot release twice even
541 // if `ExecuteOrderGate::release` itself exits by exception.
542 auto held = std::exchange(_ticket, ExecuteOrderGate::Ticket{});
543 _gate.release(held);
544 }
545
546 /// @brief Gives up ownership *without* releasing, for the one path that
547 /// hands the ticket on to a new owner.
548 void disarm() noexcept { _ticket = ExecuteOrderGate::Ticket{}; }
549
550 /// @brief Blocks until the held ticket's turn comes (see
551 /// `ExecuteOrderGate::awaitTurn`). A no-op if no ticket is held.
552 void awaitTurn() {
553 if (!_ticket.empty()) {
554 _gate.awaitTurn(_ticket);
555 }
556 }
557
558private:
559 ExecuteOrderGate& _gate;
560 ExecuteOrderGate::Ticket _ticket;
561};
