Checks that custom uses nothing its base screen does not: the base rule.

Compared: the actions it names, wherever declared and component fallbacks included, each on its model type and in a position of the same kind (a query, a mutation, a model-backed table, a collection, a wizard, or a form by its literal submit: none, explicit or auto); the commands run without a press (from a lifecycle list, a watch, a component's on event, a form whose submit is not explicit, or the onSuccess and onError of a mutation that a run, an upload or a signIn among them reaches, each name resolved in the scope that declares the mutation), by trigger. A form with no submit keeps its action schema's mode, which this check cannot see and which is automatic unless the schema says otherwise, so it counts as submitting itself.

Also compared: the client-side commands upload, download, switchBackend, signIn, signOut and resetPrefs; every host name, whether a host command, a host value or a host component; each host command as a whole, name and arguments, which must be identical to one of the base's; the delivered components, by name and content hash; and the params, which must be the base's exactly. Every upload of the custom document must send exactly {"ref": "event"} and sit directly in the onPick of a filePicker that opens files (no mode, or open) or in a dropZone's onDrop, so it is always a file the person just chose. A host command's arguments must be literals. Text, layout, styles, states and expressions are not compared.

Parameters
baseThe base screen, loaded.
baseTextThe base screen's JSON text.
customThe custom document, loaded.
customTextThe text custom was loaded from, which the host names are read from.
Returns
The first use the base does not have, with its JSON Pointer, or nothing.
Exceptions
std::logic_errorWhen a document names a model alias it does not declare, which only a document that skipped load-time validation can.

Runs every check a custom document passes, in order, and answers the first refusal.

  1. The bounds: maxDocumentBytes, and nesting within kMaxJsonDepth. Neither needs the document parsed.
  2. The base: a screen document of bundle that the person may open (screenAdmitted).
  3. The application screen checks: loadDocumentText with the bundle's catalog, and its id is screenId, which starts with kCustomScreenIdPrefix, so it is a screen and never the app document.
  4. The accessibility rules (author::checkAccessibility).
  5. The base rule (checkBaseRule).
  6. Permission: every action the document names is in permittedActions.

Check 2 reads the bundle and the authoriser on every call: the bundle's digest does not cover whether a screen entry is available, so a cached verdict cannot vouch for the base. Checks 3 to 6 are answered from cache when it holds the verdict, and stored in it otherwise.

Parameters
bundleThe served bundle.
sessionThe session, its principal verified.
authorizerThe authoriser.
basedOnThe base screen's id.
documentThe custom document's text.
screenIdThe id the document is stored under: its id member must be this.
optionsThe bounds.
cacheThe verdict cache; null checks every time.
Returns
The first refusal, with its JSON Pointer, or nothing when the document passes.

MORPH_API std::shared_ptr< CustomScreens > morph::ui::registerCustomScreens ( std::shared_ptr< ICustomScreenStore > store,

Registers the custom screens model and its five actions, with a factory that gives every instance one shared context.

A server that offers custom screens calls this once, before it serves, with the dispatcher and registry its RemoteServer uses. Its authoriser then admits morph.customScreens and its actions for every signed-in principal; the model keeps each person to what the store answers them. A client learns that a server offers custom screens by calling list: a server that did not call this answers the dispatcher's unknown-model error.

Parameters
storeWhere custom screens are kept, and the application's policy over them.
bundleThe bundle being served now; called at every action, so a development reload is seen, from action strands on any thread, so it must be thread-safe.
authorizerThe server's authoriser, for the permitted set and the base screen's admission.
dispatcherThe server's action dispatcher.
registryThe server's model registry.
optionsThe bounds. maxDocumentBytes is at most kMaxFileBytes.
Returns
The handle the model uses, for whatever else serves custom screens on this server.
