19/// @brief What one replay attempt actually achieved.
20///
21/// The distinction that matters is **delivery**, not success: a replay the
22/// server refused and a replay the server never saw both leave the item
23/// queued, but only the first is evidence about the payload. Charging both to
24/// the same retry budget means a run of reconnect flaps dead-letters work that
25/// was never offered to anyone — reported to the user as a change that could
26/// not be applied, and dropped. See `SyncWorker`'s retry documentation and
27/// docs/spec/offline/offline.md.
28enum class ReplayOutcome : std::uint8_t {
29 /// @brief Delivered and accepted. The item is removed from the queue.
30 Succeeded,
31
32 /// @brief Delivered, and the peer refused it. Charges one attempt against
33 /// the retry budget; dead-letters the item once the budget is spent.
34 /// This is what `false` means on the boolean `ReplayFunction`.
35 Rejected,
36
37 /// @brief Never reached the peer (the connection was down, or dropped
38 /// before anything was committed). Charges **nothing**: the item
39 /// stays queued with its attempt count untouched, in memory and on
40 /// disk alike. Report this only when the payload demonstrably was
41 /// not acted on — an outcome that is really "I don't know" must be
42 /// `Rejected`, or a genuinely poisonous payload is retried forever.
43 Undelivered,
44};
45
46/// @brief Aggregated result returned by `SyncWorker::run()`.
47struct SyncResult {
48 /// @brief Number of items successfully replayed and removed from the queue.
49 int successful = 0;
50
51 /// @brief Number of items that were delivered, refused, and left in the
52 /// queue for retry, each having spent one attempt.
53 int failed = 0;
54
55 /// @brief Number of items whose replay never reached the peer. They remain
56 /// in the queue with their attempt count unchanged, so they are
57 /// neither progress nor a step towards being dead-lettered. Items
58 /// left queued by this run are `failed + undelivered`.
59 int undelivered = 0;
60
61 /// @brief Number of items that exhausted their retry budget and were dropped
62 /// from the queue (handed to the `DeadLetterSink` if one is set,
63 /// otherwise logged via `morph::log::logError`).
64 int deadLettered = 0;
65};

67/// @brief Replays queued actions from an `IOfflineQueue` on reconnect.
68///
69/// `SyncWorker` drains the queue and calls a caller-supplied replay function
70/// for each item. The framework has no knowledge of what "replay" means —
71/// that is entirely the caller's domain. Retry semantics are baked in with
72/// hard-coded sensible defaults; there are intentionally no setters.
73///
74/// @par Retry & dead-letter (built-in defaults)
75/// - Each item is retried up to **5 cumulative attempts**. The count is seeded
76/// from the larger of the drained `QueueItem::attempts` (durable, if the
77/// queue persists it) and this worker's own in-memory count, so a queue that
78/// overrides `IOfflineQueue::setAttempts()` makes the budget survive a
79/// process restart; a queue that does not (the default no-op) keeps the
80/// count purely in-memory, exactly as before.
81/// - **Only a *delivered* failure spends an attempt.** A replay reporting
82/// `ReplayOutcome::Undelivered` leaves the item queued with its count
83/// untouched, in memory and on disk alike, so a run of reconnect flaps
84/// cannot walk queued work to the dead-letter sink. The boolean
85/// `ReplayFunction` cannot express that outcome; a caller that can tell the
86/// two apart should use `DetailedReplayFunction`.
87/// - After every *charged* failure, the new count is written back through
88/// `IOfflineQueue::setAttempts()` (a no-op unless the queue overrides it) so
89/// a persisting queue's next `drain()` — this run or after a restart — sees
90/// the updated value.
91/// - Items that fail their 5th cumulative attempt are dropped from the queue.
92/// If a `DeadLetterSink` is set, it is invoked with the exhausted item
93/// instead of the default log line; if unset, the item is logged at
94/// `morph::log::LogLevel::error` (the payload appears in the log line) —
95/// today's behavior, unchanged.
96/// - Items that succeed reset their attempt counter implicitly (they're removed).
97/// - There is no public knob on the retry cap — if your application needs
98/// different retry math, wrap or replace `SyncWorker`. The framework's
99/// promise is "obvious, safe defaults that the GUI never has to think about."
100///
101/// @par Replay contract
102/// `DetailedReplayFunction` (three outcomes — prefer it):
103/// - `ReplayOutcome::Succeeded` → removed from the queue.
104/// - `ReplayOutcome::Rejected` → delivered and refused; attempt counter
105/// incremented; left in queue if under the
106/// cap, otherwise dropped (dead-lettered).
107/// - `ReplayOutcome::Undelivered` → never reached the peer; **nothing is
108/// charged** and the item stays queued.
109///
110/// `ReplayFunction` (two outcomes — unchanged for existing callers):
111/// - Return `true` → same as `Succeeded`.
112/// - Return `false` → same as `Rejected`. It is deliberately *not* read as
113/// `Undelivered`: every caller written against the boolean
114/// form means "this attempt failed", and silently treating
115/// that as undelivered would retry a poison payload forever.
116///
117/// Either form:
118/// - Throw → treated as `Rejected`. A throw reports failure but not delivery,
119/// and an unknown failure has to be charged for the same reason.
120///
121/// @par Thread safety
122/// `run()` is safe to call from any thread. Concurrent calls are serialised
123/// by an internal mutex — the second caller blocks until the first `run()` completes.
124class SyncWorker {
125public:
126 /// @brief Callable that attempts to replay a single queued item, reporting
127 /// only success or failure.
128 ///
129 /// Retained unchanged for existing callers, and `false` keeps meaning
130 /// exactly what it always did — `ReplayOutcome::Rejected`, i.e. one attempt
131 /// spent. A caller that can tell an undelivered replay from a refused one
132 /// should use `DetailedReplayFunction` instead; this overload cannot
133 /// express the difference and so cannot avoid the dead-lettering it causes.
134 using ReplayFunction = std::function<bool(const std::string& payload)>;
135
136 /// @brief Callable that attempts to replay a single queued item and reports
137 /// what it achieved.
138 ///
139 /// The three-outcome counterpart of `ReplayFunction`: it is the only form
140 /// that can report `ReplayOutcome::Undelivered` and so keep a reconnect
141 /// flap from spending the item's retry budget.
142 using DetailedReplayFunction = std::function<ReplayOutcome(const std::string& payload)>;
143
144 /// @brief Callable invoked when an item exhausts its retry budget, just
145 /// before it is removed from the queue.
146 ///
147 /// Receives the exhausted item (payload, idempotencyKey, and its final
148 /// cumulative attempt count). If unset, `SyncWorker` keeps the default
149 /// behavior: log at `morph::log::LogLevel::error` and drop. A throwing
150 /// sink is caught and logged — the item is still removed.
151 using DeadLetterSink = std::function<void(const QueueItem& poisoned)>;
152
153 /// @brief Constructs a worker that drains @p queue using @p replay.
154 /// @param queue Queue to drain on each `run()` call. Borrowed, not
155 /// owned: it must outlive this worker.
156 /// @param replay Function called for each pending item. Stored and
157 /// invoked for this worker's whole lifetime, so
158 /// anything the callable refers to must outlive it.
159 /// @param deadLetterSink Optional hook invoked with the exhausted item
160 /// instead of the default log-and-drop path when an
161 /// item exhausts its retry budget. Default: unset.
162 /// Retained on the same terms as @p replay.
163 SyncWorker(IOfflineQueue& queue MORPH_LIFETIMEBOUND, ReplayFunction replay MORPH_LIFETIMEBOUND,
164 DeadLetterSink deadLetterSink MORPH_LIFETIMEBOUND = nullptr)
165 : SyncWorker{queue,
166 [replay = std::move(replay)](const std::string& payload) {
167 return replay(payload) ? ReplayOutcome::Succeeded : ReplayOutcome::Rejected;
168 },
169 std::move(deadLetterSink)} {}
170
171 /// @brief Constructs a worker that drains @p queue using @p replay, which
172 /// distinguishes an undelivered replay from a rejected one.
173 ///
174 /// Identical to the overload above except for the replay callable's return
175 /// type. Only `ReplayOutcome::Rejected` spends an attempt, so a reconnect
176 /// flap that never reached the peer no longer walks queued work towards the
177 /// dead-letter sink.
178 ///
179 /// The two overloads are unambiguous: `ReplayOutcome` is a scoped enum, so
180 /// neither return type implicitly converts to the other.
181 ///
182 /// @param queue Queue to drain on each `run()` call. Borrowed, not
183 /// owned: it must outlive this worker.
184 /// @param replay Function called for each pending item. Stored and
185 /// invoked for this worker's whole lifetime, so
186 /// anything the callable refers to must outlive it.
187 /// @param deadLetterSink Optional hook invoked with the exhausted item
188 /// instead of the default log-and-drop path when an
189 /// item exhausts its retry budget. Default: unset.
190 /// Retained on the same terms as @p replay.
191 SyncWorker(IOfflineQueue& queue MORPH_LIFETIMEBOUND, DetailedReplayFunction replay MORPH_LIFETIMEBOUND,
192 DeadLetterSink deadLetterSink MORPH_LIFETIMEBOUND = nullptr)
193 : _queue{queue}, _replay{std::move(replay)}, _deadLetterSink{std::move(deadLetterSink)} {}
194
195 /// @brief Drains the queue, replaying each item via the replay function.
196 ///
197 /// Concurrent calls are serialised. The call blocks until all pending items
198 /// have been processed or `stop()` is signalled.
199 ///
200 /// If `stop()` was called before `run()` acquired the lock, `run()` returns
201 /// immediately with an empty result and resets the stop flag.
202 ///
203 /// @return Counts of successful / failed / dead-lettered replays.
204 SyncResult run() {
205 std::scoped_lock const runLock{_runMtx};
206 bool const wasStoppedBeforeRun = _stopped.exchange(false);
207 SyncResult result;
208 if (wasStoppedBeforeRun) {
209 return result;
210 }
211
212 auto items = _queue.drain();
213 ::morph::observe::detail::emitMetric(::morph::observe::Metric::queueDepth, static_cast<double>(items.size()));
214 for (auto& item : items) {
215 if (_stopped.load()) {
216 break;
217 }
218 ReplayOutcome outcome = ReplayOutcome::Rejected;
219 try {
220 outcome = _replay(item.payload);
221 } catch (...) {
222 // A throw says the replay failed but not whether it was
223 // delivered, and "I don't know" has to be charged: treating an
224 // unknown failure as undelivered would retry a genuinely
225 // poisonous payload forever. Same reading `false` has always
226 // had on the boolean overload.
227 outcome = ReplayOutcome::Rejected;
228 }
229 if (outcome == ReplayOutcome::Succeeded) {
230 _queue.markDone(item.id);
231 _attempts.erase(item.id);
232 ++result.successful;
233 continue;
234 }
235 if (outcome == ReplayOutcome::Undelivered) {
236 // Nothing reached the peer, so there is no evidence about this
237 // payload and nothing to charge. Deliberately touches neither
238 // `_attempts` nor `setAttempts()`: the budget is durable, so
239 // leaving the in-memory count alone while advancing the
240 // persisted one would still walk the item towards the
241 // dead-letter sink across a restart.
242 ++result.undelivered;
243 continue;
244 }
245 // The effective count is the larger of the persisted item.attempts
246 // (0 unless the queue overrides setAttempts) and this worker's own
247 // in-memory count, so a durable queue's cross-restart count is
248 // never regressed by a fresh (empty) in-memory map.
249 auto& counter = _attempts[item.id];
250 counter = std::max(counter, item.attempts);
251 ++counter;
252 _queue.setAttempts(item.id, counter);
253 if (counter >= kMaxAttempts) {
254 if (_deadLetterSink) {
255 QueueItem poisoned = item;
256 poisoned.attempts = counter;
257 try {
258 _deadLetterSink(poisoned);
259 } catch (...) {
260 ::morph::log::logError("[sync_worker] dead-letter sink threw while handling payload: " +
261 item.payload);
262 }
263 } else {
264 ::morph::log::logError("[sync_worker] dropping payload after " + std::to_string(kMaxAttempts) +
265 " failed attempts: " + item.payload);
266 }
267 _queue.markDone(item.id);
268 _attempts.erase(item.id);
269 ++result.deadLettered;
270 } else {
271 ++result.failed;
272 }
273 }
274 return result;
275 }
276
277 /// @brief Signals an in-progress `run()` to stop after the current item.
278 ///
279 /// Thread-safe. The flag is automatically reset at the start of the next
280 /// `run()` call, so stopping is one-shot.
281 void stop() { _stopped.store(true); }
282
283private:
284 /// @brief Cap on per-item cumulative retry attempts. Intentionally
285 /// hard-coded — see class docs.
286 static constexpr uint32_t kMaxAttempts = 5;
287
288 IOfflineQueue& _queue;
289 // Always the three-outcome form: the boolean constructor adapts into it, so
290 // `run()` has exactly one contract to implement rather than two.
291 DetailedReplayFunction _replay;
292 DeadLetterSink _deadLetterSink;
293 std::mutex _runMtx;
294 std::atomic<bool> _stopped{false};
295 std::unordered_map<uint64_t, uint32_t> _attempts;
296};
