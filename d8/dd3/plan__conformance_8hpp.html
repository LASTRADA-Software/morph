Detailed Description

Holds a model's translation of a QueryPlan to the answers of apply.

A model that pages its rows in a database translates planQuery's plan into its own query. This header runs a corpus of queries through apply over the rows (in the model's key order) and through the model's callback, and reports every disagreement. It depends on neither a test framework nor a database: the caller asserts that the returned list is empty. See docs/spec/table/database_pages.md.

The text a corpus query uses as an operand for a cell.

A date-time cell holds whole UTC seconds and a date cell holds days since the epoch; shown as bare numbers neither parses as a date, so a query built from them is refused by apply and by the plan alike and compares nothing. They are written as ISO 8601 (2026-11-10T09:00:00Z, 2026-11-10), which the default date parser reads and which lands exactly on the second or day the cell holds. Any other cell is shown as displayText shows it.

◆ standardCorpus()

std::vector< TableQuery > morph::table::standardCorpus ( DataSource const & source)
inlinenodiscard

Queries derived from a source's own cells: every operator each column's kind defines (as an include, as an exclude and, for text, case-sensitively), both sort directions on every column and on every pair of adjacent columns, a quick-search group over the text columns, and a window of pages around the start, the middle and past the end, with a zero limit.

The operands are the cells' own text, so the corpus is only as discriminating as the data: duplicate sort keys, empty cells, accents and case, sub-second instants and mixed units come from the rows the caller supplies.

◆ conformanceFailures()

std::vector< std::string > morph::table::conformanceFailures ( DataSource const & source,
PlanModel const & model,
std::span< TableQuery const > corpus,
ConformanceOptions const & options = {} )
inlinenodiscard

Runs corpus through apply over source and through model, and describes every disagreement and every column the corpus never compared.

source must hold the rows in the model's key order, which is the order apply breaks ties in. For each query: when the plan is refused for a reason other than the model's translatable, apply must refuse with the same code and column; when the plan is accepted, the model's rows (by key), offset and total must equal apply's. Above QueryLimits::totalCap apply omits the total; the oracle then counts the view itself, and the model must report either that exact count or a lower bound equal to the cap.

Identical refusals count as agreement, so a corpus whose operands never parse would pass without comparing anything. For each column that a corpus query filters with an operand, and for each column that a sort-only query orders, the helper therefore also reports the column when at least one query on it was refused identically by apply and the plan and none was compared with the model. Queries the model's translatable refuses are skipped and count as neither, so a column the model declares untranslatable is not reported.

Parameters
sourceThe rows, in key order.
modelThe model's translation of a plan.
corpusThe queries.
optionsLimits, services and column access shared by the oracle and the plan.
Returns
One description per disagreement; empty when the model conforms.
