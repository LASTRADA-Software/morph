23/// @brief Reconnect tuning for `QtWebSocketBackend`.
24///
25/// Declared outside `QtWebSocketBackend` so its default initialisers are fully
26/// parsed before any constructor default argument that names `Config{}` is
27/// evaluated (same rationale as `morph::offline::NetworkMonitorConfig`).
28struct QtWebSocketBackendConfig {
29 /// @brief Whether to attempt automatic reconnect after an unsolicited disconnect.
30 bool reconnectEnabled = true;
31
32 /// @brief Delay before the first reconnect attempt after a disconnect.
33 std::chrono::milliseconds initialReconnectDelay = std::chrono::milliseconds{500};
34
35 /// @brief Upper bound on the exponential backoff between reconnect attempts.
36 std::chrono::milliseconds maxReconnectDelay = std::chrono::seconds{30};
37
38 /// @brief Multiplier applied to the delay after each failed attempt.
39 double backoffMultiplier = 2.0;
40
41 /// @brief Opt in to `registerModelAsync` (see its doc comment on `IBackend`).
42 ///
43 /// Defaults to `false`: `Bridge::registerHandler()` then falls back to the
44 /// synchronous `registerModel`, exactly as before this feature existed —
45 /// every existing embedder (a desktop Qt client, this backend's own test
46 /// suite) keeps registering synchronously, immediately usable the line
47 /// after `BridgeHandler`'s constructor returns.
48 ///
49 /// Set `true` only for a build where that synchronous guarantee cannot
50 /// hold at all — a WASM main thread, where the nested `QEventLoop`
51 /// `registerModel` relies on aborts the page outright. Doing so is a
52 /// deliberate trade: the caller must then wait for registration to
53 /// complete (e.g. gate the UI on it) before firing an action through that
54 /// handler, since `executeVia` fails fast with "handler not bound" for an
55 /// unbound binding rather than queuing or blocking.
56 bool asyncRegistrationEnabled = false;
57};

59/// @brief `IBackend` implementation that communicates with a `RemoteServer` over WebSocket.
60///
61/// `registerModel()` is synchronous (blocks the calling thread via a nested
62/// `QEventLoop` until the server replies) -- unusable on a WASM main thread,
63/// which Qt refuses to spin a nested loop on at all. `registerModelAsync()`
64/// is the non-blocking alternative `Bridge::registerHandler()` prefers when
65/// available (see `IBackend::registerModelAsync`'s doc comment): it assigns a
66/// call-id, sends the message, returns immediately, and invokes exactly one
67/// of its `onRegistered`/`onError` callbacks once the matching reply arrives
68/// -- the same call-id-matching mechanism `execute()` already uses.
69/// `deregisterModel()` is fire-and-forget (it sends the message without
70/// waiting, avoiding a nested event loop during destruction). `execute()` is
71/// asynchronous: it assigns a call-id, sends the message, and resolves the
72/// returned `Completion` when the matching reply arrives.
73///
74/// @par TLS
75/// Pass a `QSslConfiguration` to enable `wss://`. Build it with `tlsVerifyingConfig()`
76/// (CA-verified — the recommended production default) or `tlsPinnedConfig()`
77/// (pinned-certificate — the correct choice for a self-signed deployment), both in
78/// `qt_tls.hpp`. `tlsInsecureNoVerify()` disables peer verification entirely and is
79/// for local development and tests only — see security.md's "Transport security" section.
80///
81/// @par SSL-less Qt builds (`QT_NO_SSL`, including the standard Qt-for-WebAssembly build)
82/// The constructor's `tls` parameter (and the `_tls` member) does not exist at all
83/// when Qt itself was configured without SSL — `QSslConfiguration` isn't a type
84/// Qt provides in that configuration, so there is no value to accept or ignore.
85/// `wss://` still works on such a build regardless: in a WASM/browser
86/// deployment the browser terminates TLS before Qt's `QWebSocket` ever sees
87/// the connection, so the only thing genuinely unavailable is the ability to
88/// *configure* TLS from C++ (client certificates, pinning, etc.) — plain
89/// `wss://` and `ws://` both still connect normally.
90///
91/// @par Threading
92/// Must be used from the Qt event loop thread. `execute()` and the internal
93/// message handler are both called on that thread.
94class QtWebSocketBackend : public ::morph::backend::detail::IBackend {

151 /// @brief Sends a `register` message and returns without blocking; the
152 /// reply is matched later, asynchronously, by `callId`.
153 ///
154 /// The non-blocking counterpart to `registerModel`/`registerModelWithContext`
155 /// (see `IBackend::registerModelAsync`'s doc comment for why this exists):
156 /// `registerModel` blocks the calling thread in a nested `QEventLoop` via
157 /// `sendSync`, which a WASM main thread cannot do at all. This instead
158 /// assigns a fresh `callId` (the same counter `execute()` uses), sends the
159 /// `register` envelope, and returns `true` immediately; the reply is
160 /// matched via `_pendingRegistrations` when `onTextMessage` sees it (no
161 /// protocol change needed — the server already echoes `callId` on every
162 /// reply, `register` included). Exactly one of @p onRegistered / @p onError
163 /// fires, on the Qt event loop thread, once the reply arrives — or never,
164 /// if the socket disconnects first without ever reconnecting and
165 /// `cancelPending` is never called again for this id (a disconnect
166 /// *before* a reconnect calls `cancelPending`, which does invoke @p onError
167 /// — see `cancelPending`'s doc comment).
168 ///
169 /// @param typeId String type-id of the model to instantiate.
170 /// @param factory Unused — this backend holds no local model to construct;
171 /// the server instantiates the model from `typeId`.
172 /// @param contextKey Stable identity of the new instance; travels in the wire envelope.
173 /// @param onRegistered Invoked with the server-assigned `ModelId` on success.
174 /// @param onError Invoked with a diagnostic message on failure or disconnect.
175 /// @return `true` always — this backend has an async path (`false` is never returned).
176 bool registerModelAsync(const std::string& typeId,
177 std::function<std::unique_ptr<::morph::model::detail::IModelHolder>()> factory,
178 std::string_view contextKey, std::function<void(::morph::exec::detail::ModelId)> onRegistered,
179 std::function<void(const std::string&)> onError) override;
180
181 /// @brief Sends a shared (register-or-attach) `register` and blocks for the reply.
