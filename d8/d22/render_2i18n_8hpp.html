Detailed Description

The renderer-side translation-catalog seam over morph's derived message keys (morph::forms::i18n, forms/i18n.hpp).

morph::render is client-side only and never appears on the wire — it is the namespace the planned per-field widget-override registry (gui_renderer_toolkit.md's SlotRegistry) will eventually share. morph ships this seam and the resolution algorithm below; it defines no translation storage format. A host adapts whatever catalog it already owns (Qt QTranslator/.qm, a JSON bundle, a database) into the one TranslationProvider signature.

Resolves one display slot's text: explicit key, then derived key, then the schema literal.

Tried in order, most specific first:

  1. explicitKey (a host-declared x-i18nKey-derived key), if present;
  2. derivedKey (morph::forms::i18n::fieldKey or one of its siblings);
  3. a miss at both falls back to schemaLiteral — the schema's authored title / description / x-placeholder / group or step title, unchanged. An empty/unset provider ("no catalog installed") skips straight to schemaLiteral, matching an unconfigured renderer's behavior exactly.
    Parameters
    providerThe host's catalog lookup.
    bcp47LocaleThe locale to resolve against (e.g. "fr-FR").
    explicitKeyThe field/group/rule/step's declared x-i18nKey-based key, or std::nullopt when none is declared.
    derivedKeyThe mechanically-derived key for this slot.
    schemaLiteralThe schema's authored fallback text for this slot.
    Returns
    The resolved display text.
